# Справочник встроенных промптов

Этот файл описывает встроенные промпты MCP-сервера ModusBI: что это такое,
как их вызвать и какие промпты сервер предоставляет на самом деле.

## Что такое встроенный промпт

Промпт MCP — это готовый многошаговый сценарий-подсказка, который поставляется
вместе с сервером. У сервера две разные сущности: **инструмент (Tool)** и **промпт
(Prompt)**. Инструмент ассистент вызывает сам по ходу диалога, чтобы реально
выполнить операцию над порталом. Промпт выбирает и запрашивает клиент: пользователь
явно говорит «разверни такой-то сценарий». Сервер в ответ отдаёт заранее
заготовленный текст с пошаговой инструкцией — какие инструменты и в каком порядке
вызывать, какие параметры передавать, на что обратить внимание.

Промпт не выполняет действий сам. Это шаблон сообщения: он встраивает в текст
переданные аргументы (например, идентификатор отчёта или название шаблона) и
возвращает готовую инструкцию, которой дальше следует ассистент, вызывая обычные
инструменты сервера.

Промпт полезен, когда задача типовая и состоит из нескольких связанных шагов:
создание дашборда, добавление фильтров, настройка условного форматирования.
Вместо того чтобы вспоминать всю последовательность вызовов вручную, пользователь
запрашивает соответствующий промпт и получает выверенный сценарий.

### Инструмент и промпт: чем отличаются

| Признак | Инструмент (Tool) | Промпт (Prompt) |
|---|---|---|
| Кто инициирует | ассистент сам, по ходу диалога | пользователь, явно выбирая сценарий в клиенте |
| Что делает | выполняет операцию над порталом | возвращает текст-инструкцию |
| Результат | изменение на портале или данные | заготовленный сценарий из нескольких шагов |
| Метод протокола | `tools/call` | `prompts/get` |
| Аналогия | команда | рецепт, собранный из команд |

Подробнее об инструментах и их действиях — в [GLOSSARY](../GLOSSARY.md)
(статьи «Tool», «Action») и в соседних файлах этой папки.

## Как вызвать промпт

Промпты — часть протокола MCP и работают по тем же правилам JSON-RPC поверх stdio,
что и инструменты (см. [../architecture/concepts/protocol-and-rpc.md](../architecture/concepts/protocol-and-rpc.md)).
Концептуально клиент использует два метода протокола:

- `prompts/list` — получить список доступных промптов с их названиями, описаниями
  и перечнем аргументов.
- `prompts/get` — запросить конкретный промпт по имени, передав значения аргументов;
  в ответ приходит готовый текст-инструкция.

Практически пользователь не оперирует этими методами вручную. В клиенте,
поддерживающем MCP, промпт обычно выглядит как именованный сценарий, который можно
выбрать; клиент сам отправляет `prompts/get` и подставляет аргументы. Каждый
аргумент бывает обязательным или необязательным — это видно в `prompts/list` и
указано в описаниях ниже.

После получения текста промпта ассистент выполняет описанные в нём шаги,
вызывая обычные инструменты сервера. Перечень инструментов и их действий —
в соседних файлах этой папки и в [../GLOSSARY.md](../GLOSSARY.md).

## Доступные промпты

Ниже — промпты, которые сервер регистрирует и отдаёт по `prompts/list`. Актуальный
перечень всегда можно получить прямо у работающего сервера методом `prompts/list`:
имена, описания и аргументы там совпадают с тем, что заложено в коде.

Для каждого промпта указаны назначение и ключевые аргументы (обязательность отмечена
явно).

### create_dashboard
Пошаговое создание дашборда: выбор датасета, просмотр его полей, создание отчёта,
подбор и добавление компонентов, раскладка, визуальная настройка и фильтры.
Внутри промпта — развёрнутый справочник типов компонентов и особые паттерны
для отдельных типов.

Аргументы:
- `dataset_name` — название датасета (необязательный).
- `report_name` — название будущего отчёта (необязательный).

### style_report
Стилизация отчёта на двух уровнях: глобальный CSS на весь отчёт и точечная
настройка отдельных компонентов через пресеты и slug-параметры
(см. [Слаги компонентов](../architecture/concepts/components-json-slugs.md)).

Аргументы:
- `report_id` — идентификатор отчёта (обязательный).
- `style_type` — на чём сфокусироваться: цвета, заголовки, таблицы, графики
  (необязательный).

### query_data
Построение запроса к датасету: осмотр полей и типов, предложение вариантов запроса
(простой, агрегированный, с фильтрацией, параметризованный переменными) и выполнение
выбранного.

Аргументы:
- `dataset_id` — идентификатор датасета (обязательный).
- `question` — вопрос на естественном языке (необязательный).

### export_report
Экспорт готового отчёта в файл. Промпт проверяет существование отчёта, показывает
конфигурацию экспорта, выполняет его и сообщает путь к результату.

Аргументы:
- `report_id` — идентификатор отчёта (обязательный).
- `format` — формат выгрузки (необязательный; по умолчанию используется PDF).

### analyze_dataset
Анализ структуры датасета: метаданные, поля с типами, пример данных. На основе
этого промпт классифицирует поля (числовые, категориальные, временные) и предлагает
подходящие типы визуализации и параметры.

Аргументы:
- `dataset_id` — идентификатор датасета (обязательный).

### customize_component
Визуальная настройка одного компонента отчёта. Промпт раскрывает три уровня
оформления: атомарные параметры, точечные переопределения через slug-ключи
(`config_overrides`, см. [Слаги компонентов](../architecture/concepts/components-json-slugs.md))
и готовые пресеты.

Аргументы:
- `report_id` — идентификатор отчёта (обязательный).
- `component_idx` — индекс компонента в отчёте, 0-based (обязательный).
- `preset` — быстрый пресет оформления (необязательный); если задан, промпт сразу
  предлагает применить именно его.

### add_filters
Добавление интерактивных фильтров и каскадных зависимостей. Промпт описывает
паттерны размещения фильтров, обязательные параметры поля фильтра и важное правило:
поля фильтрации нужно добавлять не только на панель-фильтр, но и на каждый
data-компонент, иначе они не будут реагировать на выбор.

Аргументы:
- `report_id` — идентификатор отчёта (обязательный).
- `component_idx` — индекс уже существующей панели-фильтра, если она есть
  (необязательный).

### add_conditional_formatting
Настройка условного форматирования для таблиц и сводных таблиц: правила по полю и
условию, цвет текста и фона, индикаторы и стиль. Промпт показывает структуру правила
и помогает собрать и применить его.

Аргументы:
- `report_id` — идентификатор отчёта (обязательный).
- `component_idx` — индекс таблицы или сводной таблицы (обязательный).

### manage_variables
Управление переменными отчёта и категориями: просмотр текущих значений и набор
операций добавления, изменения и удаления. Промпт поясняет разницу между
переменными (параметры для запросов) и категориями (привязка к фильтрам уровня
отчёта).

Аргументы:
- `report_id` — идентификатор отчёта (обязательный).

### create_report_from_template
Создание отчёта из готового шаблона. Промпт показывает состав и раскладку каждого
шаблона и даёт пошаговую инструкцию: получить поля датасета, создать отчёт, добавить
компоненты пакетно, настроить фильтры. Перечень шаблонов можно также получить
у сервера действием `report_template(action="list")`.

Аргументы:
- `template` — название шаблона (обязательный). Допустимые значения промпт проверяет;
  при неизвестном значении возвращается подсказка со списком корректных вариантов.
- `dataset_id` — идентификатор датасета для компонентов (обязательный).
- `report_name` — название нового отчёта (необязательный).
- `group_id` — идентификатор группы для отчёта (необязательный).
