# Подключение сервера к ИИ-клиенту

Эта страница — о том, как подключить готовый ModusBI MCP Server к вашему ИИ-клиенту (например, Claude
Desktop или Claude Code), чтобы ассистент через диалог просматривал, собирал и настраивал BI-отчёты на
портале ModusBI. Сборка из исходников, изменение кода и развёртывание серверной части здесь не
предполагаются.

Если вам, наоборот, нужно собрать сервер из исходного кода, развернуть его как сервис или настроить
production-окружение — это маршрут DevOps: [for-devops.md](for-devops.md).

Понадобится доступ к порталу ModusBI (адрес, логин, пароль) и ИИ-клиент с поддержкой MCP, который умеет
подключать MCP-серверы через свой файл конфигурации.

По умолчанию сервер запускается в режиме только для чтения (`readonly`) — это безопасное состояние:
даже если ассистент попытается что-то создать, изменить или удалить, сервер отклонит вызов ещё до
обращения к порталу. Чтобы ассистент мог **собирать и менять** отчёты, сервер запускают с флагом
`--readwrite`. Полное описание режимов — в [server-modes.md](server-modes.md).

> 💡 **Не хотите настраивать вручную?** Если вы работаете в ИИ-клиенте, который умеет править файлы и
> запускать команды (например, Claude Code), просто **дайте ссылку на эту страницу своему ассистенту**
> и попросите настроить подключение — он пройдёт по шагам сам. Дальше описывайте задачи словами.

## Предусловия

1. **ИИ-клиент с поддержкой MCP.** Например, Claude Desktop. Клиент должен уметь подключать
   MCP-серверы через свой файл конфигурации.
2. **Доступ к порталу ModusBI.** Понадобятся три значения:
   - `MODUSBI_URL` — адрес вашего портала, например `https://your-portal.example.com`;
   - `MODUSBI_USERNAME` — логин учётной записи на портале (`<логин>`);
   - `MODUSBI_PASSWORD` — её пароль (`<пароль>`).

   Сервер обращается к HTTP-API портала от имени этой учётной записи, поэтому видит ровно те отчёты и
   данные, к которым у неё есть доступ.

   > ⚠️ **Заведите отдельную учётную запись портала под MCP-сервер.** Портал ModusBI допускает только
   > **один активный сеанс** на учётку. Если сервер работает под той же записью, под которой вы сами
   > заходите на портал в браузере, один из сеансов будет завершён — «выкинет». Отдельная учётка под
   > MCP снимает эту проблему и удобна для ограничения прав. Подробнее — в [DISCLAIMER](../../DISCLAIMER.md).

## Шаг 1. Получить сервер

Самый простой способ (Python не нужен) — **скачать готовый бинарник** со страницы релизов проекта на
GitHub:

**https://github.com/modus-bi/mcp-modusbi/releases**

Откройте последний релиз и в разделе **Assets** скачайте файл под свою операционную систему (здесь
`<версия>` — номер релиза, например `1.0.0`):

| Операционная система | Файл |
|---|---|
| Linux (x86-64) | `modusbi-mcp-server-<версия>-linux-x86_64` |
| Windows (x86-64) | `modusbi-mcp-server-<версия>-windows-x86_64.exe` |
| macOS (Apple Silicon, M1 и новее) | `modusbi-mcp-server-<версия>-macos-arm64` |

Рядом с каждым бинарником лежит файл `.sha256` с эталонной контрольной суммой — по нему можно
проверить, что файл скачался без повреждений. Посчитайте хеш скачанного файла и сравните его с хешем
внутри `.sha256` (это текстовый файл — откройте его, эталонный хеш стоит первым; регистр неважен):

- Linux: `sha256sum modusbi-mcp-server-<версия>-linux-x86_64` → сверьте с файлом `modusbi-mcp-server-<версия>-linux-x86_64.sha256`;
- macOS: `shasum -a 256 modusbi-mcp-server-<версия>-macos-arm64` → сверьте с файлом `modusbi-mcp-server-<версия>-macos-arm64.sha256` (на macOS утилита называется `shasum`, не `sha256sum`);
- Windows (PowerShell): `Get-FileHash .\modusbi-mcp-server-<версия>-windows-x86_64.exe -Algorithm SHA256` → сверьте с файлом `modusbi-mcp-server-<версия>-windows-x86_64.exe.sha256` (у Windows расширение `.exe` входит в имя файла суммы).

Положите бинарник в удобный каталог и запомните **абсолютный путь** к файлу — он понадобится в конфиге
клиента. В примерах ниже файл переименован в короткое `modusbi-mcp-server` (Windows —
`modusbi-mcp-server.exe`); можно оставить и исходное имя, но тогда в конфиге (Шаг 3) указывайте полный
путь именно с версией.

- Linux / macOS: скопируйте файл **с переименованием** и сделайте исполняемым (для macOS — имя
  `…-macos-arm64`):
  `cp modusbi-mcp-server-<версия>-linux-x86_64 /usr/local/bin/modusbi-mcp-server && chmod +x /usr/local/bin/modusbi-mcp-server`.
- Windows: скопируйте `.exe` в каталог (например `C:\Tools\`) и переименуйте в `modusbi-mcp-server.exe`.

> 💡 На той же странице релиза есть архив `modusbi-mcp-skills-<версия>.zip` — готовые скиллы и агенты
> для ИИ-ассистента (опционально, устанавливаются отдельно). См. [установку скиллов](../skills/install.md).

**Если готового бинарника под вашу платформу нет** (например, Linux на ARM или Mac на процессоре Intel),
сервер собирается из исходного кода — см. маршрут DevOps [for-devops.md](for-devops.md) и раздел
«Быстрый старт» в [../README.md](../README.md). В этом случае в конфиге вместо пути к бинарнику
указывают команду запуска интерпретатора (`python -m app.server`).

## Шаг 2. Открыть конфиг MCP-клиента

У каждого клиента свой файл конфигурации MCP-серверов:

| Клиент | Файл конфигурации |
|--------|-------------------|
| Claude Desktop (macOS) | `~/Library/Application Support/Claude/claude_desktop_config.json` |
| Claude Desktop (Windows) | `%APPDATA%\Claude\claude_desktop_config.json` |
| Cursor | `.cursor/mcp.json` в корне проекта |
| Claude Code | `.mcp.json` в корне проекта |

Готовый шаблон со всеми серверами — [.mcp.example.json](../../.mcp.example.json) (скопируйте из него
блок `modusbi`). Описание, какие серверы нужны и кому, — [../../MCP_SERVERS.md](../../MCP_SERVERS.md). Для
просмотра отчётов достаточно одного сервера — `modusbi`.

## Шаг 3. Прописать сервер и учётные данные

Добавьте в файл конфигурации запись сервера `modusbi`. Учётные данные портала передаются через блок
`env` — клиент сам отдаёт эти значения серверу при запуске, отдельный `export` в терминале не нужен.

**Готовый бинарник (Linux / macOS):**

```json
{
  "mcpServers": {
    "modusbi": {
      "command": "/usr/local/bin/modusbi-mcp-server",
      "args": ["--readonly"],
      "env": {
        "MODUSBI_URL": "https://your-portal.example.com",
        "MODUSBI_USERNAME": "<логин>",
        "MODUSBI_PASSWORD": "<пароль>"
      }
    }
  }
}
```

> **Внимание.** Значения `MODUSBI_URL`, `<логин>`, `<пароль>` в примерах — плейсхолдеры. Подставьте
> свои. Не храните реальный пароль в конфиге в открытом виде, если файл доступен посторонним: по
> возможности используйте механизм секретов вашего ИИ-клиента или платформы (см. примечание после
> примеров).

**Готовый бинарник (Windows):** то же самое, только в `command` — абсолютный путь к `.exe`
(в JSON обратные слэши экранируются):

```json
"command": "C:\\Tools\\modusbi-mcp-server.exe"
```

**Запуск из исходников** (если бинарника нет): вместо пути к бинарнику укажите интерпретатор и
модуль, и добавьте рабочий каталог проекта. `PYTHONPATH` должен указывать на корень проекта
modusbi-mcp — каталог, в котором лежит папка `app/`:

```json
{
  "mcpServers": {
    "modusbi": {
      "command": "python",
      "args": ["-m", "app.server", "--readonly"],
      "env": {
        "PYTHONPATH": "/path/to/modusbi-mcp",
        "MODUSBI_URL": "https://your-portal.example.com",
        "MODUSBI_USERNAME": "<логин>",
        "MODUSBI_PASSWORD": "<пароль>"
      }
    }
  }
}
```

Подставьте свои значения вместо `https://your-portal.example.com`, `<логин>` и `<пароль>`.
Пароль не стоит хранить в файлах, доступных посторонним; если ваш ИИ-клиент или платформа
предоставляет механизм секретов — используйте его вместо открытого значения в конфиге.

## Шаг 4. Запуск в readonly по умолчанию

Флаг режима задаётся в массиве `args`. Доступны три варианта:

- `--readonly` — только чтение (по умолчанию, безопасное состояние);
- `--readwrite` — чтение и запись (создание, изменение, удаление отчётов и компонентов);
- `--demo` — только чтение с дополнительными лимитами на нагрузку.

В примерах выше указан `--readonly` — явный режим только для чтения. Если флаг режима не указать
вовсе, сервер всё равно стартует в `readonly`.

В режиме `readonly` ассистент может:

- получать списки и содержимое отчётов, датасетов, компонентов (`list`, `get`, `summary`, `*_list`);
- проверять подключения и данные (`validate`, `check_connection`);
- выгружать готовые отчёты в файлы (PDF, PNG, PPTX) — через действие `export` инструмента
  `report_operations` или пакетно через `batch_operations`.

Создание, изменение и удаление в этом режиме заблокированы. Если они вам понадобятся — это уже режим
`readwrite`; о том, как и зачем его включать, читайте в [server-modes.md](server-modes.md). По
умолчанию для просмотра оставайтесь в `readonly`.

## Шаг 5. Проверка: «вижу инструменты»

1. Полностью закройте и заново откройте ИИ-клиент (не сворачивайте — именно перезапуск, чтобы клиент
   перечитал конфиг и поднял сервер).
2. В диалоге с ассистентом попросите показать список доступных инструментов сервера `modusbi`.
   Всего сервер публикует 19 инструментов. Среди них должны появиться, например, `report_operations`,
   `dataset_operations`, `style_operations` и инструменты для работы с компонентами.
3. Для содержательной проверки попросите ассистента вызвать чтение — например, получить список
   отчётов на портале (`report_operations(action="list")`). Если в ответ пришёл список — значит
   сервер подключён, авторизация на портале прошла и режим `readonly` работает.

Компоненты (виджеты) внутри отчёта управляются через четыре отдельных инструмента: `component_crud`
(добавление/изменение/удаление), `component_filters` (фильтры), `component_axes` (оси, страницы,
drill-down, вкладки) и `component_styling` (условное форматирование, сортировка, гео-ключи карты).

Для справки по любому инструменту вызовите его с действием `help`, например:
`component_crud(action="help")`.

Сам по себе сервер не открывается «как сайт»: он общается с ассистентом по протоколу MCP
(JSON-RPC 2.0 поверх стандартного ввода-вывода, stdio) и ждёт вызовов от клиента. Видимый результат
появляется именно в диалоге ИИ-клиента.

## Если что-то не работает

| Симптом | Что проверить |
|---------|---------------|
| Клиент не видит сервер | Путь в `command` должен быть **абсолютным**. Перезапустите клиент полностью. |
| `Authentication failed` | Проверьте `MODUSBI_USERNAME` / `MODUSBI_PASSWORD` — попробуйте войти на портал в браузере под этими же данными. |
| `Connection refused` | Проверьте `MODUSBI_URL` и сеть. Если портал за VPN — включён ли VPN? |
| Ассистент пишет «требует режим: readwrite» | Вы запросили изменение, а сервер в `readonly`. Для просмотра это норма — пересмотрите запрос. Подробнее — [server-modes.md](server-modes.md). |
