# С чего начать: маршрут по ролям

> ⚠️ **Перед практической работой** прочитайте [../../DISCLAIMER.md](../../DISCLAIMER.md): изменения на портале необратимы (нет отмены/истории), безопасность доступов при работе с LLM — на стороне пользователя.

Этот раздел — навигатор по документации. Найдите ниже свою роль и читайте
перечисленные файлы в указанном порядке: каждый следующий опирается на
предыдущий.

Если встретится незнакомое слово — загляните в
[словарь терминов](../GLOSSARY.md). Минимум, который стоит знать заранее:
**MCP**, **MCP-сервер**, **инструмент (tool)**, **действие (action)**, **отчёт**,
**компонент**, **датасет**, **портал**.

## Какая роль вам подходит

| Роль | Кто это | Цель |
|---|---|---|
| **DevOps** | Разворачивает и эксплуатирует сервер (установка из исходников, окружение, режимы) | Установить, настроить, поддерживать |
| **Разработчик** | Дорабатывает сам сервер: добавляет слаги, билдеры, инструменты | Понять код и устройство, начать вносить изменения |
| **Аналитик / Пользователь** | Работает с BI-отчётами через ассистента — от «подключить готовый сервер и пользоваться» до «строить и настраивать дашборды» | Подключить и собирать/менять отчёты словами |
| **Тестировщик** | Проверяет, что отчёты и компоненты корректно отрисовываются в браузере | Прогнать сценарии и зафиксировать результат |

Одному человеку может подходить сразу несколько ролей — например, DevOps,
который сам же дорабатывает сервер, проходит маршрут DevOps, а затем
«Разработчик».

---

## DevOps

Вы устанавливаете сервер из исходников, настраиваете окружение и режимы запуска,
подключаете один или несколько порталов и поддерживаете работу.

1. [Установка из исходников и эксплуатация](for-devops.md) — окружение,
   переменные, запуск, подключение порталов.
2. [Режимы работы сервера](server-modes.md) — режимы запуска, флаги
   `--readonly` / `--readwrite` / `--demo` и жёсткая верхняя граница
   (`--security-ceiling`).
3. [Сборка и выпуск релизов](releasing.md) — бинарники по ОС, тег `vX.Y.Z`,
   автоматическая публикация в Release.

## Разработчик

Вы дорабатываете сам сервер. Сначала разверните его как DevOps, затем разберитесь
в концепциях, и только потом переходите к коду.

1. [Установка из исходников и эксплуатация](for-devops.md) — разверните сервер
   локально.
2. [Что такое MCP](../architecture/concepts/what-is-mcp.md) — модель «ИИ → сервер → портал»
   и доменные сущности.
3. [Протокол: JSON-RPC, а не REST](../architecture/concepts/protocol-and-rpc.md) — как
   устроен обмен: JSON-RPC наружу к клиенту и действия (action/command) поверх
   HTTP к порталу.
4. [Концепция слагов](../architecture/concepts/components-json-slugs.md) (три имени: UI / слаг / JSON-путь).
5. [Руководство разработчика](developer.md) — структура кода и
   цикл «правка → перезапуск → проверка».
6. [Механика расширения](../architecture/extending.md) — как добавить слаг, билдер или инструмент.

## Аналитик / Пользователь

Вы работаете с BI-отчётами на портале **через ассистента**, не трогая исходный код. Эта роль
покрывает оба сценария — от обычного пользователя до BI-аналитика:

- **Обычный пользователь** — подключаете готовый сервер к ИИ-клиенту и работаете с отчётами словами:
  посмотреть, собрать простой отчёт, что-то поправить. Настраивать вручную не обязательно: можно
  **дать ссылку на инструкцию по подключению своему ассистенту, и он сам настроит подключение** и
  проведёт по шагам.
- **BI-аналитик** — строите и настраиваете дашборды, **руководя ассистентом**: знаете свои данные,
  SQL и какой тип графика к какой задаче, а ассистент берёт на себя ручную сборку — быстро
  прототипирует и меняет отчёт по промптам.

В обоих случаях MCP **не анализирует данные за вас** — он ускоряет сборку и правки отчётов.

1. [Подключение сервера к ИИ-клиенту](connect.md) — установка **общая для всех**, делается один раз.
   Обычному пользователю проще всего дать эту инструкцию ассистенту — он настроит подключение сам.
2. [Руководство аналитика](analyst.md) — три способа собрать отчёт (промпты в чате,
   скиллы и агенты, отчёт по скриншоту), как ставить задачу и что нужно доустановить
   для скиллов.

Глубокие технические разделы (слаги, API, устройство сервера) для этой роли не нужны — это работа
ассистента. Можно дать ссылку на руководство своему ассистенту, и он проведёт по шагам.

## Тестировщик

Вы проверяете, что отчёты и компоненты действительно отрисовываются в браузере, и
фиксируете результат. Исходный код сервера при этом не меняется.

1. [Руководство тестировщика](tester.md) — сценарии проверки в
   браузере, единая сессия, формат журнала результатов.

Ключевой принцип проверки — «источник истины то, что отрисовано в браузере» —
описан в [словаре терминов](../GLOSSARY.md) (см. «Рендер» и «Рендер-контракт»).
