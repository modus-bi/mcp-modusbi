# Общий АРМ дашбордов с GigaChat

JS-компонент Modus BI вызывает HTTP-методы действующего MCP-сервера. Python-шлюз пилота заменён встроенным модулем MCP. Сервер берёт список действующих отчётов из API Modus BI. Отчёт становится чатом при первом обращении, а все участники АРМ видят одну историю. «Создать» начинает черновик. После подтверждённого создания история открывается из каталога по ID нового отчёта.

## Запуск

Установите зависимости `python -m pip install -r requirements-dashboard-arm.txt`. Используйте штатные `MODUSBI_URL`, `MODUSBI_USERNAME`, `MODUSBI_PASSWORD` для сервисного доступа на портал. Дайте учётной записи нужные права на группы AРМ и источники данных. Сохранение управляется штатным режимом MCP.

| Настройка | Назначение |
| --- | --- |
| `MODUSBI_ARM_ORIGIN` | Точный origin портала, например `https://portal.example.test` |
| `MODUSBI_ARM_ACCESS_KEY` | Общий ключ HTTP-доступа к АРМ длиной от 24 символов |
| `MODUSBI_ARM_ID` | Идентификатор в URL, по умолчанию `dashboard-builder` |
| `MODUSBI_ARM_DATA_DIR` | Постоянный том для SQLite, вложений и зашифрованных настроек |
| `MODUSBI_ARM_REPORT_GROUP` | ID группы для новых отчётов, по умолчанию `1` |
| `MODUSBI_ARM_IMPORT_SOURCE` | ID хранилища Modus BI для импорта Excel и CSV. При `0` доступны существующие датасеты и скриншоты |
| `GIGACHAT_CREDENTIALS` | Ключ из проекта GigaChat при настройке через окружение |
| `GIGACHAT_MODEL`, `GIGACHAT_SCOPE`, `GIGACHAT_CA_FILE` | Модель, тип доступа к API и дополнительный CA-файл при необходимости |
| `MODUSBI_ARM_ADMIN_KEY`, `MODUSBI_ARM_SECRET_KEY` | Отдельный ключ администратора АРМ и Fernet-ключ для шифрования настроек. Вместе включают настройку GigaChat через UI |

```sh
python -m app.server --transport http --http-port 8000 --tool-profile gigachat --dashboard-arm --readwrite
```

Публикуйте по HTTPS только `/api/dashboard-arm/` для входного трафика компонента. Оставьте обычный интерфейс `/mcp` в своём контуре доступа. Для одного адреса с порталом можно направить `/api/dashboard-arm/` на MCP через действующий прокси портала. Ключ АРМ можно передавать заголовком `X-Modus-ARM-Key` из доверенного прокси после проверки доступа к рабочему месту. При выделенном HTTPS-адресе ключ вводится в окне компонента. Трафик направляется на один экземпляр MCP с постоянным томом, чтобы очередь и общая история оставались согласованы.

Для изменения настроек GigaChat нужен отдельный заголовок `X-Modus-ARM-Admin`. После проверки модели новый ключ сохраняется зашифрованным. Статус подключения и чтение истории ключи не возвращают. Если настройка через UI отключена, используйте переменные окружения сервера.

## Методы компонента

| Метод | Маршрут относительно `/api/dashboard-arm/{arm}` |
| --- | --- |
| `GET` | `/chats` — действующие дашборды и их количество |
| `GET` | `/datasets` — доступные датасеты для нового дашборда |
| `GET` | `/status` — подключение к Modus BI и результат проверки модели |
| `POST` | `/settings` — проверка и смена подключения GigaChat с ключом администратора |
| `GET`, `POST` | `/chats/{chat}` — чтение истории и отправка сообщения с опциональными вложениями |
| `GET` | `/chats/{chat}/images/{image}` — изображение из истории |

Сервер связывает существующий чат с `report-{ID}` и сериализует работу по дашборду. Для черновика компонент использует UUID. Модель получает только инструменты профиля GigaChat и параметры текущего отчёта и датасетов. При уточнении сообщение сохраняется, а запись в отчёт ждёт ответа. Для правки существующего компонента нужен его стабильный ключ профиля MCP. Компоненты без такого ключа видны в отчёте и доступны для чтения их конфигурации. Поддержка их точечных правок требует привязки к ключам профиля.

Проверка маршрутов `python -m pytest -q app/tests/test_dashboard_arm.py` использует две отдельные HTTP-сессии, настоящую диспетчеризацию MCP и тестовые реализации портала и GigaChat.
