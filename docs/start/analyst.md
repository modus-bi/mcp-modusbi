# Аналитику: сборка BI-отчётов через ИИ-ассистента

> ⚠️ Изменения на портале применяются сразу и **необратимы** (нет отмены/истории). См.
> [../../DISCLAIMER.md](../../DISCLAIMER.md).

> 💡 **Можно дать ссылку на этот файл своему ИИ-ассистенту** (в Claude Desktop или Claude Code) — он
> прочитает её и будет действовать по ней. Дальше вы ставите задачи промптами, а ассистент собирает и
> правит отчёт.

Вы — BI-аналитик. Вы знаете свои данные, владеете SQL и понимаете, какой тип графика уместен под какую
задачу. **MCP-сервер не анализирует данные и не думает за вас** — он быстро **собирает и меняет
дашборды** на портале ModusBI по вашим промптам: создаёт отчёт, описывает датасет на SQL, добавляет
компоненты, ставит фильтры, применяет стили. Ценность — скорость и итеративность: собрать прототип за
минуту, поменять одним промптом, поэкспериментировать с типами визуалов, layout и темами — вместо
ручной сборки через UI портала.

Распределение ролей простое: **вы** приносите SQL датасета, выбор метрик и выбор визуала; **ассистент**
убирает ручную рутину сборки; **вы** открываете результат в браузере и правите словами. Это рабочий
цикл, а не «опишу — и соберётся само с первого раза».

---

## Перед началом

1. **Сервер подключён к вашему ИИ-клиенту.** Делается один раз — см.
   [подключение сервера к ИИ-клиенту](connect.md) (или попросите коллегу-DevOps). Чтобы
   ассистент мог **создавать и менять** отчёты, сервер должен быть запущен с флагом `--readwrite`
   (по умолчанию — только чтение).
2. **Для скиллов и агентов (способ 2) нужна отдельная установка.** Они не приходят вместе с сервером —
   подробности в самом разделе ниже. Работа промптами в чате (способ 1) ничего доустанавливать не требует.

---

## Рабочий цикл

1. **Сформулируйте задачу** — какими данными (датасет/поля), что показать, каким срезом. Чем точнее
   назовёте — тем меньше правок (см. [«Как ставить задачу»](#как-ставить-задачу-чтобы-быстрее-прийти-к-результату)).
2. **Ассистент собирает** — создаёт или правит отчёт через инструменты сервера.
3. **Откройте отчёт в браузере и проверьте** — браузер источник истины. Не то, что хотели — скажите,
   что поправить.
4. **Повторите** — отчёт доводится правками-промптами, а не угадывается с первого раза.

---

## Три способа собрать отчёт

Все три приводят к готовому отчёту — выбирайте под задачу, их можно смешивать.

### 1. Просто опишите задачу в чате (промптами)

Самый обычный способ — **написать ассистенту словами, что нужно**, прямо в чате: «собери дашборд
продаж по регионам за 2025 год», «добавь фильтр по менеджеру», «поменяй столбцы на горизонтальные».
Ассистент сам подберёт компоненты, привяжет данные и соберёт отчёт через инструменты сервера. Никаких
команд и синтаксиса учить не нужно: вы описываете результат, а правки вносите так же — глядя на отчёт в
браузере. Это рабочий режим по умолчанию; способы 2 и 3 ниже — лишь ускорители под конкретные ситуации.

**Необязательно — готовые промпты-шорткаты.** Помимо свободного описания, у сервера есть 10 встроенных
промптов-сценариев (приходят вместе с сервером, ставить ничего не надо) — заготовки частых задач
(собрать дашборд, отчёт по шаблону, добавить фильтры и т. п.). В Claude Code их можно вызвать как
`/mcp__modusbi__create_dashboard` (наберите `/` и выберите из меню; аргументы — через пробел), в Claude
Desktop — через меню вложений. Промпт ничего не делает сам: он лишь подставляет ваши параметры в готовую
пошаговую инструкцию для ассистента — то же самое получится, если просто описать задачу словами. Полный
список с аргументами — [каталог промптов](../prompts/README.md).

### 2. Скиллы и агенты (нужна отдельная установка)

> ⚠️ **Скиллы и агенты — не часть MCP-сервера** и не приходят при его подключении. Это артефакты
> **Claude Code**. Чтобы они стали доступны:
> - работайте в **Claude Code** (Claude Desktop скиллы и агентов не загружает);
> - один раз скопируйте папки `.claude/skills/` и `.claude/agents/` из этого репозитория в каталог
>   `.claude/` вашего проекта (или в `~/.claude/skills` и `~/.claude/agents` — тогда они доступны во
>   всех проектах);
> - сервер `modusbi` всё равно должен быть подключён — скиллы вызывают его инструменты;
> - отдельным скиллам и агентам нужны **доп. MCP-серверы**: postgres (PG) — тем, кто читает БД напрямую
>   (агент `dashboard-builder`, скилл `analyze-data`); playwright (PW) — для визуальной сверки оформления.
>   Что и кому нужно — в [MCP_SERVERS.md](../../MCP_SERVERS.md).
>
> Пошаговая установка (в том числе скачивание готового бандла из релиза) —
> [установка скиллов и агентов](../skills/install.md). Если скиллов нет — попросите коллегу-DevOps
> развернуть их. Способ 1 (промпты в чате) в этом не нуждается — он работает в любом MCP-клиенте.

Скилл — это готовый сценарий-экспертиза: попросите ассистента применить нужный (или просто опишите
цель — он подберёт сам).

| Задача | Скилл |
|---|---|
| Дашборд с ключевыми метриками | `create-kpi-dashboard` |
| Рейтинг / топ-N | `create-ranking` |
| Сравнение периодов | `create-comparison` |
| Факторный анализ (что повлияло на показатель) | `create-factor-analysis` |
| Карта / территориальный анализ | `create-geo-analytics` |
| Простой отчёт (фильтр + график + таблица) | `create-simple-report` |
| Подобрать подходящий тип визуала под задачу | `bi-visualization-expert` |
| Добавить навигацию между отчётами | `add-navigation-panel` |

Есть и **агенты** — они делают задачу целиком сами. Например, агент `dashboard-builder` соберёт готовый
дашборд по описанию данных. Полный каталог — [каталог скиллов](../skills/README.md).

### 3. Отчёт по скриншоту

Покажите ассистенту **картинку** нужного дашборда — скриншот из другой BI-системы, слайд из
презентации, набросок от руки — и попросите собрать такой же на ModusBI по вашим данным.

**Как:** прикрепите скриншот в чат и напишите, например: «сделай такой же отчёт по датасету продаж».
Ассистент разберёт, какие графики и блоки на картинке, и соберёт аналог; что понял не так — поправите
словами, глядя на результат.

## Как ставить задачу, чтобы быстрее прийти к результату

Чем конкретнее промпт, тем меньше итераций. Полезно назвать:

- **данные** — какой датасет/таблица и какие поля (вы их знаете лучше ассистента); если нужного
  датасета ещё нет — какой SQL под него собрать;
- **что показать** — метрику и срез: «выручка по месяцам», «топ-10 регионов», «доли по категориям»;
- **тип визуала, если есть предпочтение** — «воронка», «treemap», «KPI сверху». Нет предпочтения —
  ассистент предложит, вы оцените и поправите.

Примеры рабочих формулировок:

- «Добавь на дашборд продаж воронку по этапам сделки и фильтр по менеджеру; воронку — в левую колонку».
- «Собери KPI-дашборд по выручке из шаблона `kpi_dashboard` на датасете продаж: 4 KPI, тренд по
  месяцам, сводная по менеджерам».
- «Замени столбчатый график регионов на treemap, отсортируй по убыванию, оставь топ-10, примени синюю
  тему».
- «Сделай каскадный фильтр Регион → Город и проставь его на карте, баре и таблице, чтобы данные реально
  фильтровались».

После сборки **откройте отчёт в браузере** — не то, что хотели, опишите правку словами.

## Полезно помнить

- **Изменения необратимы.** Отмены и истории нет — проверяйте результат и для важных отчётов делайте
  копии (попросите ассистента склонировать отчёт). См. [DISCLAIMER](../../DISCLAIMER.md).
- **Отдельная учётка под MCP.** Портал допускает только один сеанс на пользователя: если сервер и вы
  сами зайдёте под одной учётной записью, одного «выкинет». Используйте для MCP отдельного пользователя
  портала. См. [DISCLAIMER](../../DISCLAIMER.md).
- **Данные и визуал — на вас.** Сервер соберёт то, что попросили; корректность SQL, выбор метрики и
  уместность типа графика остаются вашей зоной ответственности. Глубокий анализ данных (гипотезы,
  причины аномалий) — отдельная задача, а не основная функция этого сервера.
- **Точный дизайн — через визуальную проверку.** Если важно «пиксель-в-пиксель», ассистент сверяет
  оформление по скриншоту в браузере (см. [проверку отрисовки](tester.md)); часть тонких настроек CSS
  подтверждается только так.
- **Не знаете, что доступно** — просто спросите ассистента: «что ты умеешь с отчётами ModusBI?».
