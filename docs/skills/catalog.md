# Скиллы: матрица свойств

Скилл — это готовый сценарий работы ассистента (например, «создать дашборд» или «проверить
отчёт»), который под капотом вызывает инструменты MCP-сервера. Эта страница помогает
**выбрать безопасный скилл под доступный режим работы**. Для каждого скилла указано три свойства:

- нужен ли серверу режим **`readwrite`** (создание/изменение/удаление) или хватит `readonly`;
- нужны ли **реальные данные портала** (живой портал, существующие датасеты/отчёты, запросы к данным);
- нужен ли **браузер** (MCP-сервер `playwright`) — для проверки отрисовки и сквозных UI-сценариев.

Что такое скилл, режимы и MCP-серверы — см. [обзор раздела «Скиллы»](README.md),
[словарь терминов](../GLOSSARY.md) и [режимы запуска сервера](../start/server-modes.md).
Описания скиллов и примеры запросов — в [обзоре раздела «Скиллы»](README.md).

> Базово любому скиллу достаточно MCP-сервера **`modusbi`**. Дополнительные серверы
> (`postgres`, `playwright`) нужны только части скиллов — это видно в таблицах ниже.

---

## Как читать колонки

| Колонка | Значение |
|---|---|
| **Режим** | 🟢 `readonly` — скилл работает в режиме только чтения; ✏️ `readwrite` — скилл создаёт или изменяет отчёты на портале, поэтому сервер должен быть запущен с `--readwrite` |
| **Данные портала** | ✅ нужны реальные данные/объекты портала (датасеты, отчёты, источники); ⬚ работает на тексте/шаблонах без обращения к данным |
| **Браузер (PW)** | ✅ нужен MCP-сервер `playwright` (открывает портал в браузере, делает скриншоты, проверяет отрисовку); ⬚ браузер не нужен |
| **PG** | ✅ скилл умеет ходить в БД напрямую через MCP-сервер `postgres` (исследование схемы/данных); опционален там, где данные уже есть в датасете |

Пометки:

- **✏️ readwrite** означает, что скилл *пишет* на портал (создаёт отчёт, добавляет компонент,
  меняет конфиг, применяет стиль). В режиме `readonly` такой скилл выполнить нельзя — сервер
  вернёт ошибку вида «требует режим: readwrite».
- **🟢 readonly** означает, что скилл либо только читает портал, либо вообще работает с текстом
  (генерация SQL, методология, планы презентаций) и безопасен в режиме только чтения.

## Создание отчётов и дашбордов

Эти скиллы собирают отчёты на портале — им нужен **`readwrite`** и реальные данные
(чтобы создать датасет и привязать компоненты к полям). Большинство умеет исследовать
исходную БД через `postgres`, когда данных ещё нет в датасете.

| Скилл | Режим | Данные портала | Браузер (PW) | PG |
|---|---|---|---|---|
| **create-dashboard** | ✏️ readwrite | ✅ | ✅ | ✅ |
| **create-kpi-dashboard** | ✏️ readwrite | ✅ | ⬚ | ✅ |
| **create-ranking** | ✏️ readwrite | ✅ | ⬚ | ✅ |
| **create-comparison** | ✏️ readwrite | ✅ | ⬚ | ✅ |
| **create-factor-analysis** | ✏️ readwrite | ✅ | ⬚ | ✅ |
| **create-geo-analytics** | ✏️ readwrite | ✅ | ⬚ | ✅ |
| **create-simple-report** | ✏️ readwrite | ✅ | ⬚ | ✅ |
| **add-navigation-panel** | ✏️ readwrite | ✅ | ⬚ | ⬚ |

Примечание: `create-dashboard` дополнительно может проверить готовый отчёт в браузере
(скриншот раскладки) — поэтому у него стоит браузер; остальным скиллам этой группы браузер
не нужен для основной работы.

## Анализ данных и выводы

Скиллы получают данные, формулируют выводы и при необходимости добавляют визуализацию
к отчёту (тогда нужен **`readwrite`**).

| Скилл | Режим | Данные портала | Браузер (PW) | PG |
|---|---|---|---|---|
| **analyze-data** | ✏️ readwrite | ✅ | ✅ | ✅ |
| **explain-chart** | ✏️ readwrite | ✅ | ✅ | ⬚ |
| **dq-profiler** | ✏️ readwrite | ✅ | ✅ | ✅ |

Все три добавляют результат на портал (визуализацию, текстовый вывод, DQ-дашборд) и проверяют
итог в браузере, поэтому требуют `readwrite` и `playwright`. `analyze-data` и `dq-profiler`
дополнительно исследуют исходные данные через `postgres`; `explain-chart` работает с данными
уже существующего компонента, поэтому `postgres` ему не нужен.

## SQL и подготовка данных

Чисто текстовая генерация SQL — данные портала и браузер не нужны, режим только чтения безопасен.

| Скилл | Режим | Данные портала | Браузер (PW) | PG |
|---|---|---|---|---|
| **generate-sql** | 🟢 readonly | ⬚ | ⬚ | ⬚ |
| **sql-bi-expert** | 🟢 readonly | ⬚ | ⬚ | ✅ |

`sql-bi-expert` может опционально сверить запрос с реальной схемой через `postgres`, но в
основе остаётся справочником-генератором и не пишет на портал.

## Методология (справочные)

Подключаются автоматически другими скиллами. Это базы знаний: работают на тексте, ничего
не пишут на портал, браузер не требуется.

| Скилл | Режим | Данные портала | Браузер (PW) | PG |
|---|---|---|---|---|
| **bi-visualization-expert** | 🟢 readonly | ⬚ | ⬚ | ⬚ |
| **data-analyst-expert** | 🟢 readonly | ⬚ | ⬚ | ⬚ |
| **statistical-analysis** | 🟢 readonly | ⬚ | ⬚ | ⬚ |
| **data-storytelling** | 🟢 readonly | ⬚ | ⬚ | ⬚ |
| **prompt-engineering-bi** | 🟢 readonly | ⬚ | ⬚ | ⬚ |

Примечание: `bi-visualization-expert` содержит раздел про визуальную проверку раскладки в
браузере, но как справочный скилл сам её не запускает — браузер подключают вызывающие
его `create-*` скиллы при необходимости.

## Презентации и контент

Генерация презентаций, сценариев демо и скринкастов — это создание текста/HTML, а не запись
на портал. Режим только чтения безопасен.

| Скилл | Режим | Данные портала | Браузер (PW) | PG |
|---|---|---|---|---|
| **present-outline** | 🟢 readonly | ⬚ | ⬚ | ⬚ |
| **create-presentation** | 🟢 readonly | ⬚ | ⬚ | ⬚ |
| **demo-scenario** | 🟢 readonly | ✅ | ✅ | ⬚ |
| **screencast-script** | 🟢 readonly | ⬚ | ⬚ | ⬚ |
| **mcp-explainer** | 🟢 readonly | ⬚ | ⬚ | ⬚ |

Примечание: `demo-scenario` готовит сценарий живого показа и для этого может открывать портал
в браузере (навигация, скриншоты, запасной план) на существующих отчётах — отсюда браузер и
данные портала; но сам он отчёты не создаёт и не меняет.

## Тестирование и разработка (технические)

Технические скиллы для проверки портала, компонентов и кода сервера. Часть из них **создаёт
тестовые отчёты/компоненты** на портале (нужен `readwrite`) и **проверяет отрисовку в браузере**
(нужен `playwright`).

| Скилл | Режим | Данные портала | Браузер (PW) | PG |
|---|---|---|---|---|
| **verify-report** | 🟢 readonly | ✅ | ✅ | ⬚ |
| **modusbi-e2e** | 🟢 readonly | ✅ | ✅ | ⬚ |
| **component-deep-settings** | 🟢 readonly | ✅ | ✅ | ⬚ |
| **component-visual-verify** | ✏️ readwrite | ✅ | ✅ | ⬚ |
| **portal-component-probe** | ✏️ readwrite | ✅ | ✅ | ⬚ |
| **mcp-prompt-writer** | 🟢 readonly | ⬚ | ⬚ | ⬚ |

Пояснения к этой группе:

- **verify-report**, **modusbi-e2e**, **component-deep-settings** — *проверяющие* скиллы: они
  читают уже существующий отчёт/компонент и сверяют его с ожиданиями в браузере, ничего не
  записывая. Достаточно `readonly`, но нужны реальные отчёты и браузер.
- **component-visual-verify**, **portal-component-probe** — *создают* тестовый отчёт/компонент,
  применяют настройки и смотрят результат в браузере. Нужен `readwrite` и `playwright`.
- **mcp-prompt-writer** правит исходный код сервера (определения промптов), а не данные портала —
  ему не нужны ни `readwrite`-режим портала, ни реальные данные, ни браузер.

## Быстрый выбор под доступный режим

- **Только `readonly` (без записи на портал):** генерация SQL, методология, презентации/контент,
  а также проверяющие скиллы (`verify-report`, `modusbi-e2e`, `component-deep-settings`).
- **Нет браузера (`playwright`):** все `create-*` (кроме случаев, где нужна визуальная проверка),
  `generate-sql`, `sql-bi-expert`, методология, `screencast-script`, `present-outline`,
  `create-presentation`, `mcp-explainer`, `mcp-prompt-writer`.
- **Нет реальных данных портала:** генерация SQL, методология, планирование презентаций
  и сценариев, `mcp-prompt-writer`. Любой `create-*` или анализ требуют доступа к данным.
- **Нет сервера `postgres`:** работают все скиллы, которым данные уже доступны через датасет;
  `postgres` нужен лишь для исследования исходной БД напрямую (часть `create-*`, `analyze-data`,
  `dq-profiler`, опционально `sql-bi-expert`).
