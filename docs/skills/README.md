# Скиллы ModusBI MCP — каталог и сценарии использования

Эта страница — каталог **скиллов**: что они умеют, по группам, и в каком случае какой применять.

## Что такое скилл

**Скилл** — это готовый сценарий (экспертиза) для ИИ-ассистента поверх инструментов MCP-сервера.
Сам по себе скилл ничего не меняет на портале — он лишь подсказывает ассистенту, *как* и *в каком
порядке* вызывать инструменты (RPC-методы) сервера, чтобы решить типовую задачу: собрать дашборд,
проанализировать данные, проверить отчёт, написать SQL.

На практике это выглядит так: вы **формулируете запрос обычными словами** («создай дашборд по
продажам за год»), ассистент сам подбирает подходящий скилл и выполняет его шаги через инструменты
ModusBI. Знать названия скиллов наизусть не нужно — достаточно описать задачу.

Рядом со скиллами существуют **агенты** — это не отдельный тип скилла, а оркестраторы: агент
запускается автоматически в составе более крупного сценария и сам вызывает нужные скиллы и
инструменты. Отдельно вызывать агента не требуется. В таблицах ниже тип каждой строки помечен явно.

Скиллы делятся на несколько групп:

- **Пользовательские** — создание отчётов, анализ данных, SQL, презентации. Запускаются вашим запросом.
- **Технические** — проверка портала, аудит компонентов, документирование, написание серверных
  промптов. Запускаются разработчиком; части из них нужен браузерный MCP-сервер.
- **Справочные (методология)** — готовые методики (выбор визуализации, статистика, формулировка
  выводов). Их может вызвать ассистент напрямую, либо они автоматически подключаются другими
  скиллами как база знаний.

> Базово достаточно одного MCP-сервера — `modusbi`. Карта серверов и пример конфигурации —
> [../../MCP_SERVERS.md](../../MCP_SERVERS.md), образец конфига [.mcp.example.json](../../.mcp.example.json),
> переменные окружения [.env.example](../../.env.example); пошаговая установка — в
> [../start/for-devops.md](../start/for-devops.md). Дополнительные серверы нужны лишь отдельным
> техническим скиллам — см. колонку «Нужно» ниже.

## Легенда

| Обозначение | Значение |
|---|---|
| **Скилл** | Сценарий, запускаемый запросом обычными словами |
| **Агент** | Оркестратор: запускается автоматически в составе более крупного сценария; отдельно вызывать не нужно |
| **Что делает** | Назначение скилла или агента |
| **Пример запроса** | Как вызвать — достаточно написать похожую фразу |
| **Нужно** | Доп. MCP-серверы: **PW** браузерный (playwright) · **PG** прямой доступ к БД (postgres). Если пусто — хватает базового `modusbi` |

## 📊 Создание отчётов и дашбордов

*Когда применять:* нужно собрать готовый отчёт под задачу. Опишите задачу и источник данных —
ассистент исследует данные, создаёт датасет (с русскими подписями полей), собирает компоненты,
привязывает фильтры, применяет стиль и возвращает готовый отчёт.

| Скилл | Что делает | Пример запроса |
|---|---|---|
| **create-dashboard** | Полноценный дашборд под задачу: исследует данные, создаёт датасеты, собирает компоненты, фильтры, стиль | «создай дашборд по продажам за год» |
| **create-kpi-dashboard** | Дашборд мониторинга: крупные KPI, тренд, карта, сводная таблица | «KPI-дашборд по выручке с динамикой» |
| **create-ranking** | Рейтинг: топ-N, treemap, таблица с детализацией (drill-down) | «топ-10 регионов по продажам» |
| **create-comparison** | Сравнение двух периодов: KPI-дельты (▲▼), stacked bar, структура (pie + таблица) | «сравни этот квартал с прошлым» |
| **create-factor-analysis** | Факторный анализ: waterfall (вклад факторов), KPI, таблица с подсветкой | «разложи изменение выручки по факторам» |
| **create-geo-analytics** | Геоаналитика: карта (точки/хороплет), KPI, таблица по территориям | «карта продаж по регионам» |
| **create-simple-report** | Минимальный отчёт: фильтр + график + таблица (3 компонента) — самый быстрый | «быстрый отчёт по продажам» |
| **add-navigation-panel** | Навигационная панель-меню между несколькими отчётами | «свяжи мои отчёты навигацией» |

> 💡 **Совет новичку:** не нужно запоминать названия скиллов. Опишите задачу обычными словами —
> ассистент сам выберет подходящий скилл. Например, «создай дашборд по продажам за год» запустит
> `create-dashboard`, а «топ-10 регионов по выручке» — `create-ranking`.

> Каждый `create-*` скилл соответствует одному из шаблонов-каркасов сервера
> (kpi_dashboard, ranking, comparison, factor_analysis, geo_analytics, simple).
> Подробнее о шаблонах — в [../architecture/tools/README.md](../architecture/tools/README.md).

## 🔍 Анализ данных и выводы

*Когда применять:* есть датасет или вопрос «почему», и нужны выводы, а не просто график.
Ассистент запрашивает данные, проверяет гипотезы и качество, формулирует бизнес-выводы с цифрами
и при необходимости добавляет визуализацию к отчёту.

| Скилл | Что делает | Пример запроса |
|---|---|---|
| **analyze-data** | Глубокий анализ: проверяет гипотезы, ищет корреляции, формулирует бизнес-выводы с рекомендациями и оценкой эффекта | «проанализируй, почему упали продажи» |
| **explain-chart** | Объясняет готовый график и добавляет к дашборду текстовый вывод «что это значит / что делать» | «объясни этот график, какие выводы» |
| **dq-profiler** | Профилирование качества данных: полнота, уникальность, аномалии → правила проверки → DQ-дашборд | «проверь качество данных в таблице» |

## 🗄 SQL и подготовка данных

*Когда применять:* нужен SQL под BI — с правильными типами, сортировкой и подписями, чтобы сразу
подать его в создание датасета.

| Скилл | Что делает | Пример запроса |
|---|---|---|
| **generate-sql** | Генерирует SQL под BI: сортировка, типы, округление, технические alias + русские подписи через `field_aliases` | «SQL для топ-N категорий по сумме» |
| **sql-bi-expert** | Расширенный SQL-справочник для BI (паттерны: динамика, когорты, сравнения) с правильными типами и сортировкой | «напиши SQL для дашборда продаж» |

## 🎤 Презентации и сторителлинг

*Когда применять:* нужно превратить данные или фичу в доклад/демо/видео — структуру слайдов,
готовую HTML-презентацию или сценарий.

| Скилл | Что делает | Пример запроса |
|---|---|---|
| **present-outline** | Планирует структуру презентации: narrative arc, карта слайдов, тайминги | «спланируй презентацию про продукт» |
| **create-presentation** | Собирает готовую HTML-презентацию (reveal.js) из плана: слайды, диаграммы, таблицы | «сделай слайды по этому плану» |
| **data-storytelling** | Методика подачи данных как истории: «So what?», визуальная иерархия, адаптация под аудиторию | «оформи выводы из данных в нарратив» |
| **demo-scenario** | Сценарий живого демо: шаги, тайминги, речевой и запасной план | «подготовь сценарий показа продукта» |
| **screencast-script** | Сценарий скринкаста/видео: hook, таймкоды, закадровый текст, монтажные заметки | «напиши текст для видео-демо фичи» |
| **mcp-explainer** | Справочник по архитектуре MCP для слайдов: что такое MCP, чем удобен для ИИ, диаграммы | «объясни архитектуру MCP для доклада» |

## 📐 Методология (справочные)

*Когда применяются:* это готовые методики и справочники. Их может вызвать ассистент напрямую (например,
«проверь статистическую значимость»), либо они автоматически подключаются скиллами выше — для выбора
визуализации, формулировки выводов, статистических проверок и подготовки запроса к ИИ.

| Скилл | Что делает | Когда применяется |
|---|---|---|
| **bi-visualization-expert** | Правила выбора типа графика и layout дашборда (что для каких данных) | внутри `create-*`, при выборе визуализации |
| **data-analyst-expert** | Методика бизнес-выводов: что → почему → что делать, с оценкой эффекта (Root Cause Analysis) | внутри `analyze-data`, `explain-chart` |
| **statistical-analysis** | Статметоды: значимость, A/B, корреляции, аномалии, прогноз | «проверь значимость», «найди корреляцию» |
| **prompt-engineering-bi** | Как формулировать запросы к ИИ для дашбордов и анализа, чтобы получить качественный результат | при подготовке запроса к ассистенту |

## 🛠 Тестирование и разработка (технические)

Скиллы и агенты для проверки портала, аудита и документирования компонентов и разработки сервера.
Описание более техническое. Часть требует браузерного MCP-сервера (**PW**) или прямого доступа к
БД (**PG**) — см. колонку «Нужно».

*Когда применять:* проверить собранный отчёт или компонент перед сдачей, прогнать сквозной сценарий
в UI, разобрать или задокументировать настройки компонента, написать или проверить серверный промпт.

### Скиллы

| Скилл | Что делает | Когда применять | Нужно |
|---|---|---|---|
| **verify-report** | Детальная проверка отчёта: фильтры привязаны, данные грузятся, layout без перекрытий, alias, стили | проверить собранный отчёт перед сдачей | — |
| **modusbi-e2e** | Сквозная проверка портала через браузер: вход, открытие отчётов, рендер компонентов | прогон сценария в UI | PW |
| **component-deep-settings** | Разбор всех настроек компонента: UI-контрол → JSON-путь → MCP-слаг, классификация связи | аудит соответствия настроек компонента | PW |
| **component-visual-verify** | Визуальная проверка, что применённый слаг реально отрисовался (скриншот + сверка DOM) | подтвердить, что `config_overrides` рендерится | PW |
| **portal-component-probe** | Проверка одного компонента через UI портала: палитра → добавление → панель настроек → сверка с документацией | проверить добавляемость и настройку типа | PW |
| **mcp-prompt-writer** | Написание и аудит серверных промптов: корректность имён действий и параметров относительно API | добавить или проверить промпт сервера | — |

### Агенты

Агенты запускаются автоматически как часть оркестрации — отдельно вызывать их не нужно.

| Агент | Что делает | Когда применяется | Нужно |
|---|---|---|---|
| **dashboard-builder** | Строит отчёт/дашборд по полученным данным (оркестрирует скиллы `create-*`) | авто: когда нужен дашборд из данных | PG |
| **portal-ui-prober** | Ориентируется в UI портала и проверяет готовность набора типов через интерфейс (оркестрирует скилл `portal-component-probe`) | авто: проверка набора типов через UI | PW |
| **component-visual-verifier** | Визуально верифицирует, что слаг рендерится на компоненте | авто: визуальная верификация слага | PW |

## Как начать

> Подробная пошаговая инструкция, включая **скачивание готового бандла из релиза**, —
> [установка скиллов и агентов](install.md).

1. **Работайте в Claude Code.** Скиллы и агенты — это артефакты Claude Code, а не часть MCP-сервера;
   Claude Desktop их не загружает.
2. **Установите скиллы и агентов в клиент.** Один раз скопируйте папки `.claude/skills/` и
   `.claude/agents/` из этого репозитория в каталог `.claude/` вашего проекта (или в `~/.claude/skills`
   и `~/.claude/agents` — тогда они доступны во всех проектах). При подключении сервера они **не**
   приходят автоматически.
3. Подключите MCP-сервер `modusbi` — образец конфига [.mcp.example.json](../../.mcp.example.json),
   карта серверов [../../MCP_SERVERS.md](../../MCP_SERVERS.md). Пошаговая установка из исходников описана
   в [../start/for-devops.md](../start/for-devops.md). Скиллы вызывают инструменты сервера, поэтому он
   должен быть подключён.
4. Заполните `.env` по образцу [.env.example](../../.env.example) (адрес портала + учётные данные).
5. Для скиллов тестирования UI добавьте браузерный сервер (PW), для прямой аналитики из БД — PG
   (см. [../../MCP_SERVERS.md](../../MCP_SERVERS.md)).
6. Дальше пишите запрос обычными словами — ассистент подберёт скилл сам.
