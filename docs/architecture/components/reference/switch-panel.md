# Переключатель

Тип компонента: `HsSwitchControlPanel`

## Описание

Переключатель (контейнер с переключениями) показывает выпадающий список из нескольких полей-разрезов и позволяет на лету менять группировку данных сразу в нескольких компонентах отчёта. В отличие от drill-down (последовательного спуска по уровням иерархии), переключатель даёт **произвольный** выбор любого из подготовленных разрезов анализа.

Компонент управляет общим объектом разрезов на уровне отчёта: при выборе значения в списке устанавливается активное поле категории, и все компоненты, у которых первое поле на оси «Категории» совпадает по подписи (alias) с первым полем переключателя, автоматически перестраивают свою группировку.

## Когда применять

Переключатель — утилитарный компонент управления: сам он данные не показывает, а меняет группировку в других компонентах.

- Пользователю нужно переключаться между разными разрезами анализа (например: Регион / Продукция / Месяц).
- Несколько графиков и таблиц должны синхронно менять группировку по одному критерию.
- Нужен произвольный выбор разреза, а не фиксированный спуск по иерархии.

## Когда не подходит

- Последовательный drill-down по уровням иерархии — задайте несколько полей на оси «Категории» самого графика (механизм перехода между уровнями).
- Фильтрация по значениям — используйте [Панель фильтра](filter-panel.md) (`HsFilterControlPanel`), см. также [Фильтры и каскады](../filter-patterns.md).
- Навигация между страницами — используйте контейнер страниц (`HsPageContainer`) или панель вкладок (`HsTabsPanel`).
- Единственный фиксированный разрез — просто задайте поле на оси «Категории» нужного компонента.

## Поля

У переключателя одна рабочая ось — **«Категории»**. На неё помещаются поля-разрезы, между которыми идёт переключение. Этот компонент требует датасета: поля разрезов берутся из набора данных, поэтому при добавлении обязателен `dataset_id`. Агрегация к этим полям не применяется (она сбрасывается в `None`), оси значений и серий у компонента нет.

Роли полей:

- **Первое поле** — определяет «ключ связи» (первое поле, по которому переключатель синхронизирует другие компоненты). Его подпись (поле `alias` в конфиге) должна совпадать с подписью первого поля на оси «Категории» в связанных компонентах — именно по совпадению подписи переключатель управляет их группировкой.
- **Остальные поля** — альтернативные разрезы. Их подписи показываются как варианты в выпадающем списке.

Рекомендуется минимум 2 поля (иначе переключать нечего). Поддерживаются текстовые, числовые, дата- и вычисляемые поля.

В терминах параметров добавления первое поле передаётся через `category_field`, остальные — через строку `value_field` (comma-separated; агрегация для них не нужна).

Несколько переключателей в одном отчёте работают независимо: каждый управляет своим разрезом, если у них разные подписи первого поля.

## Параметры добавления

| Параметр | Назначение |
|----------|-----------|
| `dataset_id` | Набор данных, из которого берутся поля-разрезы (обязателен) |
| `category_field` | Первое поле-разрез, ключ связи с компонентами (строка) |
| `value_field` | Остальные поля-разрезы, comma-separated строка — альтернативные варианты в списке. Пример: `"product,month_name"` |
| `x`, `y`, `w`, `h` | Позиция и размер компонента в сетке отчёта |

Для оформления выпадающего списка и расположения вариантов используйте `config_overrides` со слагами `switch.*` (см. ниже).

## Пример

Переключатель между тремя разрезами в верхней строке дашборда:

```python
component_crud(
    action="add",
    report_id=35,
    component_type="HsSwitchControlPanel",
    title="Разрез анализа",
    dataset_id=54,
    category_field="region",                  # первое поле — ключ связи
    value_field="product,month_name",         # альтернативные разрезы (comma-separated)
    x=0, y=0, w=24, h=2,
    config_overrides={
        "switch.selectorTitleOverride": "Выберите разрез",
        "switch.filterType": "column",
    },
)
```

Чтобы переключение влияло на график или таблицу, у них на оси «Категории» первое поле должно иметь ту же подпись, что и первое поле переключателя (здесь — подпись поля `region`, например «Регион»). Только при совпадении подписей компонент откликается: при выборе «Продукция» все такие компоненты перегруппируют данные по полю `product`.

Горизонтальный ряд вариантов внутри одного компонента — задаётся слагом `switch.filterType="panel"`:

```python
component_crud(
    action="add",
    report_id=35,
    component_type="HsSwitchControlPanel",
    title="Разрезы данных",
    dataset_id=54,
    category_field="fed_okrug",
    value_field="region,product_type,year",
    x=0, y=0, w=48, h=3,
    config_overrides={"switch.filterType": "panel"},
)
```

Здесь `component_crud` — это RPC-метод MCP-сервера (вызов инструмента), а не REST-эндпоинт; `component_idx` в других действиях — 0-based индекс компонента в отчёте.

## JSON-конфигурация

Сервер собирает и хранит конфигурацию компонента в JSON. Ниже — аннотированная структура переключателя: рядом с каждым ключом указано, что он задаёт и каким слагом управляется (полное соответствие — в таблице «Все настройки»).

```jsonc
{
  "type": "HsSwitchControlPanel",               // тип компонента (его отдаёт component_crud action="types_list")
  "config": {
    "title": "Разрез анализа",                  // заголовок компонента
    "chartType": "SwitchControlPanel",          // внутренний тип (фиксирован)
    "showtitle": true,                          // показывать заголовок            ← слаг showtitle
    "noexport": true,                           // не экспортировать (по умолч. true: это элемент управления)
    "nocopy": true,                             // запрет копирования данных (спец. default переключателя)
    "autoApply": true,                          // переключение применяется сразу, минуя кнопку «Применить» (спец. default)
    "bgColor": "rgba(255,255,255,1)",           // цвет фона                       ← слаг bgColor
    "selectorTitleOverride": "Выберите разрез", // заголовок списка вместо подписи первого поля ← слаг switch.selectorTitleOverride
    "filterType": "column",                     // расположение вариантов: "column" = выпадающий список | "panel" = горизонтальные кнопки в ряд ← слаг switch.filterType
    "margin":  { "l": 0, "r": 0, "t": 0, "b": 0, "pad": 0 },   // отступы (спец. компактные нули для переключателя) ← слаги margin.l/r/t/b/pad
    "outline": { "enabled": false, "width": 4 },               // рамка            ← слаги outline.enabled/width
    "axes": [                                   // оси (поля привязываются параметрами при добавлении)
      { "name": "filters",    "type": "filters",    "fields": [] },               // служебная ось фильтров, у переключателя всегда пуста
      { "name": "categories", "type": "categories", "fields": [                   // ось разрезов ← category_field + value_field
          { "name": "region",  "alias": "Регион",   "type": "string", "agg": null, "datasetId": 54 },   // agg всегда null — агрегация на переключателе не применяется
          { "name": "product", "alias": "Продукция","type": "string", "agg": null, "datasetId": 54 }
      ]}
    ]
  }
}
```

> Заголовок выпадающего списка: если задан `switch.selectorTitleOverride` — используется он, иначе подпись (alias) первого поля. У переключателя нет осей значений и серий — только «Категории», и агрегация полей здесь всегда снята.

## Все настройки (config_overrides)

Полный перечень слагов этого типа — специфичные для типа и общие оформительские. Колонки: **UI-контрол** — название в панели настроек портала (пусто = прямого UI-контрола нет, настройка только через `config_overrides`); **MCP-слаг** — ключ в `config_overrides`; **JSON-путь** — куда настройка пишется в конфиг и откуда её читает отображение (это и есть «фронт-ключ»; путь в `(скобках)` обрабатывается секционно — итоговый ключ внутри указанной секции конфига); **Тип**; **По умолчанию**.
