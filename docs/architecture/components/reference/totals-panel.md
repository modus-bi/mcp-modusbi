# Панель показателей (KPI)

Тип компонента: `HsTotalsPanelV2`

## Описание

Панель показателей отображает один ключевой показатель эффективности (KPI) крупной плиткой: значение, заголовок, подзаголовок и индикатор тренда. Это «карточка» для мониторинга метрики — выручки, количества, конверсии, процента выполнения плана.

Панель состоит из четырёх независимо настраиваемых элементов:

- **Значение (value)** — основное число, берётся из первого поля оси Значения.
- **Заголовок (caption)** — берётся из заголовка компонента.
- **Подзаголовок (subcaption)** — поясняющая строка под заголовком.
- **Тренд (trend)** — вычисленное отклонение со стрелкой и цветовой индикацией (рост/падение или процент достижения цели).

В отличие от диаграмм, у панели нет осей категорий в привычном смысле: категория используется только для вычисления тренда (поле периода). Несколько KPI на дашборде собирают из нескольких отдельных панелей.

## Когда применять

- Мониторинг 1–5 ключевых метрик на дашборде (по одной панели на метрику).
- Показ значения с трендом «рост/падение» относительно предыдущего периода.
- Показ процента достижения целевого значения (план/факт).
- Управляющий фильтр: клик по плитке фильтрует другие компоненты дашборда.

## Когда не подходит

- Более 5 метрик на одной плитке — используйте несколько панелей.
- Детализированные данные по строкам — таблица (`HsTableReactabularChart`).
- Сравнение категорий между собой — столбчатая диаграмма (`HsBarAMchartsChart`).
- Динамика по времени (временной ряд) — линейная диаграмма (`HsLineAMchartsChart`).
- Мини-график (sparkline) внутри плитки не поддерживается — ставьте рядом отдельную линейную диаграмму на тех же данных.

## Поля и оси

Панель показателей использует три полки данных:

- **Значения** — числовое поле основного показателя. Первое поле = значение KPI. Для значения нужна агрегация (`sum`, `avg`, `min`, `max`, `count`). Второе числовое поле (если задано) трактуется как готовый тренд из датасета либо как целевое значение (в режиме цели).
- **Категории** (для тренда) — поле периода. Когда оно задано, панель вычисляет тренд по двум последним строкам отсортированного датасета: последняя строка — текущее значение, предпоследняя — предыдущее. Сортировка поля периода обязательна (`order: "asc"`). Агрегация для категории не применяется.
- **Фильтры** — локальные фильтры панели. Если поле помечено как управляющее (`correctable=1`), клик по плитке передаёт его значение в глобальные фильтры дашборда.

Дополнительно на полку Значения можно класть строковые поля с особой ролью: `subheader` (используется как подзаголовок панели) и `info` (дополнительная строка информации внизу карточки).

### Логика тренда

Панель вычисляет тренд тремя способами:

- **По двум последним строкам** — задайте поле периода на полку Категории. Процентный тренд: `(текущее − предыдущее) / предыдущее × 100%`; абсолютный (при `absolute=true`): `текущее − предыдущее`.
- **Готовый тренд из датасета** — второе числовое поле на полке Значения используется как заранее посчитанное значение тренда.
- **Режим целевого значения** — включается слагом `delta.delta`; второе поле трактуется как цель, тренд показывает отклонение факта от цели: `(значение − цель) / цель × 100%`.

Слаг `delta.percent` переключает абсолютное/процентное отображение отклонения. По умолчанию рост окрашивается «хорошим» цветом, падение — «плохим»; для показателей, где рост = ухудшение (жалобы, долг, расходы), инверсию знака настраивают в панели свойств визуала тренда (отдельного `config_overrides`-слага для этого нет).

### Правила агрегации

- **Предагрегированный датасет** (значение уже посчитано через `GROUP BY` в SQL) — передавайте агрегацию явно (например, `aggregation="max"`); без агрегации поле значения считается неготовым и плитка выходит пустой.
- **Сырой датасет** — задайте нужную агрегацию явно (`"sum"`, `"avg"`, и т.д.).
- При заданном `category_field` агрегация по умолчанию = `"max"`.

## Параметры добавления

Помимо привязки к датасету и полю значения, при добавлении доступны параметры:

| Параметр | Назначение |
|----------|-----------|
| `x`, `y`, `w`, `h` | Позиция и размер плитки в сетке отчёта |
| `value_field` | Поле основного показателя (обязательно) |
| `aggregation` | Агрегация значения (`sum`, `avg`, `min`, `max`, `count`) |
| `category_field` | Поле периода для вычисления тренда |
| `subheader_field` | Строковое поле, отображаемое как подзаголовок плитки |
| `info_fields` | Список полей через запятую — дополнительные инфо-строки внизу карточки |
| `where_filter` | Предфильтр данных компонента |

## Формат данных

Особого формата не требуется. Для простой плитки достаточно одного числового поля. Для тренда «по периодам» нужен датасет с полем периода и числовой метрикой, отсортированный по периоду, где минимум две строки (текущий и предыдущий период). Для режима цели — две числовые колонки (факт и план).

## Пример

Простая плитка KPI по предагрегированному датасету:

```python
component_crud(
    action="add",
    report_id=35,
    component_type="HsTotalsPanelV2",
    title="Количество заявок",
    dataset_id=54,
    value_field="count",
    aggregation="sum",
    x=0, y=0, w=12, h=6,
)
```

Плитка с трендом по периодам — поле периода задаётся через `category_field`:

```python
component_crud(
    action="add",
    report_id=35,
    component_type="HsTotalsPanelV2",
    title="Выручка за месяц",
    dataset_id=54,
    value_field="revenue",
    category_field="month",
    aggregation="sum",
    x=0, y=6, w=12, h=6,
)
```

Крупное значение с цветом и подзаголовком — оформление через `config_overrides`:

```python
component_crud(
    action="add",
    report_id=35,
    component_type="HsTotalsPanelV2",
    title="Выполнение плана",
    dataset_id=54,
    value_field="actual",
    aggregation="sum",
    subheader_field="period_label",
    config_overrides={
        "visuals.value.color": "rgba(37,99,235,1)",
        "visuals.value.font.size": 3.2,
        "visuals.value.font.weight": 700,
        "delta.delta": True,        # режим целевого значения (2-е поле = цель)
        "numberPrecision": 0,       # значение целыми числами
    },
)
```

Здесь `component_crud` — это RPC-метод MCP-сервера (вызов инструмента), а не REST-эндпоинт; `component_idx` в других действиях (`get`, `update`, `delete`, `data`) — 0-based индекс компонента в отчёте.

## JSON-конфигурация

Сервер собирает и хранит конфигурацию компонента в JSON. Ниже — аннотированная структура панели показателей: рядом с каждым ключом указано, что он задаёт и каким слагом управляется (полное соответствие — в таблице «Все настройки»).

```jsonc
{
  "type": "HsTotalsPanelV2",                    // тип компонента (его отдаёт component_crud action="types_list")
  "config": {
    "title": "Выручка за месяц",                // заголовок плитки (он же caption)
    "caption": "Выручка за месяц",              // дублирует заголовок для блока caption
    "subtitle": "",                             // подзаголовок (текст блока subcaption)
    "chartType": "totalsPanelV2",               // внутренний тип (фиксирован)
    "orientation": "v",                         // компоновка элементов: "v"|"h"
    "showtitle": true,                          // показывать заголовок            ← слаг showtitle
    "precision": -1,                            // знаков после запятой значения   ← слаг numberPrecision (-1 = авто)
    "percentPrecision": 1,                      // знаков после запятой тренда (%)  ← слаг percentPrecision
    "backgroundColor": "rgba(255, 255, 255, 1)",// цвет фона плитки                ← слаг bgColor
    "maximizable": false,                       // кнопка разворота на весь экран
    "autoApply": true,                          // авто-применение фильтров (всегда true для этого типа)
    "noexport": false,                          // запрет экспорта                 ← слаг noexport
    "nocopy": false,                            // запрет копирования              ← слаг nocopy
    "margin":  { "l": 10, "r": 10, "t": 10, "b": 0, "pad": 0 },   // отступы       ← слаги margin.l/r/t/b/pad
    "outline": { "enabled": false, "width": 4 },                  // рамка         ← слаги outline.enabled/width
    "axes": [                                   // полки данных (поля привязываются параметрами при добавлении)
      { "name": "filters",    "type": "filters",    "fields": [] },              // фильтры плитки (correctable=1 → управляющий)
      { "name": "Categories", "type": "categories", "fields": [                  // поле периода для тренда ← category_field
          { "name": "month", "alias": "Месяц", "type": "string", "datasetId": 54, "agg": null, "order": "asc" }
      ]},
      { "name": "Indicator",  "type": "values",     "fields": [                  // показатель ← value_field + aggregation
          { "name": "revenue", "alias": "Выручка", "type": "number", "agg": "sum", "datasetId": 54 }
          // второе число здесь = готовый тренд или цель (для delta.delta);
          // строковое поле с valueType:"subheader" ← subheader_field;
          // строковые поля с valueType:"info" ← info_fields
      ], "sortable": true }
    ],
    "visuals": [                                // оформление каждого элемента плитки (по якорю anchor)
      { "anchor": "value",      "visible": true, "thresholdForPercent": 100,     // основное значение
        "font": { "size": 2.8, "weight": 600 } },                               // ← visuals.value.font.size / .weight
      { "anchor": "caption",    "visible": true, "font": { "size": 1 } },        // заголовок  ← visuals.caption.*
      { "anchor": "subcaption", "visible": true, "font": { "size": 0.8 } },      // подзаголовок ← visuals.subcaption.*
      { "anchor": "trend",      "visible": true, "font": { "size": 1.2 } }       // тренд      ← visuals.trend.*
      // hasTarget на якоре trend ← слаг delta.delta (режим цели);
      // absolute ← слаг delta.percent (абс./процент отклонения)
    ]
  }
}
```

> Точность значения задаётся слагом `numberPrecision` (пишется в `precision`; `-1` — авто), точность тренда в процентах — `percentPrecision`. Цвет и шрифт каждого элемента — слагами `visuals.<элемент>.*` (`value`, `caption`, `subcaption`, `trend`), которые пишутся в соответствующий объект `visuals[anchor]`. Размер шрифта (`font.size`) задаётся в `rem`: `2.8` — крупное значение, `1` — заголовок, `0.8` — подзаголовок.

Каждый ключ внутри `config` соответствует строке в таблице ниже. Колонка **JSON-путь** показывает, где значение хранится в конфиге. Для вложенных параметров используется запись `объект[раздел].ключ` (например, `visuals[trend].hasTarget` — ключ `hasTarget` внутри элемента тренда). Пустой путь означает верхний уровень `config`.
