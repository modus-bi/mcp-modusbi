# Иерархический фильтр

Тип компонента: `HsHierarchicalFilterPanel` — управляющий компонент.

> Это фильтр-компонент: он управляет другими виджетами дашборда, а сам данные не отображает — только ограничивает их по иерархии.

## Описание

Иерархический фильтр — это панель фильтрации, в которой поля выстроены в уровни дерева: выбор значения на верхнем уровне автоматически сужает доступные значения на нижнем. В отличие от обычной панели фильтров, где каждое поле работает независимо, здесь уровни связаны между собой автоматически.

Компонент отображается как набор выпадающих списков с древовидным содержимым (например: Федеральный округ → Регион → Город). Порядок полей задаёт иерархию: первое поле — корневой (верхний) уровень, последнее — конечный (нижний). Все уровни загружаются одним запросом значений (DISTINCT), затем дерево собирается на стороне отображения.

Компонент требует датасет, но использует его только как справочник: не как источник чисел для графика, а как набор уникальных значений для уровней иерархии. Агрегация для полей фильтра не применяется.

## Когда применять

- Географическая иерархия: Федеральный округ → Регион → Город.
- Временная иерархия: Год → Квартал → Месяц → Дата.
- Категорийная иерархия: Категория → Подкатегория → Товар.
- Организационная иерархия: Дирекция → Отдел → Сотрудник.
- Любая фильтрация, где значения нижнего уровня зависят от выбора верхнего.

## Когда не подходит

- Независимые фильтры без иерархии — используйте обычную панель фильтров (`HsFilterControlPanel`), см. [Фильтры и каскады](../filter-patterns.md).
- Фильтрация по диапазону или по сравнению — иерархический фильтр поддерживает только выбор по значениям.
- Слайдер, период, кнопки — поддерживается только дерево выпадающих списков.
- Смешивание обычных и иерархических полей в одном компоненте — разместите их как отдельные компоненты.

## Уровни иерархии

> Датасет требуется как справочник значений. Агрегация к уровням не применяется.

Уровни задаются полями на единственной оси `filters`. **Порядок полей критичен**: первое поле — верхний уровень, последнее — нижний. Каждый следующий уровень автоматически фильтруется по выбору предыдущего.

> Порядок задания полей и есть порядок иерархии. Первое поле — самый верхний уровень (пользователь видит его первым), последнее — самый нижний.

При добавлении через `component_crud` поля передаются так:

- `category_field` — первый (верхний) уровень иерархии;
- `value_field` — остальные уровни через запятую, в порядке сверху вниз.

Например, `category_field="region"`, `value_field="district,city"` даёт иерархию: Регион → Район → Город. Все поля приводятся к строковому типу, агрегация для них не назначается.

Каждый уровень создаёт запись в глобальных фильтрах отчёта по своему `alias`. Чтобы фильтр влиял на данные графиков и таблиц, поля этих компонентов должны совпадать по `alias` с уровнями иерархии — как и для обычных фильтров (см. [Фильтры и каскады](../filter-patterns.md), раздел про `filter_field_add` на каждом data-компоненте).

> Если на дашборде несколько иерархических фильтров, задавайте уникальные `alias` полей у каждого — иначе их записи в глобальных фильтрах перезапишут друг друга.

## Параметры добавления

| Параметр | Назначение |
|----------|-----------|
| `dataset_id` | Датасет-справочник, из которого берутся значения уровней (обязателен) |
| `category_field` | Поле верхнего (корневого) уровня иерархии |
| `value_field` | Поля остальных уровней через запятую, сверху вниз |
| `x`, `y`, `w`, `h` | Позиция и размер компонента в сетке отчёта |
| `config_overrides` | Слаги настройки поведения и оформления (см. таблицу ниже) |

Рекомендуемая высота для удобного отображения дерева — `h` от 8 и выше; минимально допустимо `h=2`.

## Пример

> Примеры ниже используют RPC-метод `component_crud` MCP-сервера (вызов инструмента), а не REST-эндпоинт портала. Первый параметр `action` выбирает конкретную операцию.

Двухуровневая географическая иерархия (Регион → Город):

```python
component_crud(
    action="add",
    report_id=35,
    component_type="HsHierarchicalFilterPanel",
    title="Иерархический фильтр",
    dataset_id=54,
    category_field="region",
    value_field="city",
    x=0, y=0, w=24, h=10,
)
```

Трёхуровневая иерархия (Категория → Подкатегория → Товар) с единичным выбором и заголовком:

```python
component_crud(
    action="add",
    report_id=35,
    component_type="HsHierarchicalFilterPanel",
    title="Каталог",
    dataset_id=54,
    category_field="category",
    value_field="subcategory,product",
    x=0, y=0, w=24, h=12,
    config_overrides={
        "hierFilter.multipleChoice": False,
        "hierFilter.bothChoice": False,
        "hierFilter.filterTitle": "Выберите товар:",
        "hierFilter.headerWidth": 25,
    },
)
```

Большой справочник (тысячи значений) — поиск выполняется в базе при вводе:

```python
component_crud(
    action="add",
    report_id=35,
    component_type="HsHierarchicalFilterPanel",
    title="Номенклатура",
    dataset_id=54,
    category_field="group",
    value_field="item",
    x=0, y=0, w=24, h=10,
    config_overrides={
        "hierFilter.searchInBaseMode": True,
        "hierFilter.searchInBaseMinNumber": 3,
        "hierFilter.noLoadOptions": True,
    },
)
```

Здесь `component_crud` — это RPC-метод MCP-сервера (вызов инструмента), а не REST-эндпоинт; `component_idx` в других действиях — 0-based индекс компонента в отчёте.

## JSON-конфигурация

Сервер собирает и хранит конфигурацию компонента в JSON. Ниже — аннотированная структура: рядом с ключом указано, что он задаёт и каким слагом управляется (полное соответствие — в таблице «Все настройки»).

```jsonc
{
  "type": "HsHierarchicalFilterPanel",          // тип компонента
  "config": {
    "title": "Иерархический фильтр",            // заголовок компонента
    "chartType": "hierarchicalFilter",          // внутренний тип фильтра (задаёт сервер)
    "showtitle": true,                          // показывать заголовок            ← слаг showtitle
    "noexport": true,                           // не экспортировать (умолчание для фильтров)
    "nocopy": true,                             // запрет копирования
    "autoApply": true,                          // применять выбор автоматически
    "bgColor": "rgba(255,255,255,1)",           // цвет фона                       ← слаг bgColor
    "margin":  { "l": 5, "r": 10, "t": 10, "b": 5, "pad": 0 },  // отступы (умолчания) ← слаги margin.*
    "outline": { "enabled": false, "width": 4 },               // рамка            ← слаги outline.*

    // Поведение фильтра (слаги hierFilter.*):
    "multipleChoice": true,                     // множественный выбор             ← слаг hierFilter.multipleChoice
    "bothChoice": true,                         // кнопка очистки                  ← слаг hierFilter.bothChoice
    "inversed": false,                          // инвертированный режим (NOT IN)  ← слаг hierFilter.inversed
    "hideTitle": false,                         // скрыть заголовок фильтра        ← слаг hierFilter.hideTitle
    "filterTitle": "",                          // текст заголовка фильтра         ← слаг hierFilter.filterTitle
    "headerWidth": 0,                           // ширина заголовка в % (0=auto)   ← слаг hierFilter.headerWidth
    "searchInBaseMode": false,                  // поиск значений в базе при вводе ← слаг hierFilter.searchInBaseMode
    "searchInBaseMinNumber": 1,                 // минимум символов для поиска     ← слаг hierFilter.searchInBaseMinNumber
    "updateOnCloseDropdown": true,              // применять при закрытии списка   ← слаг hierFilter.updateOnCloseDropdown
    "updateOnApply": false,                     // применять по кнопке «Применить» ← слаг hierFilter.updateOnApply
    "noLoadOptions": true,                       // отложенная загрузка значений    ← слаг hierFilter.noLoadOptions
    "sortSelectedOptionsToTop": false,          // выбранные значения вверху       ← слаг hierFilter.sortSelectedOptionsToTop

    "axes": [                                   // единственная ось — filters
      { "name": "filters", "type": "filters", "fields": [        // уровни иерархии по порядку
          { "name": "region", "alias": "Регион", "type": "string", "agg": null, "datasetId": 54 },
          { "name": "city",   "alias": "Город",  "type": "string", "agg": null, "datasetId": 54 }
      ]}
    ]
  }
}
```

> Поля оси `filters` идут строго в порядке иерархии: первый элемент массива — верхний уровень, последний — нижний.

Каждый ключ внутри `config` соответствует строке в таблице ниже. Колонка **JSON-путь** показывает, где значение хранится в конфиге. Пустой путь означает верхний уровень `config`.

## Все настройки (config_overrides)

Полный перечень слагов этого типа — специфичные для типа и общие оформительские. Колонки: **UI-контрол** — название в панели настроек портала (пусто = прямого UI-контрола нет, настройка только через `config_overrides`); **MCP-слаг** — ключ в `config_overrides`; **JSON-путь** — куда настройка пишется в конфиг и откуда её читает отображение (это и есть «фронт-ключ»; путь в `(скобках)` обрабатывается секционно — итоговый ключ внутри указанной секции конфига); **Тип**; **По умолчанию**. Полный справочник по всем типам — [Справочник настроек](../slugs/by-type.md).
