# Контейнер страниц

Тип компонента: `HsPageContainer`

## Описание

Контейнер страниц — утилитарный компонент-контейнер, который переключает отображение визуализаций (и их групп) как страницы или вкладки внутри одного отчёта, без его перезагрузки. Каждая страница содержит один или несколько дочерних компонентов; при клике по вкладке показывается привязанная к ней группа, а остальные скрываются. Данные не перезагружаются при переключении — дочерние компоненты загружены заранее.

Сам контейнер не привязан к датасету и не отображает данные: он лишь хранит список страниц (вкладок) и оформление панели ярлычков. Дополнительно числовой показатель можно вывести прямо в заголовке вкладки (через ось значений), но основное назначение — навигация.

## Когда применять

- Несколько визуализаций должны делить одну область дашборда, переключаясь по клику.
- Большой отчёт нужно разбить на логические разделы (страницы) без создания отдельных дашбордов.
- Нужно показать разные представления одних данных (таблица / график / карта) в одном месте.
- Требуется двухуровневая навигация — вложенный контейнер внутри другого.

## Когда не подходит

- Переходы между разными отчётами — используйте [панель вкладок](tabs-panel.md) (`HsTabsPanel`), это навигация по ссылкам.
- Условное переключение по значению поля — используйте [переключатель](switch-panel.md) (`HsSwitchControlPanel`).
- Фильтрация данных вместо переключения страниц — используйте [панель фильтра](filter-panel.md) (`HsFilterControlPanel`).
- На дашборде всего 1–2 компонента — контейнер избыточен, размещайте их напрямую.

## Навигация и страницы

Датасет не требуется: контейнер относится к утилитарным типам без привязки к данным (у него нет агрегации и осей категорий). Структура навигации хранится в массиве `config.visuals` — каждый элемент описывает одну страницу (вкладку):

- `id` — числовой идентификатор страницы (1, 2, 3, …);
- `labelText` — текст на ярлычке/кнопке вкладки;
- `anchor` — строковый якорь страницы для привязки дочерних компонентов;
- `tabWidth` — ширина ярлычка: `{"type": "auto"|"percent"|"fixed", "value": …}`;
- `isHtml` — разрешить HTML-теги в `labelText` (по умолчанию `false`);
- `tab` — id числового поля, чьё значение выводится в заголовке вкладки как показатель (по умолчанию `null`). Поле берётся не из датасета самого контейнера (его нет), а из привязанных к вкладке дочерних компонентов.

Страницами управляют действия RPC-метода `component_axes`:

| Действие | Назначение | Ключевые параметры |
|----------|-----------|--------------------|
| `page_list` | Список страниц контейнера | `report_id`, `component_idx` |
| `page_add` | Добавить страницу (вкладку) | `report_id`, `component_idx`, `label_text` (текст вкладки) |
| `page_rename` | Переименовать страницу | `report_id`, `component_idx`, `page_id`, `label_text` (новый текст) |
| `page_remove` | Удалить страницу | `report_id`, `component_idx`, `page_id` |

Действие `page_remove` необратимо удаляет страницу вместе со всеми привязанными к ней дочерними компонентами.

Привязка дочерних компонентов к странице выполняется через режим группировки в веб-интерфейсе: активируется нужная вкладка, затем компонент добавляется в группу при выбранной вкладке. Сам контейнер не содержит данных — он лишь переключает видимость дочерних компонентов.

## Параметры добавления

Контейнер добавляется общим действием `add` RPC-метода `component_crud` как тип без датасета — `dataset_id`, поля и агрегация не нужны. При создании контейнер заводится без страниц (`visuals` — пустой массив); страницы добавляются отдельными вызовами `component_axes(action="page_add", …)`.

| Параметр | Назначение |
|----------|-----------|
| `report_id` | Отчёт, в который добавляется компонент (обязателен) |
| `component_type` | `"HsPageContainer"` |
| `title` | Заголовок компонента (показывается при `showtitle=true`) |
| `x`, `y`, `w`, `h` | Позиция и размер контейнера в сетке отчёта |
| `showtitle` | Показывать заголовок панели над вкладками (по умолчанию `true`) |

Тонкая настройка оформления панели вкладок доступна через `config_overrides` — общие оформительские слаги (`bgColor`, `margin.*`, `outline.*`); см. таблицу «Все настройки» ниже. После добавления контейнера страницы заводятся действиями `component_axes(action="page_add", …)`.

## Пример

Добавление контейнера на всю ширину дашборда:

```python
component_crud(
    action="add",
    report_id=35,
    component_type="HsPageContainer",
    title="Разделы отчёта",
    x=0, y=0, w=48, h=16,
)
```

Заведение трёх страниц (вкладок) в добавленный контейнер (индекс `component_idx` — 0-based):

```python
component_axes(action="page_add", report_id=35, component_idx=0, label_text="Обзор")
component_axes(action="page_add", report_id=35, component_idx=0, label_text="Детализация")
component_axes(action="page_add", report_id=35, component_idx=0, label_text="Карта")
```

Каждый вызов возвращает `page_id` созданной страницы. Переименование и удаление страницы по этому id:

```python
component_axes(action="page_rename", report_id=35, component_idx=0, page_id=3, label_text="Геоаналитика")
component_axes(action="page_remove", report_id=35, component_idx=0, page_id=3)
```

Здесь `component_crud` и `component_axes` — это RPC-методы MCP-сервера (вызовы инструментов), а не REST-эндпоинты; `component_idx` — 0-based индекс компонента в отчёте. Дочерние компоненты раскладываются по страницам в режиме группировки веб-интерфейса.

## JSON-конфигурация

Сервер собирает и хранит конфигурацию компонента в JSON. Ниже — аннотированная структура контейнера страниц: у утилитарного типа нет осей категорий, серий и агрегации — только список страниц и оформление панели вкладок.

```jsonc
{
  "type": "HsPageContainer",                      // тип компонента (его отдаёт component_crud action="types_list")
  "config": {
    "title": "Разделы отчёта",                    // заголовок панели (виден только при showtitle=true)
    "chartType": "pageContainer",                 // внутренний тип (фиксирован)
    "showtitle": true,                            // показывать заголовок панели над вкладками     ← слаг showtitle
    "noexport": true,                             // контейнер исключён из экспорта                ← слаг noexport
    "nocopy": true,                               // запрет копирования контейнера                 ← слаг nocopy
    "bgColor": "rgba(255, 255, 255, 1)",          // цвет фона панели вкладок                      ← слаг bgColor
    "margin":  { "l": 0, "r": 0, "t": 0, "b": 0, "pad": 0 },   // отступы контейнера               ← слаги margin.l/r/t/b/pad
    "outline": { "enabled": false, "width": 4 },               // рамка вокруг контейнера          ← слаги outline.enabled/width/color
    "hideSpinner": false,                         // скрыть спиннер загрузки при обновлении данных ← слаг hideSpinner
    "dirty": false,                               // служебный флаг несохранённых изменений
    "visuals": [                                  // СТРАНИЦЫ (вкладки) — управляются action page_*
      {
        "id": 1,                                  //   числовой id страницы
        "anchor": "Обзор",                        //   якорь для привязки дочерних компонентов
        "labelText": "Обзор",                     //   текст на ярлычке/кнопке вкладки
        "tabWidth": { "type": "auto", "value": "auto", "label": "Авто" },  // ширина ярлычка
        "isHtml": false,                          //   разрешить HTML-теги в labelText
        "tab": null                               //   id поля из оси значений для показателя в заголовке (опц.)
      }
    ]
  }
}
```

> Контейнер не содержит данных: `dataset_id` всегда `null`, а сами дочерние компоненты хранятся отдельно (привязка по странице через режим группировки веб-интерфейса). Полная конфигурация контейнера доступна в JSON-представлении отчёта.

Каждый ключ внутри `config` соответствует строке в таблице ниже. Колонка **JSON-путь** показывает, где значение хранится в конфиге. Пустой путь означает верхний уровень `config`.

## Все настройки (config_overrides)

Полный перечень слагов этого типа — специфичные для типа и общие оформительские. Колонки: **UI-контрол** — название в панели настроек портала (пусто = прямого UI-контрола нет, настройка только через `config_overrides`); **MCP-слаг** — ключ в `config_overrides`; **JSON-путь** — куда настройка пишется в конфиг и откуда её читает отображение (это и есть «фронт-ключ»; путь в `(скобках)` обрабатывается секционно — итоговый ключ внутри указанной секции конфига); **Тип**; **По умолчанию**. Полный справочник по всем типам — [Справочник настроек](../slugs/by-type.md).
