# Таблица

Тип компонента: `HsTableReactabularChart`

## Описание

Таблица — основной табличный компонент для вывода детализированных и агрегированных данных. Это самый функционально насыщенный тип: он умеет показывать строки без группировки, сводить данные по измерениям с агрегацией, строить динамические колонки по значениям поля-разреза, форматировать ячейки по условиям, замораживать колонки, считать подытоги и итоговую строку, а также работать источником фильтра для других компонентов отчёта.

Если коротко: бары и круговые отвечают на вопрос «кто больше», а таблица показывает сами данные — точные значения по строкам и колонкам, в том числе с HTML-разметкой и ссылками. Спарклайны и цветовая подсветка ячеек настраиваются через условное форматирование (`rules`).

## Когда применять

- Детализированный вывод данных (все поля построчно) — обычно конечный уровень дашборда.
- Агрегированные данные с группировкой по одному или нескольким измерениям.
- Кросс-таблица: динамические колонки, образованные уникальными значениями поля-разреза (ось серий).
- Ячейки с HTML-разметкой (цветные ячейки, ссылки, изображения).
- Таблица как фильтр: клик по строке применяет глобальный фильтр к остальным компонентам.
- Экспорт больших объёмов данных.

## Когда не подходит

- Сводная таблица с перестановкой строк/колонок и мерами — лучше тип `HsPivotChart`.
- Сравнение двух объектов с дельтой — лучше `HsComparisonChart`.
- Визуальный тренд, сравнение категорий или доли целого — лучше линейная, столбчатая или круговая диаграмма.
- Одиночные KPI-метрики — лучше `HsTotalsPanelV2`.

## Поля и оси (колонки таблицы)

> Определения осей и агрегации см. в [Глоссарии](../../../GLOSSARY.md).

Ось — это привязка поля данных к определённой роли (группировка, значения, разрез, фильтр). Таблица использует четыре оси. Колонки результата формируются из оси значений (а при заполненной оси серий — динамически из её уникальных значений):

- **Значения** (обязательная ось) — поля с данными, которые становятся колонками таблицы. Сюда попадают числовые, строковые, датовые и вычисляемые поля. Это единственная обязательная ось.
- **Категории** (необязательно) — поля группировки. Их уникальные комбинации формируют строки, а числовые значения сворачиваются по правилам агрегации. Если ось пуста — выводится детализация (каждая строка датасета как есть, без группировки).
- **Серии** (необязательно) — поле-разрез: его уникальные значения превращаются в дополнительные колонки (кросс-таблица).
- **Фильтры** (необязательно) — поля для глобальной фильтрации; их имена должны совпадать с ключами фильтров отчёта.

### Правила агрегации

Агрегация определяет, как несколько строк датасета сводятся в одно значение ячейки. Для таблицы она осмыслена только когда заполнена ось категорий (есть группировка):

- **Детализация без группировки** — категории пусты, агрегация не нужна: используйте `aggregation="none"`, чтобы вывести все строки как есть.
- **Группировка, нужна сумма по категории** — `aggregation="sum"`.
- **Среднее по категории** — `aggregation="avg"` (аналогично `min`, `max`, `count`).
- Строковые, датовые и вычисляемые поля агрегации обычно не получают (`none`/`null`).

В отличие от диаграмм, поля оси категорий в таблице формируют уникальные комбинации строк (как `GROUP BY` в SQL) и сами по себе не становятся отдельными колонками результата — данные приходят через поля оси значений.

## Параметры добавления

Помимо привязки к датасету и полям, при добавлении доступны параметры:

| Параметр | Назначение |
|----------|-----------|
| `x`, `y`, `w`, `h` | Позиция и размер компонента в сетке отчёта |
| `category_field` | Поля группировки (через запятую) — строки таблицы |
| `value_field` | Поля значений (через запятую) — колонки таблицы (обязательно) |
| `value_fields_type` | Тип полей значений: `"number"` или `"string"`; опционально — если не указан, определяется автоматически по типам полей |
| `aggregation` | Агрегация значений (`sum`, `avg`, `min`, `max`, `count`, `none`) |
| `field_titles` | Заголовки колонок (через запятую) |
| `where_filter` | SQL-фильтр, поля которого кладутся на ось фильтров |
| `config_overrides` | Слаги тонкой настройки (см. таблицу ниже) |

Для детализированного вывода всегда передавайте `aggregation="none"` — иначе строки свернутся.

При обновлении существующего компонента вместо `report_id` указывается `component_idx` — 0-based индекс компонента в отчёте.

## Формат данных

Особого формата не требуется. Для детализации подойдёт любая выборка — каждая строка датасета станет строкой таблицы. Для группировки добавьте измерения в `category_field`, а метрики — в `value_field` с агрегацией. Для кросс-таблицы дополнительно укажите поле-разрез на оси серий: его уникальные значения станут заголовками колонок.

## Пример

Детализированная таблица (все строки, без группировки):

```python
component_crud(
    action="add",
    report_id=35,
    component_type="HsTableReactabularChart",
    title="Детали операций",
    dataset_id=68,
    value_field="region,product,summa_rub",
    aggregation="none",
    x=0, y=0, w=48, h=20,
)
```

Таблица с группировкой и агрегацией суммы по категории:

```python
component_crud(
    action="add",
    report_id=35,
    component_type="HsTableReactabularChart",
    title="Продажи по регионам",
    dataset_id=68,
    category_field="region",
    value_field="summa_rub",
    aggregation="sum",
    field_titles="Продажи, руб.",
    x=0, y=0, w=24, h=14,
)
```

Тонкая настройка через слаги: зебра, цвет шапки, счётчик строк в заголовке:

```python
component_crud(
    action="add",
    report_id=35,
    component_type="HsTableReactabularChart",
    title="Реестр",
    dataset_id=68,
    category_field="region",
    value_field="summa_rub",
    aggregation="sum",
    config_overrides={
        "table.zebraType": "even",       # "none" | "odd" | "even"
        "table.zebraColor": "rgba(245,245,245,1)",   # цвет действует при активной зебре
        "table.headersBackground": "rgba(0,120,212,1)",
        "table.headersColor": "rgba(255,255,255,1)",
        "table.showNumberLineInHeader": True,
        "table.precision": 2,
    },
)
```

Здесь `component_crud` — это RPC-метод MCP-сервера (вызов инструмента), а не REST-эндпоинт; `component_idx` в других действиях — 0-based индекс компонента в отчёте.

## JSON-конфигурация

Сервер собирает и хранит конфигурацию компонента в JSON. Ниже — аннотированная структура таблицы: рядом с каждым ключом указано, что он задаёт. Поля привязываются параметрами при добавлении, тонкая настройка идёт через слаги `config_overrides` (полное соответствие — в таблице «Все настройки»).

```jsonc
{
  "type": "HsTableReactabularChart",            // тип компонента (его отдаёт component_crud action="types_list")
  "config": {
    "title": { "text": "Продажи по регионам" }, // заголовок компонента
    "chartType": "table",                       // внутренний тип (фиксирован)
    "visualType": "table",                      // визуальный тип (фиксирован)
    "showtitle": true,                          // показывать заголовок            ← слаг showtitle
    "showNumberLineInHeader": true,             // счётчик строк в заголовке       ← слаг table.showNumberLineInHeader
    "precision": 0,                             // точность чисел (знаков)         ← слаг table.precision
    "bgColor": "rgba(255, 255, 255, 1)",        // цвет фона компонента            ← слаг bgColor
    "noexport": false,                          // запрет экспорта                 ← слаг noexport
    "nocopy": false,                            // запрет копирования              ← слаг nocopy
    "margin":  { "t": 0, "l": 0, "b": 0, "r": 0 },                // отступы       ← слаги margin.t/l/b/r
    "outline": { "enabled": false, "width": 4 },                  // рамка         ← слаги outline.enabled/width
    "zebraType": "none",                        // чередование строк: "none"|"odd"|"even" ← слаг table.zebraType
    "zebraColor": null,                         // цвет строк зебры                ← слаг table.zebraColor
    "headersBackground": null,                  // цвет фона шапки колонок         ← слаг table.headersBackground
    "headersColor": null,                       // цвет текста шапки колонок       ← слаг table.headersColor
    "theme": null,                              // CSS-класс темы таблицы          ← слаг table.theme
    "linkByForRow": null,                       // поле-URL для перехода по строке ← слаг table.linkByForRow
    "axes": [                                   // оси полей (привязка — параметрами при добавлении)
      { "name": "filters",    "type": "filters",    "fields": [] },               // фильтры       ← where_filter
      { "name": "categories", "type": "categories", "fields": [] },               // группировка   ← category_field
      { "name": "series",     "type": "series",     "fields": [] },               // разрез-колонки
      { "name": "y", "type": "values", "selectedFieldIndex": -2, "fields": [      // значения      ← value_field + aggregation
          { "name": "summa_rub", "alias": "Продажи", "type": "number", "agg": "sum", "datasetId": 68 }
      ], "sortable": true }
    ],
    "settings": {                               // режимы таблицы (булевы флаги)
      "AllowResizable": true,                   //   менять ширину колонок мышью
      "AllowSort": true,                        //   сортировка по клику на заголовок
      "AllowSearch": false,                     //   поле поиска над таблицей
      "AllowTree": false,                       //   режим дерева (раскрытие строк)
      "AllowPagination": false,                 //   постраничный вывод
      "AllowColumnDnD": true,                   //   перетаскивание колонок
      "AllowVirtualization": true,              //   виртуализация строк (рекомендуется)
      "AllowAutoWidth": true,                   //   равномерная ширина колонок
      "AllowMultilineHeader": true              //   многострочный заголовок
    },
    "massUpdate": { "enabled": false },         // режим групповой обработки строк
    "rules": [],                                // правила условного форматирования ячеек (подсветка, спарклайны)
    "columns": {},                              // настройки отдельных колонок по id поля
    "visuals": []                               // служебный массив (пуст для таблицы)
  }
}
```

> Зебра (`table.zebraType`) принимает три значения: `"none"` — без чередования, `"odd"` — выделяются нечётные строки, `"even"` — выделяются чётные строки. Цвет выделения задаётся слагом `table.zebraColor` и действует только при активной зебре (`"odd"`/`"even"`).

Каждый ключ внутри `config` соответствует строке в таблице ниже. Колонка **JSON-путь** показывает, где значение хранится в конфиге; пустой путь означает верхний уровень `config`.

## Все настройки (config_overrides)

Полный перечень слагов этого типа — специфичные для типа и общие оформительские. Колонки: **UI-контрол** — название в панели настроек портала (пусто = прямого UI-контрола нет, настройка только через `config_overrides`); **MCP-слаг** — ключ в `config_overrides`; **JSON-путь** — куда настройка пишется в конфиг и откуда её читает отображение (это и есть «фронт-ключ»; путь в `(скобках)` обрабатывается секционно — итоговый ключ внутри указанной секции конфига); **Тип**; **По умолчанию**.
