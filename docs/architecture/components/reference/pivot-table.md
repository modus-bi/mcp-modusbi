# Сводная таблица

Тип компонента: `HsPivotChart`

## Описание

Сводная (pivot) таблица предназначена для многомерного анализа: данные группируются одновременно по строкам и столбцам, образуя кросс-таблицу с автоматическим расчётом промежуточных и общих итогов. В отличие от обычных диаграмм у неё собственный набор осей — строки, столбцы, значения (меры), а также детали, фильтры и «резервные» поля.

Это основной инструмент OLAP-подобного анализа: позволяет смотреть пересечение измерений (например, месяцы × годы), строить многоуровневые иерархии со сворачиванием/разворачиванием и показывать несколько мер одновременно.

## Когда применять

- Многомерный анализ — пересечение строк и столбцов (кросс-таблица).
- Группировка по двум и более измерениям одновременно (месяцы × регионы).
- Иерархический drill-down: Год → Квартал → Месяц → День со сворачиванием уровней.
- Промежуточные и общие итоги по строкам и столбцам.
- Сводные отчёты с несколькими мерами одновременно.

## Когда не подходит

- Простые плоские данные без группировки — используйте обычную таблицу.
- Визуальное сравнение категорий — используйте столбчатую диаграмму.
- Тренд по времени — используйте линейную диаграмму.
- Менее двух измерений — сводная таблица избыточна, достаточно обычной таблицы.

## Поля и оси

У сводной таблицы шесть типов осей. Для базового отчёта достаточно строк и значений; столбцы добавляют второе измерение в «шапку».

- **Строки** (`rows`) — поля вертикальной группировки. Несколько полей образуют многоуровневую иерархию (аккордеон): порядок полей задаёт глубину. Поддерживаются текстовые, числовые и датовые поля. Агрегация не применяется (поля группируют, а не считают).
- **Столбцы** (`columns`) — поля горизонтальной группировки, формируют «шапку» кросс-таблицы. Несколько полей дают многоуровневый заголовок (например, Год → Пол).
- **Значения** (`values`) — числовые меры; отображаются в ячейках на пересечении строк и столбцов. Поддерживается несколько мер сразу, а также вычисляемые поля.
- **Фильтры** (`filters`) — поля, связываемые с глобальными фильтрами отчёта по совпадению алиаса/имени.
- **Детали** (`details`) — ось для колонок справа от самого глубокого уровня строк с неагрегированными (сырыми) данными. Поддерживается бэком, но в типовых конфигурациях не используется (остаётся пустой); заполняется вручную через интерфейс или API.
- **Резервные** (`spares`) — поля, доступные пользователю в режиме просмотра через боковую панель: их можно перетаскивать на строки/столбцы интерактивно, без входа в редактирование (self-service режим). Ось существует только у этого типа.

### Правила агрегации

Для сводной таблицы агрегация определяется не на уровне оси, а на уровне поля или датасета:

- **Меры со встроенной агрегацией** — если поле значения уже агрегируется в датасете, в сводной оно сворачивается автоматически. Агрегацию поля можно переопределить через свойство `agg` поля (`sum`, `avg`, `min`, `max`, `count` или `null`) — явное значение имеет приоритет над агрегацией датасета, а `null` означает наследование агрегации из датасета.
- **Поля строк и столбцов** агрегацию не используют: они группируют данные, формируя оси таблицы.

## Параметры добавления

Помимо привязки к датасету, при добавлении компонента доступны параметры:

| Параметр | Назначение |
|----------|-----------|
| `x`, `y`, `w`, `h` | Позиция и размер компонента в сетке отчёта |
| `row_fields` | Поля строк через запятую (например, `"region,city"`) — задают иерархию строк |
| `column_fields` | Поля столбцов через запятую (например, `"year,quarter"`) — задают «шапку» |
| `value_field` | Поле(я)-меры (числовые), которые выводятся в ячейках |
| `category_field` | Альтернатива `row_fields` для одного поля строк (используется как единственная строка, если `row_fields` не задан) |
| `field_titles` | Подписи полей в интерфейсе |

## Формат данных

Особого формата не требуется: подойдёт обычная таблица «измерения + числовые метрики». Для иерархии строк перечислите поля в `row_fields` в порядке вложенности (внешний уровень — первым). Для второго измерения в «шапке» укажите поля в `column_fields`. Производные измерения (год/квартал/месяц из даты) удобно готовить в датасете или вычисляемыми полями.

## Пример

Классическая кросс-таблица: строки — наименование, столбцы — категория, значение — сумма.

```python
component_crud(
    action="add",
    report_id=<id отчёта>,
    component_type="HsPivotChart",
    title="Сводная таблица",
    dataset_id=<id датасета>,
    row_fields="Наименование",
    column_fields="Категория",
    value_field="Значение",
    x=0, y=0, w=24, h=16,
)
```

Многоуровневая иерархия строк с двумя мерами: строки сворачиваются по уровням, столбцы дают разрез по стадии.

```python
component_crud(
    action="add",
    report_id=<id отчёта>,
    component_type="HsPivotChart",
    title="Трудозатраты по исполнителям",
    dataset_id=<id датасета>,
    row_fields="Исполнитель,Дата регистрации",
    column_fields="Стадия задачи",
    value_field="Трудозатраты,ПрЗавершения",
    x=0, y=0, w=24, h=16,
)
```

Оформление и итоги настраиваются слагами через `config_overrides` (светлая тема, убраны общие итоги, фирменная шапка):

```python
component_crud(
    action="update",
    report_id=<id отчёта>,
    component_idx=0,
    config_overrides={
        "pivot.theme": "light",
        "pivot.headerBackgroundColor": "rgba(21,101,192,1)",
        "pivot.headerTextColor": "rgba(255,255,255,1)",
        "pivot.headerAling": "center",  # написание слага намеренное (соответствует фронту)
        "totals.noSums": True,
    },
)
```

Здесь `component_crud` — это RPC-метод MCP-сервера (вызов инструмента), а не REST-эндпоинт; `component_idx` в действиях `update`/`get`/`delete` — 0-based индекс компонента в отчёте.

## JSON-конфигурация

Сервер собирает и хранит конфигурацию компонента в JSON. Ниже — аннотированная структура сводной таблицы: рядом с каждым ключом указано, что он задаёт и каким слагом управляется (полное соответствие — в таблице «Все настройки»).

```jsonc
{
  "type": "HsPivotChart",                       // тип компонента (его отдаёт component_crud action="types_list")
  "config": {
    "title": "Сводная таблица",                 // заголовок компонента
    "chartType": "pivotChart",                  // внутренний тип (фиксирован)
    "showtitle": true,                          // показывать заголовок            ← слаг showtitle
    "noexport": false,                          // запрет экспорта                 ← слаг noexport
    "nocopy": false,                            // запрет копирования данных       ← слаг nocopy
    "autoApply": true,                          // авто-применение фильтров
    "bgColor": "rgba(255, 255, 255, 1)",        // цвет фона                       ← слаг bgColor
    "autoHeightEnabled": true,                  // авто-высота строк/шапки         ← слаг pivot.autoHeightEnabled
    "autoWidthEnabled": true,                   // авто-ширина колонок             ← слаг pivot.autoWidthEnabled
    "margin":  { "l": 5, "r": 10, "t": 10, "b": 5, "pad": 0 },   // отступы        ← слаги margin.l/r/t/b/pad
    "outline": { "enabled": false, "width": 4 },                 // рамка          ← слаги outline.enabled/width
    "theme": null,                              // тема: null|"light"              ← слаг pivot.theme
    "headerBackgroundColor": "",                // фон шапки                       ← слаг pivot.headerBackgroundColor
    "headerTextColor": "",                      // цвет текста шапки               ← слаг pivot.headerTextColor
    "headerHorTextAlignment": "left",           // выравнивание шапки              ← слаг pivot.headerAling
    "isNoSums": false,                          // скрыть все итоги                ← слаг totals.noSums
    "isNoGrandSumsX": false,                    // скрыть промежуточные по строкам ← слаг totals.noGrandSumsX
    "isNoGrandSumsY": false,                    // скрыть итоги по столбцам        ← слаг totals.noGrandSumsY
    "sumRowAtTop": false,                       // строка итогов сверху            ← слаг totals.sumRowAtTop
    "sumColumnAtLeft": false,                   // столбец итогов слева            ← слаг totals.sumColumnAtLeft
    "isGrandSumsFixed": false,                  // закрепить итоги при прокрутке   ← слаг totals.grandSumsFixed
    "axes": [                                   // оси (поля привязываются параметрами при добавлении)
      { "name": "filters", "type": "filters", "fields": [] },                  // фильтры компонента
      { "name": "rows",    "type": "rows",    "fields": [                      // ось строк      ← row_fields
          { "name": "Исполнитель", "alias": "Исполнитель", "type": "string", "datasetId": <id датасета> }
      ]},
      { "name": "columns", "type": "columns", "fields": [                      // ось столбцов   ← column_fields
          { "name": "Стадия задачи", "alias": "Стадия задачи", "type": "string", "datasetId": <id датасета> }
      ]},
      { "name": "spares",  "type": "spares",  "fields": [] },                  // резервные поля (self-service)
      { "name": "values",  "type": "values",  "sortable": true, "fields": [    // ось значений   ← value_field
          { "name": "Трудозатраты", "alias": "Трудозатраты", "type": "number", "datasetId": <id датасета>, "agg": null }  // null = наследовать агрегацию датасета
      ]}
      // ось details поддерживается, но в типовых конфигурациях отсутствует
    ],
    "columns": {                                // оформление колонок по id поля
      "Трудозатраты_X7xekZ": {                  //   ключ = id поля из axes[].fields[].id
        "valueSeparator": true,                 //   разделитель разрядов 1 000 000 ← слаг columns.{поле}.valueSeparator
        "precision": 2,                         //   знаков после запятой           ← слаг columns.{поле}.precision
        "suffix": " ч.",                        //   суффикс-единица                ← слаг columns.{поле}.suffix
        "isHideSame": false                     //   скрывать повторы в строках     ← слаг columns.{поле}.isHideSame
      }
    },
    "rules": []                                 // правила условного форматирования (slug rules.{N}.*)
  }
}
```

> Настройки колонок (`config.columns`) ключуются по `id` конкретного поля. Чтобы узнать `id`, запросите конфиг через `component_crud(action="get", ...)` и возьмите `id` нужного поля из `axes[].fields[]` — этот ключ и используется в слаге `columns.{поле}.{свойство}`.

Каждый ключ внутри `config` соответствует строке в таблице ниже. Колонка **JSON-путь** показывает, где значение хранится в конфиге. Для вложенных параметров используется запись `объект[раздел].ключ`. Пустой путь означает верхний уровень `config`.

## Все настройки (config_overrides)

Полный перечень слагов этого типа — специфичные для типа и общие оформительские. Колонки: **UI-контрол** — название в панели настроек портала (пусто = прямого UI-контрола нет, настройка только через `config_overrides`); **MCP-слаг** — ключ в `config_overrides`; **JSON-путь** — куда настройка пишется в конфиг и откуда её читает отображение (это и есть «фронт-ключ»; путь в `(скобках)` обрабатывается секционно — итоговый ключ внутри указанной секции конфига); **Тип**; **По умолчанию**.
