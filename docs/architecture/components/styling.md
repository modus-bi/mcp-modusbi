# Стилизация отчётов

Внешний вид отчёта в ModusBI настраивается на двух разных уровнях. Их легко перепутать,
потому что оба меняют то, как отчёт выглядит, но работают они по-разному и решают разные
задачи. Этот файл объясняет, чем они отличаются, когда применять каждый и какие приёмы
безопасны, а какие ломают раскладку.

Базовые термины (`компонент`, `config`, `слаг`, `config_overrides`, `рендер`) определены в
[../../GLOSSARY.md](../../GLOSSARY.md). Каталог типов компонентов — в
[README.md этой папки](README.md). Принцип слагов — в
[../concepts/components-json-slugs.md](../concepts/components-json-slugs.md).

---

## Два уровня стиля

| Уровень | Чем настраивается | На что влияет |
|---|---|---|
| **Стиль компонента** (per-component) | `config_overrides` — слаги и пресеты, через инструменты `component_crud` или `component_styling` | Один конкретный компонент: его цвета, легенда, шрифты, рамка, отступы |
| **Стиль отчёта** (per-report) | CSS-код в поле отчёта, через `style_operations` | Весь отчёт целиком: шапка, сетка, все таблицы, диаграммы, фильтры, скроллбары |

Различие простое: слаги в `config_overrides` правят настройки **внутри** одного компонента
(они хранятся в его `config`). CSS через `style_operations` — это таблица стилей всего отчёта,
которая применяется ко **всем** его элементам сразу, по CSS-селекторам.

### Когда что выбирать

- Нужно изменить **один компонент** (цвет легенды конкретной диаграммы, формат чисел в одной
  KPI-панели, рамку у одной таблицы) — берите слаги в `config_overrides`. Это адресная правка,
  которая не затрагивает остальной отчёт.
- Нужна **единая тема для всего отчёта** (все заголовки компонентов одного цвета, все таблицы
  с полосатыми строками, общий фон сетки, кастомный скроллбар) — берите report-level CSS через
  `style_operations`. Один CSS описывает оформление сразу для всех компонентов.

Оба уровня сочетаются: общую тему задают через CSS отчёта, а отдельные исключения — слагами
конкретного компонента. CSS с `!important` имеет приоритет над тем, что задано слагами.

> **Точность дизайна и охват CSS.** Стилизация идёт **от стандартного шаблона оформления
> портала** — CSS отчёта накладывается поверх него, а не задаёт оформление с нуля. Набор
> поддержанных селекторов и стилей задокументирован не полностью, поэтому покрытие report-level
> CSS не стоит считать стопроцентным (ориентир — около **80%**). Для **точной работы с дизайном**
> подключите **Playwright-MCP** и используйте визуальную верификацию: применили правило → сняли
> скриншот → сверили результат. Порядок такой проверки — в
> [руководстве тестировщика](../../start/tester.md); какие MCP-серверы нужны — в
> [../../../MCP_SERVERS.md](../../../MCP_SERVERS.md).

## Стиль компонента: config_overrides

Слаги — это короткие плоские имена настроек, которые сервер сам раскладывает в нужный адрес
внутри `config` компонента. Их передают словарём `config_overrides` в инструменты редактирования:

```python
component_crud(
    action="update",
    report_id=35,
    component_idx=0,
    config_overrides={
        "outline.enabled": True,
        "outline.width": 1,
        "bgColor": "rgba(255,255,255,1)",
    },
)
```

Помимо отдельных слагов есть пресеты — готовые наборы настроек оформления (например, более
светлый минималистичный вид или вид для KPI). Полный перечень доступных слагов для конкретного
типа компонента отдаёт сам сервер через листинг слагов инструмента `component_crud`. Принцип
слагов и пресетов подробно описан в
[../concepts/components-json-slugs.md](../concepts/components-json-slugs.md).

Важная особенность слагов: правка через `config_overrides` сохраняется в `config` компонента и
становится «истиной» для отрисовки. Но не всякая настройка имеет видимый эффект на каждом типе
компонента — результат всегда стоит проверять по тому, что реально отрисовано в браузере (см.
понятие «рендер-контракт» в [../../GLOSSARY.md](../../GLOSSARY.md)).

## Стиль отчёта: style_operations

Инструмент `style_operations` управляет CSS-кодом отчёта. CSS хранится в самом отчёте (в его
опциях) и при открытии отчёта применяется ко всем компонентам внутри: шапке, сетке, таблицам,
диаграммам, фильтрам, скроллбарам.

Доступные действия:

| Действие | Что делает | Обращается к порталу |
|---|---|---|
| `get` | Вернуть текущий CSS отчёта | да |
| `update` | **Заменить весь CSS отчёта** на переданный | да |
| `validate` | Проверить CSS на синтаксис и запрещённые свойства\* | нет (локально) |
| `classes_list` | Справочник доступных CSS-классов ModusBI | нет (локально) |
| `examples_list` | Готовые примеры оформления | нет (локально) |

\* перечень запрещённых свойств — см. таблицу «Чего НЕ трогать» ниже.

Действия `validate`, `classes_list`, `examples_list` не требуют обращения к порталу — это
встроенные справочники MCP-сервера и локальная проверка.

### КРИТИЧНО: update заменяет весь CSS

Действие `update` **полностью перезаписывает** CSS отчёта переданной строкой. Если отправить
только новые правила, всё ранее заданное оформление будет потеряно.

Правильный порядок — всегда **GET → merge → update**:

```python
# 1. Получить текущий CSS (чтобы не потерять то, что уже задано)
current = style_operations(action="get", report_id=35)
existing_css = current["current_css"]   # ключ ответа — current_css

# 2. Объединить существующий CSS с новым
new_css = existing_css + "\n\n/* Новые стили */\n.componentBody { padding: 20px !important; }"

# 3. Записать полный объединённый CSS
style_operations(action="update", report_id=35, css=new_css)
```

> Ответ действия `get` возвращает CSS в поле `current_css` (пустая строка, если стиль не задан).

Действие `update` требует, чтобы MCP-сервер был запущен в режиме `readwrite` — в режиме
`readonly` запись недоступна (см. [../../GLOSSARY.md](../../GLOSSARY.md), «Режимы readonly / readwrite»).

### Адресация одного компонента из CSS отчёта

Чтобы из общего CSS отчёта оформить **один** компонент, не трогая остальные, используется
селектор `#panel_N`, где `N` — порядковый индекс компонента в отчёте (тот же `component_idx`,
0-based):

```css
/* Особый стиль только для таблицы с индексом 3 */
#panel_3 .hs-table__table th {
    background: #1e40af !important;
    color: white !important;
}
```

Узнать индекс нужного компонента можно через `report_operations(action="components_list", report_id=...)`.

## Что удобно делать через CSS отчёта

Некоторые задачи решаются именно на уровне отчёта, потому что касаются общих элементов или
требуют CSS-селекторов, которых нет среди слагов.

### Карточный вид панелей

Скругление углов, тень и рамка у всех виджетов сетки — задаются один раз для всего отчёта:

```css
.react-grid-item {
    border-radius: 14px !important;
    box-shadow: 0 2px 12px rgba(30, 58, 95, 0.08) !important;
    overflow: hidden !important;
    border: 1px solid rgba(200, 215, 230, 0.5) !important;
}
.react-grid-item:hover {
    box-shadow: 0 8px 24px rgba(30, 58, 95, 0.15) !important;
    border-color: #38bdf8 !important;
}
```

### Иконки-бейджи на KPI-панелях

У KPI-панели (`HsTotalsPanelV2`) нет встроенного поля для иконки. Цветной бейдж-кружок в углу
карточки добавляется псевдоэлементом `::before` на саму грид-ячейку компонента `#panel_N`.

Портал подключает шрифт **Material Icons** — иконку задают её лигатурой через свойство `content`
(как в примере ниже). FontAwesome не подключён, а эмодзи в `content` рендерятся как пустые
прямоугольники.

```css
/* report-level CSS (style_operations action=update) */
#panel_0::before {
    position: absolute; top: 10px; right: 12px; z-index: 10; pointer-events: none;
    font-family: 'Material Icons'; content: 'paid';   /* лигатура иконки */
    font-size: 19px; line-height: 34px; text-align: center;
    width: 36px; height: 36px; border-radius: 50%;
    background: #eaf1fe; color: #2563eb; border: 1.5px solid #2563eb;
    -webkit-font-feature-settings: 'liga'; font-feature-settings: 'liga';
}
/* для следующей плитки — другой индекс и другая лигатура:
   #panel_1::before { content: 'trending_up'; ... } */
```

Полезные лигатуры Material Icons: `paid`, `trending_up`, `track_changes`, `show_chart`,
`person`, `check_circle`, `verified_user`, `schedule`, `savings`, `percent`.

### Фиксы перекрытия выпадающих списков фильтров

Выпадающий список фильтра иногда оказывается под соседними компонентами и обрезается. Это
лечится повышением порядка наложения (`z-index`) у ячейки с панелью фильтра:

```css
.react-grid-item:has(.hsFilterControlPanel) {
    z-index: 100 !important;
}
```

### Где взять селекторы

Справочник CSS-классов ModusBI и готовые примеры отдаёт сам сервер:

```python
style_operations(action="classes_list", category="all")   # все классы
style_operations(action="classes_list", category="tables") # классы конкретной категории
style_operations(action="examples_list", category="colors") # готовые примеры
```

Категории классов: `header`, `selectors`, `components`, `tables`, `charts`, `maps`, `pivot`,
`filters`, `grid`, `page_container`, `icons`, `text_block`, `mui`, `scrollbar`.

> Для категории примеров заголовков используется имя `headers` (с `s`), а не `header`.

## Правила написания CSS для ModusBI

### Используйте !important

Многие стили в портале заданы инлайново или через JavaScript. Чтобы CSS из настроек отчёта
гарантированно применился, добавляйте к свойствам `!important`:

```css
.componentHeader {
    background: #1976D2 !important;
    color: white !important;
}
```

### Для SVG-диаграмм используйте fill, а не color

Диаграммы рисуются в SVG. Для их элементов (подписи осей, секторы, столбцы) цвет задаётся
свойствами `fill` и `stroke`, а не `color`:

```css
#panel_8 .amcharts-axis-label > TSPAN {
    fill: #FF0000 !important;   /* color здесь не сработает */
}
```

### Не используйте transform в hover

Сетка компонентов (react-grid-layout) использует CSS-`transform` для позиционирования.
Добавление `transform` в правила наведения вызывает «скачки» компонентов. Для эффекта при
наведении используйте только `box-shadow` и `border-color`:

```css
/* Правильно */
.react-grid-item:hover {
    box-shadow: 0 8px 24px rgba(0,0,0,0.15) !important;
    border-color: #38bdf8 !important;
}
/* Нельзя — ломает раскладку:
   .react-grid-item:hover { transform: translateY(-2px); } */
```

## Чего НЕ трогать

| Свойство / правило | Почему опасно | Альтернатива |
|---|---|---|
| `position` у `.react-grid-item` / `.hsGridPanel` | Это та же грид-ячейка; перебивает её собственное `position: absolute` от сетки → весь отчёт рассыпается «лесенкой» | Не переопределять; для бейджей `::before` достаточно `position: absolute` на самом псевдоэлементе |
| `transform` в `:hover` | Вызывает скачки сетки | `box-shadow`, `border-color` |
| `position: fixed` | Нарушает раскладку отчёта | `position: relative` или `position: sticky` |
| `z-index` с очень большими значениями | Перекрывает элементы интерфейса портала | Минимально необходимый `z-index` (например, `100` для дропдаунов фильтров) |
| `display: none` | Полностью убирает элементы из потока | `visibility: hidden` или `opacity: 0` |

Действие `validate` предупреждает о части этих случаев (`position: fixed`, высокий `z-index`,
`display: none`, неизвестные классы) — но это базовая проверка, а не полный анализ. Итог всегда
стоит сверять с тем, что реально отрисовано в браузере.

## Особенности и ограничения

- **CSS применяется ко всему отчёту целиком.** Нельзя задать разный CSS для разных страниц
  (вкладок) одного отчёта.
- **`update` заменяет весь CSS** — всегда сначала `get`, затем объединение, затем `update`.
- **Нет изоляции стилей.** CSS из настроек отчёта влияет на все элементы страницы. Чтобы
  ограничить правило одним компонентом, используйте `#panel_N`.
- **Стили не наследуются от группы отчётов** — CSS задаётся для каждого отчёта отдельно.
- **Эмодзи в подписях компонентов** на портале отображаются как пустые прямоугольники — для
  значков используйте иконки Material Icons через CSS, как показано выше.
- **DOM может содержать селекторы, которых нет в справочнике** `classes_list`. Точный селектор
  нужного элемента можно найти инструментами разработчика браузера (F12).

## Порядок работы со стилем отчёта

```
1. ИЗУЧИТЬ   classes_list + examples_list  → доступные классы и готовые шаблоны
2. ПРОЧИТАТЬ get (report_id)               → текущий CSS (чтобы не потерять)
3. НАПИСАТЬ  новый CSS                      → из примеров или вручную
4. ОБЪЕДИНИТЬ существующий + новый          → update заменяет всё целиком
5. ПРОВЕРИТЬ validate (css)                 → синтаксис и запрещённые свойства
6. ПРИМЕНИТЬ update (report_id, css)        → записать полный CSS
```
