# Инструменты (tools) MCP-сервера

> ⚠️ **Перед практической работой** прочитайте [../../../DISCLAIMER.md](../../../DISCLAIMER.md): изменения на портале необратимы (нет отмены/истории), безопасность доступов при работе с LLM — на стороне пользователя.

Этот раздел описывает, что такое инструменты сервера, как они сгруппированы и
почему большинство из них устроено вокруг параметра `action`. Документ —
отправная точка: он даёт карту инструментов, а детали по каждому из них смотрите
через самосправку сервера (`action="help"`) и в смежных разделах документации.

> 📖 **Подробный справочник по каждому инструменту** (назначение, все действия с
> пояснениями, ключевые параметры, примеры, типичные ошибки) — в
> [reference.md](reference.md). Краткая карта действий/параметров — в
> [tool-reference.md](tool-reference.md).

Термины (инструмент, действие, отчёт, компонент, датасет, портал) определены в
[../../GLOSSARY.md](../../GLOSSARY.md).

## 1. Что такое инструмент

**Инструмент (tool)** — это публичная функция сервера, которую ИИ-ассистент
вызывает по протоколу MCP. С точки зрения протокола инструмент — это **RPC-метод**,
а не URL-эндпоинт: ассистент не делает HTTP-запрос на адрес ресурса, а отправляет
сообщение JSON-RPC с указанием имени инструмента и его аргументов. Подробный
разбор протокола — в [../concepts/protocol-and-rpc.md](../concepts/protocol-and-rpc.md).

Из этого следует несколько практических свойств:

- **Нет URL-путей и HTTP-глаголов.** У инструмента есть имя (например,
  `report_operations`), описание и набор параметров со схемой. Операцию задаёт не
  `GET`/`POST`/`PUT`, а аргументы вызова.
- **Список инструментов отдаёт сам сервер.** Клиент получает перечень инструментов
  и их схемы параметров через встроенный механизм MCP — ему не нужен отдельный
  каталог или спецификация.
- **Один инструмент покрывает группу операций над одной сущностью.** Вместо десятка
  мелких методов («создать отчёт», «удалить отчёт», «получить отчёт») сервер даёт
  один инструмент `report_operations` с переключателем операции.

Ниже по стеку, когда инструмент выполняется, сервер обращается к HTTP-API портала
ModusBI. Этот HTTP-API — **не чистый ресурсный REST**: операция кодируется в теле
запроса (поле `command`), а не в HTTP-глаголе или URL-пути. Эта деталь скрыта от
ассистента, но полезна при отладке — см. тот же документ про протокол.

## 2. Почему инструменты диспетчеризуют по `action`

**Большинство инструментов мультидейственные**: первый аргумент `action` выбирает
конкретную операцию, а инструмент маршрутизирует вызов к нужной внутренней
функции. Например, один инструмент `component_crud` обслуживает целый набор
действий над компонентами:

```text
component_crud(action="add",    report_id=35, component_type="HsBarAMchartsChart", ...)
component_crud(action="update", component_idx=0, config_overrides={...})
component_crud(action="delete", component_idx=0)
component_crud(action="get",    component_idx=0)
component_crud(action="data",   component_idx=0)
```

Зачем так сделано:

- **Меньше инструментов в каталоге.** Родственные операции собраны под одним именем,
  поэтому ассистент видит компактный список инструментов, а не сотни отдельных
  методов. Это снижает объём контекста, который клиент держит в памяти.
- **Единая точка входа на сущность.** Все операции над компонентом проходят через
  один инструмент с общим набором параметров; добавить новое действие — значит
  добавить ветку, а не новый метод.
- **Предсказуемые имена действий.** Действия именуются единообразно: `list`, `get`,
  `create`, `update`, `delete` для CRUD-операций; более специфичные действия —
  по смыслу (`clone`, `scaffold`, `filter_field_add`, `conditional_rule_add` и т.п.).

**Исключения — инструменты без `action`.** Несколько инструментов не имеют
параметра-переключателя, потому что делают ровно одну вещь, а их «параметры» — это
не выбор операции, а данные самой операции:

- `dataset_query` — запрос данных из датасета; первый параметр — `dataset_id`,
  далее `select` / `where` / `group` / `order` / `limit`.
- `sql_query_validate` — проверка SQL-запроса без выполнения.

Если вы вызвали мультидейственный инструмент с неизвестным действием, сервер
вернёт ответ вида `{error: "Unknown action: X"}` — это сигнал свериться со списком
действий через самосправку (см. раздел 4).

## 3. Группы инструментов по назначению

Инструментов на сервере — 19. Полный актуальный список с
параметрами всегда можно получить от самого сервера (через механизм перечисления
инструментов MCP); ниже — карта по назначению, чтобы понимать, куда смотреть.

### Отчёты и группы отчётов

- **`report_operations`** — отчёты (дашборды): `list` / `get` / `create` /
  `update` / `delete`, глубокое копирование (`clone`), сводка и состав отчёта,
  экспорт, глобальные фильтры, переменные, категории.
- **`reportgroup_operations`** — группы (папки) отчётов.
- **`report_template`** — готовые шаблоны отчётов: `list` (перечень шаблонов),
  `preview` (предпросмотр структуры), `scaffold` (создать отчёт по шаблону).

### Датасеты, данные и SQL

- **`dataset_operations`** — датасеты и семантический слой: `list` / `get` /
  `create` / `update` / `delete`, список полей, человекочитаемые имена полей
  (field_aliases).
- **`dataset_create_from_sql`** — создание датасета из SQL-запроса.
- **`dataset_query`** *(без `action`)* — основной способ получить данные из
  датасета: выборка `select` / `where` / `group` / `order` / `limit`.
- **`query_batch`** — несколько запросов к датасетам одним вызовом.
- **`sql_query_validate`** *(без `action`)* — проверка корректности SQL до создания
  датасета, без выполнения.

### Компоненты

Операции над компонентами разнесены по четырём инструментам — по смыслу, чтобы
каждый оставался обозримым. Все они работают с компонентом по его порядковому
индексу в отчёте (`component_idx`, отсчёт с нуля).

- **`component_crud`** — добавление / получение / обновление / удаление /
  копирование компонента, его раскладка (позиция и размеры), а также служебные
  справочные действия (список типов компонентов, список слагов настроек, список
  пресетов).
- **`component_filters`** — фильтры компонента: привязка и удаление полей
  фильтрации, каскадные связи между фильтрами, глобальные фильтры.
- **`component_axes`** — оси и поля: вычисляемые поля, страницы контейнера,
  drill-down (детализация по уровням), переходы между отчётами (pivot links),
  кнопки вкладок, привязка карты к гео-данным.
- **`component_styling`** — визуальное оформление: условное форматирование,
  сортировка, гео-привязка карты и визуальные параметры компонента.

> Визуальная настройка компонента трёхуровневая (атомарные параметры → слаги в
> `config_overrides` → пресеты). Подробности — в
> [../components/styling.md](../components/styling.md) и
> [../concepts/components-json-slugs.md](../concepts/components-json-slugs.md).

### Стиль отчёта

- **`style_operations`** — CSS-темизация отчёта на уровне всего отчёта.
  Действие `update` **заменяет** весь CSS отчёта, поэтому перед изменением
  сначала получают текущий CSS (`get`) и при необходимости дополняют его.

### Экспорт и пакетные операции

- **`data_export_operations`** — выгрузка данных в файлы (CSV / Excel).
- **`batch_operations`** — пакетные операции над несколькими объектами (например,
  массовое добавление компонентов или экспорт нескольких отчётов одним вызовом).

### Безопасность, инстанс, источники данных

- **`security_operations`** — Row-Level Security (RLS): ограничение видимости строк
  данных по пользователю.
- **`instance_operations`** — информация о подключённом портале (только чтение).
- **`datasource_operations`** — подключения к базам данных (источники данных).
- **`preflight_check_datasource`** — предварительная проверка доступности источника
  данных.

## 4. Самосправка: `action="help"`

Мультидейственные инструменты умеют рассказывать о себе. Вызов с
`action="help"` возвращает список доступных действий инструмента, а с указанием
конкретного действия — его описание и пример:

```text
component_crud(action="help")                       # список действий инструмента
component_crud(action="help", slug_category="add")    # справка по действию add
report_operations(action="help", name="clone")      # справка по действию clone
```

Это самый надёжный способ узнать актуальный набор действий и их параметры: справка
формируется из самого кода сервера и не расходится с реализацией. Имя параметра, в
котором передаётся интересующее действие, у разных инструментов отличается (для
части — `name`, для части — `value_field`); если сомневаетесь, сначала вызовите
`action="help"` без аргументов и посмотрите подсказку.

## 5. Где взять полное описание каждого инструмента

Авторитетный источник описаний инструментов со всеми параметрами — сам сервер.
Подробности по конкретному инструменту и его действиям всегда актуальны и не
расходятся с реализацией, потому что формируются из кода:

- **самосправка сервера** (`action="help"`, раздел 4) — список действий и их
  параметры для каждого мультидейственного инструмента;
- **механизм перечисления инструментов MCP** — клиент получает имена, описания и
  схемы параметров всех инструментов напрямую от сервера.
