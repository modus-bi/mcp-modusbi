# Готовность инструментов MCP

Этот документ показывает текущий статус готовности **инструментов (tools)**
MCP-сервера — нейтральным «светофором». Он отвечает на вопрос: что у сервера
работает в полном объёме, что работает с оговорками, а что не поддерживается и
почему. Документ предназначен для партнёров и интеграторов, которые планируют
строить сценарии поверх сервера и хотят заранее понимать границы.

Термины (инструмент, действие, отчёт, компонент, датасет, портал) определены в
[../../GLOSSARY.md](../../GLOSSARY.md). Карта инструментов по назначению — в
[../tools/README.md](../tools/README.md).

> **Актуально на 2026-06-22.** Все 19 инструментов перепроверены вживую (прогон всех действий на
> тестовом стенде): **17 ✅ работает, 2 🟡 частично** (средний % ≈ 96). Открытых дефектов на стороне сервера нет; обе 🟡 —
> ограничения движка портала. Незакрытые пункты — в [backlog по инструментам](../../backlog/tools.md).

## Как читать таблицу

Каждая строка — один **инструмент** MCP. Инструмент с точки зрения протокола —
это RPC-метод (вызов JSON-RPC по stdio), а не URL-эндпоинт; см.
[../concepts/protocol-and-rpc.md](../concepts/protocol-and-rpc.md). Под капотом
инструмент обращается к HTTP-API портала, где операция кодируется в теле запроса
(командой/действием), а не в HTTP-глаголе.

Статус — это обобщённая оценка инструмента в целом, по совокупности его действий:

| Значок | Что означает |
|---|---|
| ✅ работает | Инструмент и его действия выполняются в полном объёме |
| 🟡 частично | Основное работает, но есть оговорка или ограничение в одной из возможностей |
| 🔴 не поддерживается | Ключевая возможность недоступна (по дизайну либо из-за ограничения портала) |

Колонка «Причина / ограничение» — одна строка, объясняющая статус простыми
словами. Если инструмент имеет статус ✅, ограничений нет либо они несущественны
для типового использования.

> Точное число инструментов и точный набор действий у каждого из них не
> фиксируются в этом документе — они могут меняться между версиями. Авторитетный
> и всегда актуальный источник — **сам сервер**: вызов инструмента с
> `action="help"` отдаёт список его действий и параметров, а механизм
> перечисления инструментов MCP отдаёт схемы всех инструментов. См. раздел
> «Где взять точные детали» ниже.

## Поведенческие особенности (не ошибки)

Несколько правил, которые важно учитывать, чтобы не принять штатное поведение за
сбой:

- **Проверка SQL = выполнение.** `sql_query_validate` проверяет запрос, читая
  источник; разрешён только `SELECT`.
- **Обновление CSS заменяет всё.** Действие обновления у `style_operations`
  затирает весь CSS отчёта; для добавления используйте применение темы со
  слиянием, предварительно прочитав текущий CSS.
- **Имена полей — до привязки.** Человекочитаемые имена полей датасета задают до
  того, как поля используются в компонентах: портал блокирует переименование уже
  используемых полей.
- **Фильтр привязывают дважды.** Чтобы фильтр менял данные, его поле добавляют и
  в сам компонент-фильтр, и в каждый фильтруемый компонент.
- **Экспорт требует сервиса отрисовки.** Экспорт отчётов в PDF/PNG зависит от
  доступности сервиса рендеринга на стороне портала.
- **Поверхность запросов сужена намеренно.** В `dataset_query` нет `between`,
  `offset`, `distinct`: диапазон — через `>=`/`<=`, постраничность — через лимит.

## Где взять точные детали

Авторитетный источник по каждому инструменту — **сам сервер**, потому что справка
формируется из его кода и не расходится с реализацией:

- **Самосправка инструмента** — вызов с `action="help"` отдаёт список действий и
  их параметры. Имя параметра, в котором передаётся интересующее действие, у
  разных инструментов отличается; если сомневаетесь, вызовите `action="help"` без
  аргументов и посмотрите подсказку.
- **Перечисление инструментов MCP** — клиент получает имена, описания и схемы
  параметров всех инструментов напрямую от сервера.

```text
component_crud(action="help")                       # список действий инструмента
report_operations(action="help", name="clone")      # справка по конкретному действию
```
