# Дисклеймер: необратимость изменений и безопасность при работе с LLM

Прочитайте перед использованием. Запуская ModusBI MCP Server, вы принимаете изложенные ниже условия.

---

## 1. Нет версионирования изменений — операции необратимы

У сервера **нет** версионирования изменений в ходе работы: истории правок, снимков состояния,
отмены (undo) или отката (rollback). Любая операция применяется к порталу **сразу и окончательно**.

Это относится ко всем операциям записи:

- создание отчётов, датасетов, компонентов, фильтров, групп (create);
- изменение параметров, конфигурации, стилей, прав доступа (update);
- удаление отчётов, датасетов, компонентов и других объектов (delete);
- перемещение, переименование, переупорядочение (move, swap, reorder);
- импорт и пакетные операции (batch).

**Ответственность за корректность и обратимость изменений — на пользователе.** Сервер ничего не
откатывает и не подтверждает намерение. Снизить риск помогают:

- режим `--readonly` (по умолчанию) для просмотра и подготовки без записи;
- включение `--readwrite` только на время операций записи;
- ограничение потолка прав на процесс: `--security-ceiling readonly` жёстко блокирует запись даже
  при случайном `--readwrite`;
- резервные копии важных отчётов перед изменением — экспорт через `report_operations` (export),
  `data_export_operations` или `batch_operations` (reports_export);
- проверка результата сразу после операции.

Принимая эти условия, вы соглашаетесь, что изменения могут быть безвозвратными, и берёте этот риск
на себя.

---

## 2. Безопасность доступов при работе с LLM — на стороне пользователя

Сервер выполняет действия, которые инициирует ИИ-ассистент. Перечисленные ниже вопросы безопасности
**целиком в зоне ответственности пользователя** — сервер их не закрывает.

### Креденшалы портала

Сервер запускается с переменными окружения `MODUSBI_URL`, `MODUSBI_USERNAME`, `MODUSBI_PASSWORD`.
Все вызовы выполняются от имени этой учётной записи; в режиме `--readwrite` ассистент может выполнить
любое действие, доступное этой учётной записи.

- используйте выделенную учётную запись с минимально необходимыми правами, не администратора;
- если задача только на чтение — запускайте в `--readonly` (либо `--security-ceiling readonly`);
- не храните креденшалы в коде, истории shell, публичных файлах; используйте механизмы секретов
  вашей платформы развёртывания.

### Prompt-injection и автономные действия

Ассистент вызывает инструменты автономно. Если во входные данные внедрены скрытые инструкции
(prompt-injection), он может выполнить незапланированные операции — например, удалить или изменить
объект вместо чтения.

- формулируйте задачу как желаемый результат, а не как список команд;
- с осторожностью подавайте на вход данные из недоверенных источников;
- ограничивайте область действий (например, конкретная группа отчётов или префикс имени);
- для задач только на чтение оставайтесь в `--readonly`;
- проверяйте результат после каждой операции записи.

### Доступ к данным

Через `dataset_query` ассистент выполняет запросы и видит их результаты. Чувствительные данные
(персональные, финансовые и т.п.) попадают в контекст ассистента.

- применяйте row-level security портала для ограничения видимости по ролям;
- не направляйте ассистента на неограниченную выборку;
- сверяйте, какие датасеты и поля доступны учётной записи подключения.

---

## 3. Один пользователь портала = одна сессия

Учётная запись портала ModusBI допускает **только один активный сеанс одновременно**. MCP-сервер,
работая под заданной учёткой (`MODUSBI_USERNAME`), держит её сессию. Если под **той же** учётной
записью одновременно зайти на портал — в браузере или другим клиентом — один из сеансов будет
завершён («выкинет»): либо у вас в браузере, либо у работающего сервера.

**Рекомендация: заведите отдельную учётную запись портала специально под MCP-сервер.** Тогда ваша
обычная работа в портале и работа ассистента не будут прерывать друг друга. Эта же выделенная учётная
запись удобна для ограничения прав (см. раздел 2 — минимально необходимые права, не администратор).

---

**Итог.** Сервер прямолинейно отражает действия ассистента на портал: не проверяет намерение,
не ведёт историю и не откатывает операции. Безопасность опирается на выбор режима
(`--readonly` / `--readwrite` / `--demo`), защиту креденшалов, формулировку задачи с учётом
prompt-injection и проверку результатов.
