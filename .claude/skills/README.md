# Скиллы ModusBI MCP — каталог и сценарии использования

Скиллы — это готовые сценарии для работы с ModusBI через MCP. Вы **формулируете запрос обычными словами**
(«создай дашборд по продажам»), ассистент сам подбирает нужный скилл и выполняет его через инструменты ModusBI.
Скиллы разделены на группы по назначению — пользовательские (создание/анализ) и технические (для разработчиков).

> 💡 У каждого скилла рядом лежит **`EXAMPLES.md`** — простые сценарии и примеры использования
> («что написать» → «что получите»). **Кликните по названию скилла** в таблице, чтобы открыть его примеры.

## Легенда

| Обозначение | Значение |
|---|---|
| **Скилл** | Сценарий, который запускается по вашему запросу обычными словами |
| **Агент** | Запускается автоматически (оркестрация), отдельно вызывать не нужно |
| **Что делает** | Назначение — для чего скилл |
| **Пример запроса** | Как вызвать — достаточно написать похожую фразу |
| **Результат** | Что вы получите на выходе |
| **Нужно** | Доп. MCP-серверы (только для технических скиллов): **PW** playwright · **PG** postgres |

> Базово нужен только MCP-сервер **`modusbi`** (см. [../../MCP_SERVERS.md](../../MCP_SERVERS.md), [.env.example](../../.env.example)).
> PW нужен лишь скиллам тестирования UI (стандарт проекта — playwright); PG — опц. для аналитики напрямую из БД.
> Полная инструкция каждого скилла (шаги, примеры вызовов) — в его `SKILL.md` (папка скилла рядом).

## 📊 Создание отчётов и дашбордов

*Путь использования:* опишите задачу и источник данных — ассистент исследует данные, создаёт датасет
(с русскими подписями), собирает компоненты, привязывает фильтры, применяет стиль и возвращает готовый отчёт (ID + ссылку).

| Скилл | Что делает | Пример запроса | Результат |
|---|---|---|---|
| **[create-dashboard](create-dashboard/EXAMPLES.md)** | Полноценный дашборд под задачу: исследует данные, создаёт датасеты, собирает компоненты, фильтры, стиль | «создай дашборд по продажам за год» | Готовый многокомпонентный отчёт |
| **[create-kpi-dashboard](create-kpi-dashboard/EXAMPLES.md)** | Дашборд мониторинга: крупные KPI, тренд, карта, сводная таблица | «KPI-дашборд по выручке с динамикой» | Отчёт с KPI + трендом + детализацией |
| **[create-ranking](create-ranking/EXAMPLES.md)** | Рейтинг: топ-N, treemap, таблица с детализацией (drill-down) | «топ-10 регионов по продажам» | Рейтинговый дашборд |
| **[create-comparison](create-comparison/EXAMPLES.md)** | Сравнение двух периодов: KPI-дельты (▲▼), stacked bar, структура | «сравни этот квартал с прошлым» | Дашборд план-факт / YoY / MoM |
| **[create-factor-analysis](create-factor-analysis/EXAMPLES.md)** | Факторный анализ: waterfall (вклад факторов), 3 KPI, таблица с подсветкой | «разложи изменение выручки по факторам» | Дашборд факторного анализа |
| **[create-geo-analytics](create-geo-analytics/EXAMPLES.md)** | Геоаналитика: карта (точки/хороплет), KPI, таблица по территориям | «карта продаж по регионам» | Геодашборд с картой |
| **[create-simple-report](create-simple-report/EXAMPLES.md)** | Минимальный отчёт: фильтр + график + таблица (3 компонента) — самый быстрый | «быстрый отчёт по продажам» | Простой отчёт из 3 компонентов |
| **[add-navigation-panel](add-navigation-panel/EXAMPLES.md)** | Навигационная панель-меню между несколькими отчётами | «свяжи мои отчёты навигацией» | Панель-меню в отчётах |

## 🔍 Анализ данных и выводы

*Путь использования:* укажите датасет или вопрос — ассистент запрашивает данные, проверяет гипотезы/качество,
формулирует бизнес-выводы с цифрами и при необходимости добавляет визуализацию к отчёту.

| Скилл | Что делает | Пример запроса | Результат |
|---|---|---|---|
| **[analyze-data](analyze-data/EXAMPLES.md)** | Глубокий анализ: проверяет гипотезы, ищет корреляции, формулирует бизнес-выводы с рекомендациями и оценкой эффекта | «проанализируй, почему упали продажи» | Выводы + цифры + визуализация |
| **[explain-chart](explain-chart/EXAMPLES.md)** | Объясняет готовый график и добавляет к дашборду текстовый вывод «что это значит / что делать» | «объясни этот график, какие выводы» | Текст-блок с выводом на дашборде |
| **[dq-profiler](dq-profiler/EXAMPLES.md)** | Профилирование качества данных: полнота, уникальность, аномалии → правила проверки → DQ-дашборд | «проверь качество данных в таблице» | Профиль качества + правила + дашборд |

## 🗄 SQL и подготовка данных

*Путь использования:* опишите, какой запрос нужен — получите готовый SQL (типы, сортировка, технические
поля + русские подписи), который можно сразу подать в создание датасета.

| Скилл | Что делает | Пример запроса | Результат |
|---|---|---|---|
| **[generate-sql](generate-sql/EXAMPLES.md)** | Генерирует SQL под BI: сортировка, типы, округление, технические alias + русские подписи через `field_aliases` | «SQL для топ-N категорий по сумме» | Готовый SQL для датасета |
| **[sql-bi-expert](sql-bi-expert/EXAMPLES.md)** | Расширенный SQL-справочник для BI (паттерны: динамика, когорты, сравнения) с правильными типами и сортировкой | «напиши SQL для дашборда продаж» | SQL + объяснение паттерна |

визуализации, формулировки выводов и статистических проверок. База знаний под капотом.

## 🛠 Тестирование и разработка (для разработчиков)

Технические скиллы и агенты для проверки портала/компонентов и разработки. Описание более техническое.

*Путь использования:* запускаются разработчиком для проверки собранного отчёта, компонента или сквозного
сценария. Часть требует браузерного MCP-сервера (PW playwright) — см. колонку «Нужно».

| Скилл / Агент | Тип | Что делает | Когда применять | Нужно |
|---|---|---|---|---|
| **[verify-report](verify-report/EXAMPLES.md)** | скилл | Детальная проверка отчёта: фильтры привязаны, данные грузятся, layout без перекрытий, alias, стили; ловит дефекты | проверить собранный отчёт перед сдачей | — |
| **[modusbi-e2e](modusbi-e2e/EXAMPLES.md)** | скилл | E2E-проверка портала через браузер: логин, открытие отчётов, рендер компонентов | сквозной прогон сценария в UI | PW |
| **[component-deep-settings](component-deep-settings/EXAMPLES.md)** | скилл | Разбор всех настроек компонента: UI-контрол → JSON-путь → MCP-slug, классификация связи | аудит соответствия настроек компонента | PW |
| **[component-visual-verify](component-visual-verify/EXAMPLES.md)** | скилл | Визуальная проверка, что применённый slug реально отрисовался (скриншот + DOM до/после) | подтвердить, что `config_overrides` рендерится | PW |
| **[portal-component-probe](portal-component-probe/EXAMPLES.md)** | скилл | Проверка компонента через UI портала: палитра → drag-add → панель настроек → сверка с докой | проверить добавляемость/настройку типа | PW |
| **[mcp-prompt-writer](mcp-prompt-writer/EXAMPLES.md)** | скилл | Написание и аудит MCP-промптов (`app/prompts.py`): корректность action-имён и параметров vs API | добавить/проверить промпт сервера | — |
| **dashboard-builder** | агент | Строит отчёт/дашборд по полученным данным (оркестрирует `create-*`) | авто: когда нужен дашборд из данных | PG |
| **portal-ui-prober** | агент | Ориентируется в UI портала, проверяет готовность компонентов (drag-add, config, сверка) | авто: проверка набора типов через UI | PW |
| **component-visual-verifier** | агент | Визуально верифицирует, что slug рендерится на компоненте | авто: визуальная верификация slug | PW |

## Настройка (как начать)

1. Подключите MCP-сервер **`modusbi`** — пример конфига в [.mcp.example.json](../../.mcp.example.json), карта серверов в [../../MCP_SERVERS.md](../../MCP_SERVERS.md).
2. Заполните `.env` по образцу [.env.example](../../.env.example) (адрес портала + учётные данные).
3. Для скиллов тестирования UI — добавьте `playwright` (см. MCP_SERVERS.md); для аналитики из БД — `postgres`.
4. Дальше просто пишите запрос обычными словами — ассистент подберёт скилл.
