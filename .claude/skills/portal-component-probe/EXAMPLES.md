# Проверка компонента через UI портала — сценарии и примеры

> **Коротко:** называете компонент — ассистент открывает портал в браузере, ищет его в палитре
> добавления, перетаскивает на сетку (drag-add), открывает панель настроек и сверяет её с
> документацией. На выходе — строка готовности: палитра / drag-add / config-панель / сверка / вердикт.

---

## Когда пригодится

- Нужно понять, **доступен ли компонент в UI** и добавляется ли он перетаскиванием, а не только через API.
- Хотите свериться, что **контролы панели настроек совпадают с документацией** (`docs/architecture/components/reference/<name>.md` + `SLUG_REFERENCE.md`): что лишнее, чего не хватает.
- Готовите **сводку готовности типов** (✅ stable / 🟡 partial / 🔴 blocker / ⚪ skip) перед релизом или ревью.

Если нужен глубокий разбор всех контролов с маппингом UI→JSON→slug — это `component-deep-settings`.
Если нужно проверить, что slug реально рендерится на компоненте, — `component-visual-verify`.

---

## Пример 1. Один компонент: «доступен ли и как добавляется»

**Вы пишете:**
> «Проверь столбчатую диаграмму через UI портала: есть ли в палитре, добавляется ли перетаскиванием, открывается ли настройка.»

**Что сделает ассистент:**
1. Прочитает креды из `.env`, залогинится (`${MODUSBI_E2E_LOGIN}`) и откроет пустой тестовый отчёт в режиме конструктора.
2. Откроет палитру «Выбор типа отображения», сделает снапшот — это сразу даёт presence для всех типов; найдёт пункт по русскому названию («Диаграмма столбчатая»).
3. Перетащит пункт типа на зону превью (`browser_drag`, startTarget/endTarget) — в превью отрендерится SVG/canvas.
4. Откроет панель настроек (force-click шестерёнки через JS, т.к. оверлей перехватывает обычный клик) и зафиксирует скриншот.

**Что получите:** строку готовности вида `| HsBar… | Столбчатая | да | да | да | … | … | ✅ | заметки |` и скриншоты ключевых шагов.

## Пример 2. Сверка контролов панели с документацией

**Вы пишете:**
> «Открой настройки круговой диаграммы и сверь, какие контролы есть в UI, а какие описаны в доке.»

**Что сделает ассистент:**
1. Добавит компонент, откроет панель и проскоупит поиск по вложенному drawer `.hsChartSettings` (НЕ по широкому `.hsComponentEditor` — иначе тянется шум из полей и кнопок).
2. Пройдёт секции (`.hsSettingsSection`), раскрывая заголовки кликом, и перечислит контролы; mode-dropdown'ы (например «Вид диаграммы» → «Бублик») переснимет — часть контролов появляется только после выбора.
3. Прочитает `docs/architecture/components/reference/<name>.md` и `SLUG_REFERENCE.md`, сопоставит: что в UI есть, чего нет, что лишнее.

**Что получите:** вердикт «UI ↔ docs»: совпадает / частично + список конкретных расхождений.

## Пример 3. Точечная проверка: какой JSON-ключ за контролом

**Вы пишете:**
> «Поменяй в настройках толщину линии и подтверди, на какой ключ config это влияет.»

**Что сделает ассистент:**
1. Снимет baseline сырого config через browser-fetch (`/v1/api/reports/<ID>`, ответ — голый массив `[report]`) — это единственный надёжный источник: MCP `get` отдаёт только summary без сырого `config`.
2. Изменит контрол в UI (числовое/слайдер — через native value-setter + `input`/`change`; чекбокс — только `.click()`), нажмёт «Сохранить» в редакторе, затем «Сохранить отчёт».
3. Снова снимет config и сделает diff A0↔A1 — изменившийся путь и есть JSON-ключ контрола; сверит со slug в `config_schema.py`.

**Что получите:** пару «контрол → путь в `config` → slug» с подтверждением диффом.

## Полезно знать

- **Нужен браузерный MCP.** Скилл работает на `playwright` (`mcp__playwright__browser_*`) — он лучше эмулирует drag-and-drop. Сервер должен быть подключён в `.mcp.json` (после рестарта клиента). Снапшот возвращает `ref=…`; это значение идёт в параметр `target=` (НЕ `ref=`).
- **Снапшот перед каждым действием.** `ref` валиден только в рамках последнего `browser_snapshot`. На canvas/SVG — обычный скриншот, без fullPage.
- **Выбор типа = drag, а не клик.** Клик/двойной клик по пункту палитры тип НЕ выбирает; тащить пункт на зону превью. Если нативный drag не сработал — fallback через эмуляцию HTML5-событий (`DragEvent` + `DataTransfer`).
- **Тестовые отчёты удалять.** По завершении прогона — снести добавленные компоненты и удалить тестовый отчёт (`report_operations(delete)`) **после** выхода из браузера, чтобы не оставлять мусор на sandbox.
- **Не чередуйте сессии.** Браузер логинится как E2E-учётка, MCP-сервер — как API-юзер; переключение API↔браузер сбрасывает состояние. Креды и URL — только из `.env`, в тексте плейсхолдеры (`${MODUSBI_URL}` и т.п.).
- **Скриншоты — с явным префиксом** `filename=".playwright-mcp/<class>_<N>.png"`, иначе спиллят в корень репозитория. Артефакты не коммитить.
