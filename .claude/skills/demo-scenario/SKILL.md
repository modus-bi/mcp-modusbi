# Demo Scenario: Генератор демо-сценариев

## Overview

Этот skill создаёт пошаговые сценарии для живых демонстраций:
- Определяет что показываем и в каком порядке
- Рассчитывает тайминги для каждого шага
- Пишет речевой план (что говорить)
- Создаёт fallback-план (если демо сломается)
- Использует playwright для навигации, скриншотов и fallback-подготовки

**Результат:** Готовый пошаговый сценарий, по которому можно провести демо.

---

## When to Use This Skill

Используй этот skill когда пользователь:

- Просит **"подготовить демо"** или **"сценарий демонстрации"**
- Хочет **"план живого показа"** для презентации
- Нужен **"script для демо"** с таймингами
- Готовится к **конференции с live demo**
- Хочет **"fallback план"** на случай сбоя

**Не использовать если:**
- Нужен только план слайдов (используй `/present-outline`)
- Нужно создать дашборд (используй `/create-dashboard`)

## Standard Workflow

### Шаг 1: Определить структуру демо

**Правило "3 Act Demo":**

```
ACT 1: SETUP (10% времени)
  Показать стартовую точку: "Вот наши данные / проблема"

ACT 2: ACTION (70% времени)
  Показать как решаем: "Смотрите, ИИ делает X, Y, Z"

ACT 3: RESULT (20% времени)
  Показать результат: "Вот что получилось за 3 минуты!"
```

### Шаг 2: Написать пошаговый сценарий

**Формат:**

```markdown
## Демо-сценарий: [Название]

### Метаданные
- Общее время: [X мин]
- Среда: [IDE / браузер / терминал]
- Инструменты: [список MCP-серверов, команд]
- Fallback: [есть / нет]

### STEP 1: [Название шага] (0:00 - 0:30)

**Что делаем:** [Описание действия]
**Команда/действие:**
```
/analyze-data "проверь качество таблицы contractors"
```
**Что видит аудитория:** [Описание экрана]
**Что говорим:** "Сейчас я покажу как ИИ анализирует качество данных..."
**Ожидаемый результат:** [Что должно произойти]
**Если не работает:** [Fallback действие]

### STEP 2: ...
```

### Шаг 3: Рассчитать тайминги

**Правила тайминга:**

| Действие | Типичное время |
|----------|---------------|
| Открыть IDE / переключить окно | 5-10 сек |
| Набрать команду (или вставить) | 10-15 сек |
| Ожидание ответа ИИ | 15-60 сек |
| Комментарий к результату | 20-30 сек |
| Переход между шагами | 5-10 сек |
| Создание дашборда | 30-90 сек |
| Загрузка страницы | 5-15 сек |

**Формула:** Реальное время = Планируемое x 1.5 (закон Хофштадтера)

### Шаг 4: Создать fallback-план

**Уровни fallback:**

| Уровень | Когда | Что делать |
|---------|-------|------------|
| **Level 0** | Всё работает | Продолжать по сценарию |
| **Level 1** | Медленный ответ | "Пока ИИ думает, давайте посмотрим на архитектуру..." (переключить слайд) |
| **Level 2** | Ошибка в одном шаге | Пропустить шаг, показать скриншот результата |
| **Level 3** | Полный сбой | Переключиться на видео-запись демо |

---

### Шаг 5: Визуальная верификация через playwright

Используй playwright для живой навигации и скриншотов во время демо:

```python
# Навигация к дашборду (показать результат в браузере)
browser_navigate(f"${MODUSBI_URL}/report/{report_id}")

# Ожидание загрузки
browser_evaluate("await new Promise(r => setTimeout(r, 3000))")

# Скриншот результата демо
browser_take_screenshot(name=f"demo_result_{step_name}")
```

**Применение в fallback:**

| Уровень | Действие с playwright |
|---------|---------------------------|
| **Level 0** | Открыть дашборд в браузере, показать live |
| **Level 1** | Сделать скриншот и показать пока ждём |
| **Level 2** | Показать заранее сохранённый скриншот |
| **Level 3** | Показать видеозапись |

**Подготовка скриншотов заранее:**
```python
# Прогнать демо и сохранить скриншоты для fallback
for step in demo_steps:
    browser_navigate(step.url)
    browser_evaluate("await new Promise(r => setTimeout(r, 3000))")
    browser_take_screenshot(name=f"fallback_{step.name}")
```

## Demo Patterns

### Pattern 1: DQ Profiling Demo (5 мин)

```markdown
## Демо: Профилирование качества данных

Время: 5 минут
Среда: Claude Code (терминал + IDE)

### STEP 1: Постановка задачи (0:00 - 0:30)
**Говорим:** "У нас есть справочник контрагентов — 10 тысяч записей из 3 источников.
Давайте посмотрим, что там с качеством."
**Действие:** Показать таблицу в IDE (первые 10 строк)

### STEP 2: Профилирование (0:30 - 2:00)
**Говорим:** "Попрошу ИИ проанализировать данные..."
**Команда:**
```
Проанализируй качество таблицы public.contractors:
полноту, уникальность, формат ИНН и телефонов, найди дубли
```
**Ожидание:** 30-60 сек (ИИ делает 5-7 SQL запросов)
**Результат:** Таблица с метриками DQ

### STEP 3: DQM-правила (2:00 - 3:00)
**Говорим:** "Теперь ИИ предложит правила валидации..."
**Команда:**
```
Предложи DQM-правила для этого справочника
```
**Результат:** Список из 8-10 правил с SQL

### STEP 4: Дашборд (3:00 - 4:30)
**Говорим:** "А теперь создадим дашборд для мониторинга..."
**Команда:**
```
Создай дашборд качества данных для contractors
```
**Ожидание:** 30-60 сек
**Результат:** Готовый дашборд в ModusBI

### STEP 5: Итог (4:30 - 5:00)
**Говорим:** "Итого за 5 минут: полное профилирование, правила валидации и дашборд мониторинга.
Аналитику на это потребовалось бы 2-3 дня."
**Показываем:** Дашборд в браузере
```

```markdown
**Результат:** Сравнительная таблица + вывод
```

```markdown
### STEP 1: Запрос (0:00 - 0:15)
```

## Fallback Resources

### Что подготовить заранее

1. **Скриншоты каждого шага** — на случай полного сбоя
2. **Видеозапись успешного прогона** — 1-2 минуты ускоренной записи
3. **Запасной датасет** — если основная БД недоступна
4. **Offline копия дашборда** — HTML-экспорт

### Fallback Script

```markdown
## Если демо не работает

"К сожалению, {описание проблемы}. Но давайте я покажу на записи,
как это выглядит в рабочем режиме."

[Включить видео или показать скриншоты]

"Как видите, ИИ за 3 минуты делает то, на что аналитику нужно 2-3 дня.
После семинара я могу показать живое демо в неформальной обстановке."
```

## Best Practices

1. **Прогони демо 3 раза** перед выступлением (в реальных условиях!)
2. **Используй заготовленные данные** — не случайные, а заранее проверенные
3. **Тайминг x1.5** — всегда закладывай запас времени
4. **Говори во время ожидания** — пока ИИ думает, объясняй что происходит
5. **Не извиняйся за скорость** — 30 секунд это быстро, не говори "подождите"
6. **Покажи "wow" рано** — первый впечатляющий результат в первые 60 секунд
7. **Имей Plan B** — скриншоты и видео всегда наготове
8. **Интернет** — проверь WiFi заранее, имей мобильный hotspot
