# Screencast Script: Продающие сценарии для скринкастов

## Overview

Этот skill превращает фичу MCP-сервера в готовый сценарий скринкаста:
- **Hook** — первые 15 секунд, ради которых зритель остаётся
- **Структура с таймкодами** — что показываем и сколько секунд это занимает
- **Закадровый текст** — дословный voiceover, готовый к записи
- **Монтажные заметки** — что в реальном времени, что таймлапсом, где зум
- **YouTube-пакет** — 3 варианта названия, описание, теги, идея превью

**Отличие от `/demo-scenario`:** demo-scenario — для живых выступлений (fallback-план, импровизация). screencast-script — для записи: монтаж скрывает ожидания, поэтому акцент на hook, ритм и продающий текст, а не на план Б.

- Слайдовая презентация → `/present-outline`, `/create-presentation`

## Формула продающего скринкаста (Result-First)

Скринкасты про BI+AI (PowerBI MCP, Copilot и т.п.) набирают просмотры на одной механике: **показать результат ДО процесса**. Зритель должен за 15 секунд понять, что он получит, если досмотрит.

```
0:00–0:15  HOOK        Готовый результат + обещание ("этот дашборд ИИ собрал за 4 минуты")
0:15–0:45  PROBLEM     Боль зрителя ("вы делаете это 2 дня: мышка, поля, фильтры…")
0:45–1:00  SETUP       Что понадобится (Claude Code + MCP, одна строка конфига)
1:00–N     DEMO        Сам процесс: команда → ИИ работает → результат по шагам
посл. 45с  PAYOFF      Результат крупно + сравнение "было/стало" (время, клики)
посл. 15с  CTA         Что сделать зрителю (ссылка, подписка, следующее видео)
```

### Правила, которые нельзя нарушать

| # | Правило | Почему |
|---|---------|--------|
| 1 | **Результат в первые 15 сек** | Удержание решается на hook; процесс без результата = выключили |
| 2 | **Одно видео = один сценарий** | "Всё про MCP за час" не смотрят; "дашборд за 4 минуты" — смотрят |
| 3 | **3–7 минут хронометраж** | Меньше — несерьёзно, больше — падает удержание |
| 4 | **Ожидание ИИ — только таймлапсом** | 40 секунд спиннера убивают ролик; ускорить ×8–16 с таймером на экране |
| 5 | **Цифры, не эпитеты** | Не "очень быстро", а "11 секунд"; не "много кликов", а "0 кликов мышкой" |
| 6 | **Сравнение было/стало** | "Аналитик: 2 дня → ИИ: 4 минуты" — главный продающий кадр |
| 7 | **Русский текст команд** | Зритель должен верить, что сможет повторить — промпты по-русски, как говорит |
| 8 | **Финальный кадр = результат** | Последнее, что видит зритель — живой дашборд, не терминал |

## Структура сценария (выходной формат)

Каждый сценарий — один MD-файл по шаблону:

```markdown
# [Название видео]

## Метаданные
- Хронометраж: X мин (реальная запись ~Y мин, ужимается монтажом)
- Среда: Claude Code (терминал) + браузер ${MODUSBI_URL}, split-screen
- MCP: modusbi [, postgres]
- Сложность подготовки: low / medium / high
- Что подготовить заранее: [список]

## Hook (0:00–0:15) — дословно
[Текст + что на экране]

## Сцены
### СЦЕНА N: [название] (таймкод)
**Экран:** что видит зритель
**Команда:** дословный промпт, который вводим
**Голос:** дословный закадровый текст
**Монтаж:** реалтайм / таймлапс ×N / зум на элемент / on-screen заметка

## Полный закадровый текст
[Сплошной текст для записи голоса]

## YouTube-пакет
- Названия (3 варианта)
- Описание (с таймкодами)
- Теги
- Идея превью (thumbnail)

## Подготовка перед записью
[Чеклист: данные, отчёты, чистый терминал, разрешение]
```

## Реальные тайминги ModusBI MCP (замерено)

Используй эти числа при планировании сцен — не выдумывай:

| Операция | Реальное время | В ролике |
|----------|---------------|----------|
| `report_template scaffold` (отчёт + 3 компонента) | ~11 сек | реалтайм — это wow |
| Ответ ИИ на простой промпт | 15–30 сек | таймлапс ×4 |
| Полный дашборд через скилл (/create-kpi-dashboard) | 4–8 мин | таймлапс ×8–16 + 2-3 реалтайм-вставки |
| Исследование схемы БД через postgres-mcp | 30–60 сек | таймлапс ×4 с зумом на найденные таблицы |
| Анализ скриншота (vision) | 10–20 сек | реалтайм с зумом на разметку |
| Добавление 1 компонента (component_crud add) | 5–10 сек | реалтайм |
| Загрузка отчёта в браузере | 5–15 сек | обрезать до 2 сек |
| Экспорт PDF | 10–30 сек | обрезать |

**Закон Хофштадтера для записи:** реальная запись = хронометраж × 3. На 5-минутный ролик закладывай 15–20 минут записи + прогон.

## Hook-паттерны (проверенные форматы)

### Pattern 1: «Результат-вперёд»
```
[ЭКРАН: готовый дашборд, камера медленно панорамирует]
"Этот дашборд — 4 KPI, карта, графики, фильтры — я не нарисовал.
Я написал одно предложение. Сейчас покажу какое."
```

### Pattern 2: «Было/стало»
```
[ЭКРАН: split — слева пустой отчёт, справа готовый]
"Слева — то, с чего начинает аналитик. Справа — то, что было через
4 минуты. Между ними — ноль кликов мышкой."
```

### Pattern 3: «Вызов/спор»
```
[ЭКРАН: скриншот чужого дашборда]
"Мне прислали скриншот дашборда и спросили: сможешь повторить?
Я не открывал редактор. Я отдал скриншот ИИ."
```

### Pattern 4: «Запретный приём»
```
[ЭКРАН: терминал крупно]
"BI-разработчики не любят это видео. Потому что здесь дашборд
собирается командой в чат — без редактора, без мышки, без ТЗ."
```

## Монтажные обозначения (для сцен)

| Метка | Значение |
|-------|----------|
| `RT` | Реалтайм, без ускорения |
| `TL×8` | Таймлапс с ускорением ×8, в углу — таймер реального времени |
| `ZOOM` | Наезд на элемент экрана (команда, цифра, компонент) |
| `SPLIT` | Разделённый экран: терминал слева, браузер справа |
| `OST` | On-screen text — надпись поверх видео ("11 секунд", "0 кликов") |
| `CUT` | Жёсткая склейка, убрать паузу |
| `B-ROLL` | Перебивка: курсор по дашборду, скролл данных |

## Особенности ModusBI vs PowerBI MCP (для позиционирования)

При написании текстов учитывай отличия — это аргументы в voiceover:

1. **Родной MCP, а не обёртка**: 19 tools покрывают весь цикл — отчёты, датасеты, компоненты, фильтры, стили, RLS, экспорт. Не "генератор DAX", а полный CRUD портала.
2. **Связка postgres-mcp + modusbi-mcp**: ИИ сам исследует БД (схемы, поля, диапазоны) и сам строит датасеты. У PowerBI MCP модель надо готовить заранее.
3. **Скиллы = кнопки-рецепты**: /create-kpi-dashboard, /create-geo-analytics — упакованный опыт лучших production-дашбордов. Зритель получает не "чистый лист", а проверенный шаблон.
4. **Русский язык end-to-end**: промпты, алиасы полей, подписи — всё по-русски без танцев.
5. **Self-hosted / on-premise**: данные не уходят в облако Microsoft — продающий аргумент для энтерпрайза РФ.

**Чего НЕ обещать:** мгновенность (полный дашборд — минуты, не секунды), работу без подготовки данных (грязная БД = плохой дашборд), полную замену аналитика (ИИ собирает, человек принимает решения).

## Workflow

### Шаг 1: Определить сценарий и wow-момент
Один ролик = один сценарий. Найди главный wow (обычно — скорость или "понял по скриншоту") и строй hook вокруг него.

### Шаг 2: Прогнать сценарий вживую
Перед написанием таймкодов — реально выполни команды через MCP (в тестовой папке/отчёте), запиши реальные тайминги. Удали тестовые артефакты (`report_operations delete`).

### Шаг 3: Написать сцены
По шаблону выше: Экран / Команда / Голос / Монтаж. Голос пиши разговорным языком — так, как говоришь, а не как пишешь документацию.

### Шаг 4: Собрать YouTube-пакет
- **Название**: число + результат + время ("Дашборд из скриншота за 5 минут — ИИ + ModusBI")
- **Превью**: результат крупно + большая цифра + лицо/эмоция (если есть)
- **Описание**: первые 2 строки — обещание + ссылка; дальше таймкоды
- **Теги**: modusbi, mcp, claude, bi, дашборд, ai analytics, искусственный интеллект

### Шаг 5: Чеклист перед записью
- [ ] Данные подготовлены и проверены (не случайные!)
- [ ] Тестовый прогон сделан, тайминги записаны
- [ ] Терминал: крупный шрифт (16–18pt), чистая история, тёмная тема
- [ ] Браузер: 1920×1080, закладки скрыты, лишние вкладки закрыты
- [ ] Кредлы не светятся в кадре (`.mcp.json`, пароли, токены)
- [ ] Имена тестовых отчётов — приличные (попадут в кадр)
- [ ] Записаны 2 дубля hook'а и payoff'а

## Живой голос: как не звучать как нейросеть

Закадровый текст читает живой человек — он должен звучать как речь, а не как лендинг.
Проверяй текст по этому списку и вычищай:

| ИИ-штамп | Чем заменить |
|----------|--------------|
| «А теперь магия», «магия, ради которой вы здесь» | «Дальше самое интересное», или просто показать без анонса |
| «Момент истины» | «Ну что, сравниваем» |
| Афоризмы-лозунги («Это не отчёт, это инструмент») | Конкретика: что человек реально сможет делать |
| «Заметьте / Смотрите / Обратите внимание» в каждой сцене | Максимум один раз за ролик; остальное — просто говорить факт |
| «И — внимание — …», «И главное — …» | Убрать связку, оставить факт |
| Идеально параллельные конструкции через весь текст | Ломать ритм: короткая фраза. Потом длиннее. Иногда неполная. |
| Тире-каскады в каждом предложении | Часть переписать простыми предложениями с точками |
| «упакованный опыт», «бесшовно», «инновационный» | «по сути чек-лист», «просто работает», убрать |
| Одинаковый CTA в каждом видео | Варьировать: иногда «команды в описании», иногда тизер следующего |
| Пафос («революция», «будущее уже здесь») | Самоирония и заниженное обещание: «минута — и, в общем, всё» |

Тест: прочитай текст вслух. Споткнулся или стало неловко — переписывай это место.
Хороший признак: в тексте остались «кстати», «честно говоря», «ну что», числа и паузы.

## Антипаттерны скринкастов

| Антипаттерн | Чем заменить |
|-------------|--------------|
| Начать с "Привет, сегодня мы..." | Сразу результат, представление — после hook |
| Показывать установку/конфиг в начале | Конфиг — отдельным видео или в конце за 20 сек |
| Читать вслух то, что на экране | Голос объясняет ЗАЧЕМ, экран показывает ЧТО |
| Ждать ответа ИИ молча | Таймлапс + голос объясняет, что происходит под капотом |
| Извиняться ("сейчас немного подождём") | "Пока ИИ строит датасет — смотрите, он сам нашёл поля" |
| Терминал во весь ролик | SPLIT с браузером: зритель видит, как портал меняется |
| Финал в терминале | Финал — живой дашборд в браузере, курсор по фильтрам |
