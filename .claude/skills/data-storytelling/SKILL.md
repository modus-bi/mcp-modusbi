# Data Storytelling: Превращение данных в истории

## Overview

Reference-скилл для создания убедительных data-driven narratives:
- Как строить narrative arc на основе данных
- Правило "So what?" — от цифр к действиям
- Адаптация под разные аудитории
- Визуальная иерархия и акценты
- Паттерны для слайдов и отчётов

**Используется:** при создании слайдов, текстовых блоков для дашбордов, выводов из анализа.

---

## When to Use This Skill

Используй как reference когда нужно:

- Подготовить **data-driven презентацию**
- Написать **текстовый вывод** для графика или дашборда
- Превратить **сухие цифры** в **убедительную историю**
- Адаптировать **одни и те же данные** для разных аудиторий
- Применить **"So what?"** тест к аналитическим выводам

---

## Три компонента Data Story

```
DATA STORY = Data + Narrative + Visuals

1. DATA (данные)        — факты, цифры, метрики
2. NARRATIVE (история)  — контекст, причины, последствия
3. VISUALS (визуал)     — графики, диаграммы, акценты
```

### Почему нужны все три?

| Компонент | Без него | С ним |
|-----------|----------|-------|
| **Data** | Красивые слова без доказательств | Обоснованная аргументация |
| **Narrative** | Цифры без контекста (что это значит?) | Понятная история с выводами |
| **Visuals** | Стена текста и таблиц | Мгновенное понимание |

## Правило "So what?"

### Тест на ценность вывода

Каждый вывод должен пройти цепочку "So what?":

```
Level 0: "Продажи составили 156M руб"
  → So what?

Level 1: "Продажи выросли на 12% год к году"
  → So what?

Level 2: "Рост обеспечен категорией Электроника (+34%)"
  → So what?

Level 3: "Если расширить ассортимент электроники, ожидаемый рост +3-4M руб в квартал"
  → ДЕЙСТВИЕ!
```

**Правило:** Не останавливайся пока не дойдёшь до **конкретного действия** или **конкретного решения**.

### Матрица уровней выводов

| Уровень | Что делает | Пример | Для кого |
|---------|------------|--------|----------|
| **Level 1: Descriptive** | Описывает что произошло | "Продажи 156M" | Никому (бесполезно) |
| **Level 2: Diagnostic** | Объясняет почему | "Рост за счёт электроники" | Аналитикам |
| **Level 3: Predictive** | Предсказывает что будет | "Тренд продолжится в Q2" | Менеджерам |
| **Level 4: Prescriptive** | Рекомендует что делать | "Расширить ассортимент → +3M" | Руководству |

**Цель: всегда Level 4** — prescriptive analytics с конкретными действиями.

## Narrative Arc для данных

### Arc 1: Situation-Complication-Resolution (SCR)

Лучший arc для бизнес-презентаций:

```
SITUATION:    "Мы управляем 50K справочниками контрагентов из 12 источников"
COMPLICATION: "23% данных содержат ошибки, обнаруживаем их слишком поздно"
RESOLUTION:   "ИИ-агент проверяет данные автоматически и находит 95% ошибок"
```

### Arc 2: Before-After-Bridge

Для демонстрации трансформации:

```
BEFORE: "Аналитик тратит 4 часа на ручную проверку одного справочника"
AFTER:  "ИИ делает полное профилирование за 3 минуты"
BRIDGE: "Протокол MCP позволяет ИИ подключаться к БД напрямую"
```

### Arc 3: What-So What-Now What

Для аналитических докладов:

```
WHAT:     "DQ Score справочника контрагентов = 67%"
SO WHAT:  "Это значит, что каждая третья запись может содержать ошибку,
           что приводит к некорректным отчётам и задвоению платежей"
NOW WHAT: "Внедряем автоматические DQM-правила: NOT NULL для ИНН,
           формат проверки, дедупликация → целевой DQ Score 90% за 3 месяца"
```

## Адаптация под аудиторию

### Один датасет — три истории

**Данные:** DQ Score упал с 85% до 72% за квартал.

**Для C-level (директор):**
```
"Качество данных упало на 13 пунктов, что создаёт риск некорректных
финансовых отчётов. Рекомендация: выделить ресурсы на автоматизацию
DQ-проверок. ROI: экономия 2.3M руб/год на исправлении ошибок."

Акцент: ДЕНЬГИ, РИСКИ, ROI
```

**Для менеджера (руководитель отдела):**
```
"За квартал качество справочников снизилось из-за массовой загрузки
из нового источника (SAP). Предлагаю: 1) добавить DQM-правила для SAP,
2) назначить data steward, 3) еженедельный отчёт по DQ Score."

Акцент: ПРИЧИНЫ, ПЛАН ДЕЙСТВИЙ, ОТВЕТСТВЕННЫЕ
```

**Для аналитика (технический специалист):**
```
"DQ Score снизился: Completeness 91% → 78% (пустые ИНН из SAP),
Uniqueness 95% → 89% (дубли при merge), Validity 88% → 71%
(неправильный формат телефонов). SQL для fix: ALTER TABLE...
Энтропия поля 'company_name' = 4.2 (высокая, много грязных значений)."

Акцент: ДЕТАЛИ, МЕТРИКИ, КОД
```

### Матрица адаптации

| Аспект | C-level | Менеджеры | Аналитики |
|--------|---------|-----------|-----------|
| **Язык** | Бизнес-термины, ROI | Процессы, KPI | Технический, код |
| **Детали** | Минимум, только итоги | Средне, причины и план | Максимум, методология |
| **Визуал** | 1-2 больших числа | Графики + таблица | Детальные таблицы + код |
| **Действие** | Стратегическое решение | Операционный план | Техническая реализация |
| **Время** | 2-3 мин | 5-7 мин | 15-20 мин |

## Визуальная иерархия

### Принцип "Перевёрнутая пирамида"

```
┌─────────────────────────────────────┐
│         ГЛАВНЫЙ ВЫВОД               │  ← Первое что видит зритель
│      (крупный шрифт, яркий цвет)      │
├─────────────────────────────────────┤
│     Поддерживающие данные           │  ← Доказательства
│   (графики, ключевые цифры)         │
├─────────────────────────────────────┤
│  Детали и контекст                  │  ← Для тех кто хочет углубиться
│  (таблицы, footnotes)               │
└─────────────────────────────────────┘
```

### Правила оформления

| Правило | Описание | Пример |
|---------|----------|--------|
| **Contrast** | Выделяй главное цветом/размером | Ключевая цифра — 48px, остальное — 14px |
| **Alignment** | Выравнивай элементы | Все графики по сетке 12 колонок |
| **Repetition** | Повторяй стиль | Все заголовки — один шрифт и цвет |
| **Proximity** | Связанное — рядом | График рядом с выводом |

## Паттерны Data Storytelling

### Pattern 1: "Одна Big Number"

Для максимального impact — один большой факт:

```html
<div style="text-align: center; padding: 40px;">
  <div style="font-size: 72px; font-weight: 700; color: #0d47a1;">
    -13%
  </div>
  <div style="font-size: 24px; color: #546e7a;">
    Падение DQ Score за квартал
  </div>
  <div style="font-size: 16px; color: #c62828; margin-top: 10px;">
    = 2.3M руб потерь на исправление ошибок
  </div>
</div>
```

**Когда:** Hook слайд, привлечение внимания.

### Pattern 2: "Before-After Split"

Визуальное сравнение двух состояний:

```
┌──────────────────┬──────────────────┐
│     ДО (ручная     │    ПОСЛЕ (ИИ)      │
│     проверка)      │                    │
│                    │                    │
│  4 часа            │  3 минуты          │
│  67% точность      │  95% точность      │
│  Только популярные │  Все справочники   │
│  справочники       │                    │
│                    │                    │
│  Цвет: красный     │  Цвет: зелёный     │
└──────────────────┴──────────────────┘
```

**Когда:** Демонстрация ценности, ROI.

### Pattern 3: "Trend + Annotation"

График с вызовами (callouts) на ключевых точках:

```
DQ Score
100% ─┐
      │     ← "Запуск DQM-правил"
 90% ─│  /─────────────────
      │ /      ← "Целевой уровень"
 80% ─│/
      │
 70% ─┤─── ← "Загрузка из нового источника SAP"
      │  \
 60% ─│   \─── ← "Минимум: нужны действия!"
      └──────────────────────────
       Q1    Q2    Q3    Q4
```

**Когда:** Показать динамику и причинно-следственные связи.

### Pattern 4: "Drivers + Risks"

Двухколоночная структура для выводов:

```
┌──────────────────┬──────────────────┐
│  ДРАЙВЕРЫ РОСТА    │  ЗОНЫ РИСКА        │
│  (зелёный фон)     │  (красный фон)     │
│                    │                    │
│  Электроника +34%  │  Одежда -5%        │
│  Москва +28%       │  Самара -12%       │
│  Онлайн +45%       │  Склад переполнен  │
│                    │                    │
│  Что усилить       │  Что исправить     │
└──────────────────┴──────────────────┘
```

**Когда:** Выводы по дашборду, рекомендации.

### Pattern 5: "Stepwise Revelation"

Постепенное раскрытие данных (для слайдов):

```
Слайд 1: "Сколько ошибок в справочнике?" (вопрос)
Слайд 2: "23% записей содержат ошибки" (факт)
Слайд 3: "Это стоит 2.3M руб/год" (impact)
Слайд 4: "ИИ находит 95% ошибок за 3 минуты" (решение)
```

**Когда:** Презентация с нарастающим эффектом.

## Текстовые блоки для дашбордов

### Шаблон Level 4 вывода для текстового блока

```html
<div style="background: linear-gradient(135deg, #e3f2fd, #bbdefb);
            padding: 20px; border-radius: 10px;
            border-left: 5px solid #1976d2;">

  <h2 style="color: #0d47a1; margin-top: 0;">
    [ЗАГОЛОВОК: главный вывод в 1 предложении]
  </h2>

  <p style="font-size: 16px;">
    <strong>Главная метрика:</strong> [значение] ([изменение] vs прошлый период)
  </p>

  <h3 style="color: #1565c0;">ДРАЙВЕРЫ</h3>
  <ul>
    <li><strong>[Фактор 1]</strong> — [вклад]% ([объяснение])</li>
    <li><strong>[Фактор 2]</strong> — [вклад]% ([объяснение])</li>
  </ul>

  <h3 style="color: #c62828;">РИСКИ</h3>
  <ul>
    <li><strong>[Риск 1]</strong> — [масштаб] ([последствие])</li>
  </ul>

  <h3 style="color: #2e7d32;">РЕКОМЕНДАЦИИ</h3>
  <ol>
    <li><strong>[ПРИОРИТЕТ]</strong> [Действие] → [Ожидаемый impact]</li>
    <li><strong>[ПРИОРИТЕТ]</strong> [Действие] → [Ожидаемый impact]</li>
  </ol>

  <p><strong>ПРОГНОЗ:</strong> [Что будет если выполнить рекомендации]</p>
</div>
```

### Пример для DQ-контекста

```html
<div style="background: linear-gradient(135deg, #fff3e0, #ffe0b2);
            padding: 20px; border-radius: 10px;
            border-left: 5px solid #ff9800;">

  <h2 style="color: #e65100;">DQ Score справочника: 67% (целевой: 90%)</h2>

  <p>
    <strong>Разрыв до цели:</strong> 23 п.п.
    Основные проблемы: полнота ИНН (78%) и формат телефонов (54%).
  </p>

  <h3 style="color: #c62828;">ТОП-3 ПРОБЛЕМЫ</h3>
  <ol>
    <li><strong>Пустые ИНН</strong> — 22% записей (2,200 из 10,000)</li>
    <li><strong>Неверный формат телефона</strong> — 46% (regex: не соответствует +7...)</li>
    <li><strong>Дубли по названию</strong> — 8% (fuzzy match, Levenshtein < 3)</li>
  </ol>

  <h3 style="color: #2e7d32;">РЕКОМЕНДАЦИИ</h3>
  <ol>
    <li><strong>[КРИТИЧНО]</strong> Обогатить ИНН через ЕГРЮЛ API → +22% полноты</li>
    <li><strong>[ВЫСОКО]</strong> Нормализовать телефоны (regex-правило) → +46% validity</li>
    <li><strong>[СРЕДНЕ]</strong> Запустить дедупликацию → -8% дублей</li>
  </ol>

  <p><strong>ПРОГНОЗ:</strong> При выполнении всех 3 → DQ Score 89% за 2 недели</p>
</div>
```

## Антипаттерны (чего НЕ делать)

| Антипаттерн | Проблема | Решение |
|-------------|----------|---------|
| **Data dump** | Выгрузить все цифры без контекста | Выбери 3-5 ключевых метрик |
| **Chart junk** | 3D, тени, ненужные украшения | Минималистичный дизайн |
| **Missing "so what"** | Факт без вывода | Всегда добавляй "это значит..." |
| **Wrong audience** | Код для директора / ROI для аналитика | Адаптируй язык и детали |
| **Too many stories** | 10 выводов на одном слайде | Один слайд = одна мысль |
| **No action** | "Интересные данные!" и всё | Всегда заканчивай рекомендацией |

## Checklist перед публикацией

- [ ] Каждый вывод прошёл тест "So what?" (есть конкретное действие)
- [ ] Язык адаптирован под аудиторию
- [ ] Визуальная иерархия: главное крупнее/ярче
- [ ] Один слайд/блок = одна идея
- [ ] Есть narrative arc (начало → середина → конец)
- [ ] Цифры округлены (не 156,234,567.89 а 156M)
- [ ] Единицы измерения указаны (руб, %, шт)
- [ ] Контрастные цвета для позитива/негатива (зелёный/красный)
