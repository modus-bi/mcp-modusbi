# Чеклист QA отчёта ModusBI — «важные моменты»

Сжатый список проверок для прогона по отчёту (человеком или отдельным агентом).
Процедура и команды — в [SKILL.md](SKILL.md). Severity: 🔴 критично · 🟡 важно · 🟢 желательно.

> Прогонять **отдельным агентом** (не тем, что строил отчёт): `verify-report` как субагент,
> вход — `report_id`, выход — таблица PASS/FAIL по пунктам ниже + список фиксов.

## 1. Данные
- 🔴 У каждого data-компонента `rows_count > 0` (`component_crud(action="data")`). Пусто = FAIL.
- 🔴 **Проверять КАЖДЫЙ компонент по отдельности** на `"Component not linked to dataset"` —
  это = **бесконечная загрузка (спиннер)** в браузере. Частая причина: `update` с `value_field` БЕЗ `dataset_id`
  отвязывает датасет. Если так — переустановить с `dataset_id`.
- 🔴 Нет `undefined` / `NaN` / `null` / «Нет данных» / «не привязан к датасету» в DOM.
- 🟡 Значения KPI совпадают с ожидаемым агрегатом (сверить с `dataset_query`).
- 🟡 Каждый компонент **привязан к датасету** (`dataset_id` задан — после scaffold это отдельный шаг!).

## 1b. Ошибки выполнения (НЕ списывать на «квирки»!)
- 🔴 **Браузер: НЕТ error-попапа / тоста** «Ошибка выполнения запроса» / `pq:` / `does not exist`.
  Сканировать DOM на текст: «Ошибка», «does not exist», «pq:», «Драйвер».
- 🔴 **Network: data-запросы компонентов = 200**, не 4xx/5xx. ⚠️ HTTP 400 на карте — это РЕАЛЬНАЯ ошибка SQL,
  НЕ «известный квирк». Проверять `component_crud(action="data")` на каждый компонент: ошибка ответа = FAIL.
- 🔴 Карта/multi-field: `category_field="region,lat,lng"` (через запятую) НЕ разбивается → `group by "region,lat,lng"`
  = «column does not exist». Для карты: `category_field="region"` (одно поле) + lat/lng через `map_set_geokeys`.

## 2. Фильтры (самое частое место дефектов)
- 🔴 `field_type="string"` (не number — иначе слайдер вместо dropdown).
- 🔴 `alias` на русском; `dataset_id` задан; `global=true`.
- 🔴 **`filter_field_add` есть на КАЖДОМ data-компоненте**, не только на FilterControlPanel
  (`component_filters(action="filter_fields_list")` по каждому idx — пусто = фильтр не применяется).
- 🔴 **Тест фильтрации вживую** (браузер, п.2.6 SKILL): открыть dropdown → выбрать значение →
  **строки/данные во ВСЕХ компонентах пересчитались**. Не пересчитались = FAIL.
- 🟡 `global_filters` без orphan'ов; имена = русские alias.
- 🟡 Каскадные фильтры (если есть): дочерний зависит от родителя (`depends_on`).
- 🟡 z-index: dropdown не прячется за компонентами
  (`.react-grid-item:has(.hsFilterControlPanel){z-index:100!important}` в CSS отчёта).

## 3. Layout
- 🔴 Нет перекрытий: сумма `w` в ряду ≤ 48 (lg) / ≤ 60 (hd); `y_next ≥ y+h`.
- 🟡 Фильтры/subheader выше data-компонентов.
- 🟢 Проверить на мобильных breakpoints (sm/xs) — компоненты не наезжают.

## 4. Подписи / локализация
- 🔴 Фильтры, столбцы таблиц, легенды — на русском (`alias`, `field_titles`, `field_aliases`).
- 🟡 Заголовки компонентов осмысленные (не «Фильтр 1», «KPI 2», «value»).

## 5. Сортировка
- 🔴 Рейтинговые bar — по убыванию метрики (`field_sort_set order=desc`).
- 🟡 Динамика по дате — по возрастанию; таблицы — по ключевой метрике.

## 6. Стили / условное форматирование
- 🟡 Conditional formatting реально отрисовался (цвет ячеек/индикаторы в браузере, не только в конфиге).
- 🟢 Стилизация фильтров (outline/bgColor/margin), тема отчёта применены.

## 7. Спец-компоненты
- 🔴 Карта (Leaflet): тайлы загрузились + маркеры/пузыри/полигоны видны
  (`.leaflet-container`, `.leaflet-tile`, маркеры; data-API может давать 400 — проверять в БРАУЗЕРЕ).
- 🟡 Treemap/Pie/Waterfall/Pivot/TreeGraph — рендерятся с данными.

## 8. Браузер / общий рендер
- 🔴 Все компоненты видны (высота > 0), графики как canvas/SVG.
- 🟡 Число `.react-grid-item` = числу компонентов из API.
- 🟢 Грузится без таймаутов; нет ошибок в консоли.

## Вердикт
`PASS` — все 🔴 пройдены, 🟡 без критичных замечаний.
`FAIL` — есть хоть один 🔴 (особенно «фильтрация не пересчитывает данные» или «пустой компонент»).
Формат отчёта верификации — в [SKILL.md](SKILL.md) (раздел «Формат отчёта»).
