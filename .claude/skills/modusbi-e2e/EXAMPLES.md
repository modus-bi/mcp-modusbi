# E2E-проверка портала через браузер — сценарии и примеры

> **Коротко:** попросите проверить отчёт «живьём» — ассистент сам залогинится в портал
> через браузер, откроет нужный отчёт, убедится, что компоненты реально отрисовались
> (а не просто числятся в конфиге), снимет скриншоты и вернёт вердикт PASS/FAIL.

---

## Когда пригодится

- Конфиг отчёта вроде корректный, но надо убедиться, что **в браузере всё действительно рендерится**.
- График/таблица не показывают данные — нужно понять, где обрыв: данные есть, а отрисовки нет.
- Ищете в отчёте артефакты вроде `undefined`, `NaN`, пустых легенд и осей.

Это проверка **через браузер**. Если достаточно сверить данные по API — это `verify-report`.

---

## Пример 1. Проверить готовый отчёт целиком

**Вы пишете:**
> «Прогони E2E-проверку отчёта <REPORT_ID> — открой в браузере и убедись, что все компоненты отрисовались.»

**Что сделает ассистент:**
1. Сначала по API сверит метаданные и данные: число компонентов, что у каждого есть строки.
2. Прочитает учётные данные из `.env`, откроет `<URL>/report/<REPORT_ID>` в браузере и залогинится.
3. Дождётся загрузки, снимет скриншот верха, прокрутит контейнер отчёта и снимет низ.
4. Проверит, что число виджетов совпадает с API и что у графиков есть `canvas`/`svg`.

**Что получите:** таблицу «компонент → API-данные → отрисовка в браузере → проблемы» и вердикт PASS/FAIL со скриншотами.

## Пример 2. Найти, почему график пустой

**Вы пишете:**
> «В отчёте <REPORT_ID> диаграмма не показывает данные. Открой в браузере и разберись, в чём дело.»

**Что сделает ассистент:**
1. Проверит по API, что у компонента вообще есть строки (данные грузятся).
2. Откроет отчёт в браузере и посмотрит, появился ли в нужном виджете `canvas`/`svg`.
3. Прогонит проверку текста на `undefined` / `NaN` / `null` и снимет скриншот проблемного места.

**Что получите:** диагноз — данные есть, но не рисуются (фронт), либо данные не пришли (конфиг/датасет), плюс скриншот.

---

## Пример 3. Снять скриншоты для отчёта о тесте

**Вы пишете:**
> «Открой <REPORT_ID> в браузере и сделай скриншоты верхней и нижней части дашборда.»

**Что сделает ассистент:** залогинится, дождётся отрисовки графиков (им нужно ~2-3 сек),
снимет viewport-скриншот верха, прокрутит контейнер `.hsReport` вниз и снимет низ.
Скриншоты делаются по viewport — так корректно захватываются `canvas`/`svg`-графики.

---

## Полезно знать

- **Нужен браузерный MCP-сервер** (playwright) — именно он открывает портал и кликает по форме логина.
- **Учётные данные — только из `.env`** (`<URL>`, `<логин>`, `<пароль>`), в запросах и скиллах их не хардкодим.
- **Одна сессия на пользователя.** Логин в браузере сбрасывает API-токен и наоборот — поэтому сначала идут все API-проверки, потом браузер. Не чередуйте.
- **Скриншоты — по viewport, не fullPage:** в `fullPage` графики на `canvas`/`svg` не попадают.
- **Прокрутка — через контейнер `.hsReport`**, обычный скролл окна не работает.
- **Тестовые артефакты убирайте:** если для проверки создавался временный отчёт/датасет на стенде — удалите его после.
