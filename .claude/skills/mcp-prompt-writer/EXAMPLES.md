# MCP Prompt Writer — сценарии и примеры

> **Коротко:** скилл помогает писать и проверять MCP-промпты сервера (`app/prompts.py`) так,
> чтобы tool-имена, action-ы и параметры в тексте промпта совпадали с реальным API инструментов.
> Не нужно держать в голове все экшены — ассистент сверится с кодом и подскажет расхождения.

---

## Когда пригодится

- Добавляете **новый промпт** в сервер и хотите, чтобы шаги внутри ссылались на существующие tool/action.
- Подозреваете, что в промпте есть **выдуманные параметры** (галлюцинации LLM), которых нет в `app/tools/`.
- Делаете **аудит** после рефактора: экшены переименовали, а тексты промптов остались старыми.

---

## Пример 1. Добавить новый промпт

**Вы пишете:**
> «Добавь промпт `setup_rls`, который проводит пользователя через включение Row Level Security для датасета.»

**Что сделает ассистент:**
1. Сверит экшены `security_operations` по коду — найдёт `enable`/`update_filter`, а не выдуманный `enable(filter=...)`.
2. Соберёт 3 части: запись в `get_prompts()` с `arguments[]`, функцию-генератор и `case` в `get_prompt_messages()`.
3. В тексте шагов укажет реальные параметры (`dataset_id`, `rls_query`, `enabled`) и примеры вызовов.

**Что получите:** готовый промпт, который вставляется в `app/prompts.py` и сразу проходит проверку cross-reference.

---

## Пример 2. Аудит промпта на «несуществующее API»

**Вы пишете:**
> «Проверь промпт `make_global_filter` — кажется, там вызовы, которых нет в инструментах.»

**Что сделает ассистент:**
1. Прогонит шаги промпта по `app/tools/` и найдёт расхождения с реальными `case "<action>"`.
2. Отметит ловушки: `set_global_filter` без обязательного `alias` (фронт читает `report.globalFilters[alias]`),
   `pivot_link_set` на Bar/Line (есть guard — только `HsPivotChart`), `tabs_button_add` через неверный tool.
3. Предложит точечные правки — заменить выдуманные параметры на рабочие.

**Что получите:** список найденных проблем с указанием места и корректный вариант каждого вызова.

---

## Пример 3. Привести промпт к новым именам после рефактора

**Вы пишете:**
> «Экшены разнесли по `component_crud` / `component_filters` / `component_axes`. Обнови старый промпт под новое разделение.»

**Что сделает ассистент:**
1. Определит, в каком из 4 tool-ов теперь живёт каждый action (например, `tabs_button_*` — только в `component_axes`).
2. Перепишет шаги промпта на актуальные tool+action и проверит `config_overrides` (flat dict, ключи-слаги).
3. Прогонит чек-лист: число промптов в `get_prompts()`, формат сообщений, обработку отсутствующих обязательных аргументов.

**Что получите:** промпт, синхронный с текущим API, без deprecated-ссылок.

---

## Полезно знать

- **Источник истины — код, а не память.** Перед вставкой вызова в промпт сверяемся с `case "<action>"` в `app/tools/<module>.py` — версии меняются.
- **SINGULAR vs PLURAL.** В `report_operations` формы смешаны: списки `*_list` (например, `variables_list`), CRUD в единственном числе (`variable_add`).
- **Если не уверены в параметрах** — в промпт можно заложить шаг `<tool>(action="help", value_field="<action_name>")`.
- **Без hardcoded ID.** В тексте промпта используются аргументы (`report_id` и т.п.), а не конкретные номера отчётов.
- **Тексты промптов — на русском**, с пошаговой инструкцией и указанием конкретного tool + action на каждом шаге.
