# SQL для аналитики — сценарии и примеры

> **Коротко:** опишите словами, какой аналитический срез нужен, — ассистент напишет
> правильный запрос: с верной сортировкой, чистыми типами чисел, нужным округлением
> и понятными русскими подписями. И объяснит, как устроен паттерн.

---

## Когда пригодится

- Нужен **не просто список, а аналитика**: динамика, тренд, сравнение периодов, доли, накопительный итог.
- Цифры в графике «прыгают» или порядок строк случайный — нужна правильная сортировка.
- Хотите **разобраться в логике запроса**, а не просто скопировать готовый SQL.

Если нужен базовый запрос «топ-N / итоги по группе» — это `generate-sql`. Здесь — более продвинутые аналитические паттерны с объяснением.

---

## Пример 1. Динамика и сравнение с прошлым годом

**Вы пишете:**
> «Покажи выручку по месяцам и насколько каждый месяц вырос относительно того же месяца год назад.»

**Что сделает ассистент:**
1. Сгруппирует данные по месяцам и посчитает выручку.
2. Подтянет значение того же месяца годом ранее и посчитает прирост в процентах.
3. Сделает хронологическую сортировку, чтобы график шёл слева направо по времени.
4. Защитит расчёт от деления на ноль и округлит проценты.

**Что получите:** запрос вида «месяц → выручка → выручка год назад → прирост, %», готовый для линейного графика, и короткое пояснение, как считается прирост.

## Пример 2. Доли и накопительный итог (правило 80/20)

**Вы пишете:**
> «Хочу увидеть, какие категории дают основную выручку: доля каждой и накопленный процент.»

**Что сделает ассистент:**
1. Посчитает выручку по каждой категории.
2. Добавит долю категории в общей сумме (в процентах).
3. Добавит накопительный процент: где проходит граница «80% выручки».
4. Отсортирует от крупных к мелким — как и положено для такого анализа.

**Что получите:** таблицу «категория → выручка → доля, % → накопленный, %», по которой сразу видно ключевые категории. Ассистент объяснит, как читать накопленный процент.

## Пример 3. Сглаживание шума: скользящее среднее

**Вы пишете:**
> «Продажи по дням слишком скачут. Добавь линию сглаживания за 7 дней, чтобы виден был тренд.»

**Что сделает ассистент:**
1. Посчитает продажи по дням.
2. Рядом добавит среднее за последние 7 дней (скользящее окно).
3. Сохранит правильный порядок дат, чтобы линии совпадали по времени.

**Что получите:** запрос «день → продажи → среднее за 7 дней» для графика с двумя линиями: «факт» и «тренд». Дёрганая линия станет читаемой.

## Полезно знать

- **Объясняем логику.** Ассистент не просто даёт SQL — он коротко поясняет, как работает паттерн (зачем сдвиг на 12 месяцев, что такое накопительный процент, как считается окно).
- **Порядок строк гарантирован.** Для динамики — по времени, для рейтингов — по значению. На графике ничего не «прыгает».
- **Числа аккуратные.** Целые остаются целыми, проценты и средние округляются, деление на ноль не ломает запрос.
- **Подписи на русском.** Технические имена полей остаются в запросе, а в отчёте поля показываются с понятными русскими названиями.
- **Можно уточнять.** «Сделай не год к году, а месяц к месяцу», «возьми окно 30 дней», «покажи только топ-10 категорий» — запрос подстроится.
