# Present Outline: Планирование структуры презентации

## Overview

Этот skill создаёт структурированный план презентации:
- Определяет narrative arc (hook -> проблема -> решение -> демо -> CTA)
- Строит слайд-карту с таймингами
- Адаптирует под аудиторию
- Выдаёт готовый outline для генерации слайдов

**Результат:** Готовый plan презентации, который можно передать в `/create-presentation`.

---

## When to Use This Skill

Используй этот skill когда пользователь:

- Просит **"спланировать презентацию"** или **"составить план доклада"**
- Хочет **"структуру слайдов"** для выступления
- Нужен **"outline"** или **"план"** для презентации
- Говорит про **"тезисы"**, **"хронометраж"**, **"порядок слайдов"**
- Готовится к **конференции**, **семинару**, **вебинару**

**Не использовать если:**
- Нужно сгенерировать готовые слайды (используй `/create-presentation`)
- Нужен только анализ данных (используй `/analyze-data`)
- Нужен только сценарий демо (используй `/demo-scenario`)

## Inputs (что нужно от пользователя)

| Параметр | Обязательность | Описание | Пример |
|----------|----------------|----------|--------|
| **Тема** | Обязательно | О чём доклад | "ИИ для качества данных" |
| **Аудитория** | Обязательно | Кто будет слушать | "MDM-специалисты, партнёры 1С" |
| **Хронометраж** | Обязательно | Сколько минут | "15 минут" |
| **Тезисы** | Желательно | Ключевые идеи | "DQ как часть MDM, профилирование, NL2SQL" |
| **Формат** | Опционально | Тип выступления | "конференция / вебинар / внутренний" |
| **Демо** | Опционально | Будет ли живая демонстрация | "да, 3-5 минут" |
| **Продукт** | Опционально | Что продвигаем | "Модус:ETL + Модус:Аналитический портал" |

**Если пользователь дал короткий запрос:**
```
User: "Спланируй презентацию про ИИ для BI"

Ассистент: "Уточните:
1. Аудитория? (технические специалисты / руководство / смешанная)
2. Хронометраж? (10 / 15 / 20 / 30 минут)
3. Ключевые тезисы? (или я предложу на основе темы)
4. Будет ли демо?"
```

## Standard Workflow

### Шаг 1: Определить тип narrative arc

**Выбери подходящий arc в зависимости от цели:**

| Arc | Структура | Когда использовать |
|-----|-----------|-------------------|
| **Problem-Solution** | Боль -> Решение -> Результат | Продуктовые доклады, sales pitch |
| **Hero's Journey** | Старый мир -> Вызов -> Трансформация | Кейсы, success stories |
| **What-So What-Now What** | Факт -> Почему важно -> Что делать | Аналитические доклады |
| **Before-After-Bridge** | До -> После -> Как перейти | Методологические |
| **Hook-Problem-Solution-Demo-CTA** | Хук -> Проблема -> Решение -> Демо -> Призыв | Конференции с демо |

**Для технических презентаций с демо — рекомендуется Hook-Problem-Solution-Demo-CTA.**

---

### Шаг 2: Рассчитать тайминги

**Правило распределения времени:**

| Блок | % от времени | При 15 мин | При 20 мин | При 30 мин |
|------|-------------|------------|------------|------------|
| Hook (захват внимания) | 5-10% | 1 мин | 1-2 мин | 2-3 мин |
| Проблема (боль аудитории) | 15-20% | 2-3 мин | 3-4 мин | 5-6 мин |
| Решение (как работает) | 20-25% | 3-4 мин | 4-5 мин | 6-8 мин |
| Демо (живой показ) | 25-30% | 4-5 мин | 5-6 мин | 8-10 мин |
| Выводы + CTA | 10-15% | 1-2 мин | 2-3 мин | 3-4 мин |
| Вопросы | 5-10% | 1 мин | 2 мин | 3-5 мин |

---

### Шаг 3: Построить слайд-карту

**Формат вывода:**

```markdown
# PLAN: [Название презентации]
## Метаданные
- Аудитория: [кто]
- Хронометраж: [мин]
- Формат: [тип]
- Narrative arc: [тип arc]

## Слайд-карта

### БЛОК 1: HOOK (1 мин)
| # | Слайд | Тип | Контент | Заметки спикера |
|---|-------|-----|---------|-----------------|
| 1 | Титульный | title | Название + подзаголовок | Представиться, контекст |
| 2 | Провокация | stat | Шокирующая статистика | "А вы знали, что..." |

### БЛОК 2: ПРОБЛЕМА (3 мин)
| # | Слайд | Тип | Контент | Заметки спикера |
|---|-------|-----|---------|-----------------|
| 3 | Боль | text+image | Типичные проблемы | Примеры из жизни аудитории |
| 4 | Масштаб | chart | Статистика проблемы | Данные, цифры |
| 5 | Последствия | quote | Что будет если не решить | Усиление боли |

### БЛОК 3: РЕШЕНИЕ (4 мин)
...

### БЛОК 4: ДЕМО (5 мин)
...

### БЛОК 5: ВЫВОДЫ + CTA (2 мин)
...
```

---

### Шаг 4: Определить типы слайдов

| Тип слайда | Описание | Когда использовать |
|------------|----------|-------------------|
| **title** | Титульный: название + автор | Первый и последний слайд |
| **section** | Разделитель блоков | Переход между частями |
| **stat** | Одна большая цифра/факт | Hook, провокация |
| **text** | Текст + буллеты | Объяснение, перечисление |
| **text+image** | Текст слева + изображение справа | Визуальные концепции |
| **diagram** | Mermaid / ASCII схема | Архитектура, workflow |
| **comparison** | Таблица "до/после" | Сравнение подходов |
| **chart** | График / диаграмма | Данные, статистика |
| **code** | Блок кода | Технические детали |
| **demo** | Слайд-маркер "LIVE DEMO" | Начало демонстрации |
| **quote** | Цитата / ключевой месседж | Акцент на идее |
| **cta** | Call to action | Призыв к действию |
| **qr** | QR-код + ссылка | Ресурсы, контакты |

---

### Шаг 5: Адаптировать под аудиторию

**Матрица адаптации:**

| Аудитория | Язык | Глубина | Примеры | Акцент |
|-----------|------|---------|---------|--------|
| **C-level** | Бизнес, ROI | Минимум техники | Кейсы, цифры | Результат, экономия |
| **Менеджеры** | Процессы, workflow | Средняя | Workflow, сценарии | Эффективность, контроль |
| **Технические** | Архитектура, код | Максимум деталей | Код, API, схемы | Как работает, интеграция |
| **MDM/DQ специалисты** | DQ-метрики, правила | Высокая в DQ | Профилирование, правила | Качество, стандарты |
| **Смешанная** | Баланс бизнес+техника | Средняя | Визуальные примеры | Понятность для всех |

## Patterns (готовые шаблоны)

### Pattern 1: Tech Talk с демо (15 мин)

```
1. [title] Название (0:00)
2. [stat] Провокация: "80% данных — грязные" (0:30)
3. [text] Проблема: типичные проблемы с данными (1:00)
4. [diagram] Архитектура решения (3:00)
5. [comparison] До/После: ручной vs ИИ (5:00)
6. [demo] LIVE DEMO — профилирование данных (6:00)
7. [demo] LIVE DEMO — создание дашборда (8:00)
8. [chart] Результаты: метрики DQ (11:00)
9. [text] Что дальше: roadmap (12:00)
10. [cta] Призыв: попробуйте / контакты (13:00)
11. [qr] QR-код + ссылки (14:00)
```

### Pattern 2: Product Pitch (20 мин)

```
1. [title] Название
2. [stat] Hook: шокирующий факт
3. [text] Проблема 1: описание
4. [text] Проблема 2: масштаб
5. [text] Проблема 3: последствия
6. [section] "Наше решение"
7. [diagram] Архитектура
8. [text] Фича 1 + польза
9. [text] Фича 2 + польза
10. [demo] LIVE DEMO
11. [chart] Результаты / ROI
12. [comparison] До/После
13. [quote] Отзыв клиента
14. [text] Roadmap
15. [cta] Призыв к действию
```

### Pattern 3: Методологический доклад (30 мин)

```
1. [title] Название
2. [text] Контекст: зачем это важно
3. [diagram] Общая картина / framework
4-6. [text] Принцип 1, 2, 3 с примерами
7. [section] "Практика"
8-10. [text+image] Кейс 1, 2, 3
11. [demo] Короткое демо (опционально)
12-13. [text] Уроки / best practices
14. [chart] Результаты
15. [text] Roadmap / что дальше
16. [cta] Призыв
```

## Visual Accents (визуальные акценты для слайдов)

### Правило "1 слайд — 1 идея"

- Максимум 6 строк текста на слайде
- Максимум 6 слов в строке (правило 6x6)
- Один ключевой месседж на слайд
- Изображения > текста

### Цветовое кодирование

| Элемент | Цвет | Назначение |
|---------|------|------------|
| Заголовки | #0d47a1 (тёмно-синий) | Иерархия |
| Позитив (рост, успех) | #2e7d32 (зелёный) | Хорошие метрики |
| Негатив (проблема, риск) | #c62828 (красный) | Боль, проблемы |
| Акцент | #ff6f00 (оранжевый) | Важные элементы |
| Фон | #e3f2fd (светло-голубой) | Корпоративный стиль Модус |

## Output Format

**Финальный outline должен содержать:**

1. **Метаданные**: тема, аудитория, хронометраж, narrative arc
2. **Слайд-карта**: таблица с номером, типом, контентом, таймингом
3. **Speaker notes**: что говорить на каждом слайде (ключевые фразы)
4. **Переходы**: как связать блоки между собой
5. **Fallback**: что делать если демо не работает

**Пример финального вывода:**

```
OUTLINE: "ИИ-помощник для качества данных"

Аудитория: MDM/DQ специалисты, партнёры 1С
Время: 15 минут
Arc: Hook → Problem → Solution → Demo → CTA

СЛАЙД 1 [title] (0:00-0:30)
Контент: "Интеллектуальный помощник для BI и ETL"
Подзаголовок: "как ИИ помогает собирать, описывать и использовать данные"
Speaker: "Добрый день! Я [имя], [должность]. Сегодня покажу как ИИ..."

СЛАЙД 2 [stat] (0:30-1:00)
Контент: "80% времени аналитика уходит на подготовку данных"
Visual: Большая цифра "80%" + маленький текст
Speaker: "Вот шокирующий факт: четыре из пяти часов рабочего дня..."
Переход: "А что если ИИ возьмёт это на себя?"

...
```

## Best Practices

1. **Начинай с Hook** — первые 30 секунд определяют внимание
2. **Проблема = боль аудитории** — говори о ИХ проблемах, не о своих
3. **Демо > слайды** — живой показ убеждает больше любых буллетов
4. **Правило 10-20-30** (Kawasaki): 10 слайдов, 20 минут, 30pt шрифт
5. **CTA конкретный** — "зайдите на сайт" лучше чем "подумайте об этом"
6. **Fallback план** — всегда имей скриншоты/видео демо на случай сбоя
7. **Repetition** — повтори ключевой месседж минимум 3 раза в разных формах
