# Разбор настроек компонента — сценарии и примеры

> **Коротко:** скажите, какой компонент разобрать, — ассистент пройдёт ВСЕ контролы его
> config-панели и сведёт таблицу «контрол в UI → путь в JSON-конфиге → MCP-slug», пометив
> для каждого, где slug реально влияет, где это алиас под другим именем, а где slug-а нет.
> Это аудит соответствия настроек, фиксы при этом не вносятся.

---

## Когда пригодится

- Нужно понять, **какие настройки компонента вообще задаются через MCP** (`config_overrides`), а какие только руками в UI.
- Подозреваете, что **slug «не срабатывает»** — хотите узнать, пишет ли MCP в тот же JSON-путь, что и фронт.
- Готовите **справку по компоненту**: полный список контролов с реальными JSON-путями и slug-ами.

Это про чтение и сопоставление, а не про правку. Нужно реально применить slug и увидеть результат на экране — это `component-visual-verify`. Найти компонент в палитре и проверить готовность — `portal-component-probe`.

---

## Пример 1. Полный разбор одного компонента

**Вы пишете:**
> «Разбери все настройки столбчатого графика: для каждого контрола покажи JSON-путь и slug, отметь несоответствия.»

**Что сделает ассистент:**
1. Создаст тестовый отчёт и добавит компонент с минимумом данных (одно измерение + одна метрика).
2. Откроет config-панель в браузере и сначала **перечислит ВСЕ контролы** по секциям (легенда, оси, подписи, всплывашка, стиль) — ни один не пропуская.
3. Для каждого контрола поменяет значение, сохранит и сравнит сырой `config` до/после — так находит **реальный JSON-путь (источник истины A)**.
4. Найдёт slug в `config_schema.py`, посмотрит, **куда пишет сам MCP (C)**, и сравнит C с A.

**Что получите:** таблицу `UI-секция | контрол | JSON(A) | тип | slug | MCP пишет(C) | связь` с метками: `linked` (slug = путь, работает), `alias` (работает, но имя slug ≠ JSON-путь — с явным маппингом), `mismatch` (MCP пишет не туда — кандидат-баг), `no-slug`, `undoc-json`.

## Пример 2. Проверка «slug не работает»

**Вы пишете:**
> «Я задаю `visuals.colorMin` через config_overrides, а цвет не меняется. Это баг или я не туда смотрю?»

**Что сделает ассистент:**
1. Применит slug через `component_crud(action="update", config_overrides={"visuals.colorMin": "..."})`.
2. Сразу прочитает сырой `config` из браузера и посмотрит, **в какой ключ реально лёг** результат.
3. Сравнит с тем путём, куда пишет фронт при изменении того же контрола в UI.

**Что получите:** однозначный вердикт. Либо `mismatch` (MCP кладёт в `visuals[0].colorMin`, а фронт читает top-level — silent-ignore, кандидат в `DISCREPANCIES.md`), либо `alias` (работает, просто под другим именем — с записанным маппингом slug → JSON).

## Пример 3. Что вообще задаётся через MCP

**Вы пишете:**
> «Покажи по таблице, какие визуальные настройки можно прокинуть через MCP, а какие только руками.»

**Что сделает ассистент:** пройдёт контролы компонента и разнесёт их на `linked`/`alias` (доступно через `config_overrides`) и `no-slug` (только UI). Для алиасов даст маппинг вида `data.rowsLimit → config.rowsLimit`, `axes.categoryGrid → config.axes[categories].showgrid`.

**Что получите:** короткий список «доступно через MCP / только UI» — основа для планирования автоматизации отчёта.

## Полезно знать

- **Источник истины A — только сырой `config` из браузера**, не MCP `get`. MCP `report_operations(get)` и `component_crud(get)` отдают урезанный summary без сырого конфига — diff по ним почти ничего не видит.
- **Связь определяется сравнением A и C**, а не совпадением имени slug с JSON-путём. Поэтому `alias` — это норма, а не баг; его всегда фиксируют явным маппингом slug → JSON.
- **Нужен браузерный MCP (playwright)** для сверки с UI: открыть панель, перечислить контролы, прочитать сырой `config`. Креды портала берутся из gitignored `.env` (`grep MODUSBI_ .env`), в скилл не зашиты.
- **Сначала перечисляем все контролы, потом разбираем** — иначе условные настройки (появляются после выбора в dropdown, например «Отображать итог» у donut) теряются.
- **Фиксы не вносятся.** Все `mismatch` идут в реестр как кандидаты-баги. Результат — файл `components/<Класс>.md` плюс обновлённые чеклист и реестр несоответствий.
